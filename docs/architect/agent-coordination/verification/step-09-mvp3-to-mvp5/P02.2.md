## 1. Requirements (verbatim from phase-02-mvp4-thin-surface-launcher.md, R5-R6 slice)

- **R5 Resume/show path.** The surface should show or return the coordination id
  and the next user-relevant action without depending on chat history.
- **R6 Setup/doctor discipline.** If the launcher introduces a new config
  default, env var, runtime-read file location, or infrastructure assumption,
  register it with setup/doctor in the same phase.

Concrete starting point (per `P02.1.md` §7 Gaps, already confirmed): a
single-shot `launch-master-loop` request only completes the fixture's
REQUIRED first pass (produce/review/red-team) — `revise-candidate`/
`reviewer-recheck`/`red-team-recheck` are all `driver-authorized` and need
a separate `authorize` step this launcher deliberately never emits. The
session therefore closes with `closed:false` and a refusal reason naming
the missing required actor (`fixer`). This is the EXPECTED shape — R5 is
about making that state legible, not building a resume door.

## 2. Design Decisions

- **R5 split into two halves, matching the cell's own Must Read split.**
  Half A (`launch-master-loop.mjs`): the launcher's own return value always
  carries a new `nextAction` field — a plain-text message computed by a new,
  exported, pure function `describeNextAction({coordinationId, closed,
  closeRefusalReason})`. It is pure (no engine call) so it is independently
  unit-testable, and it is display-only: it names `fgos coordination show
  <id>` as the next step and, when `closeRefusalReason` is present, restates
  the refusal in plain terms plus the fact that any next step is a
  driver-authorized operation requiring separate human review — never a
  `--resume` flag or any other command that does not exist. Half B
  (`show.mjs`): `showCoordinationUseCase` now also calls `replaySession`
  (previously unused there) and renders `authorizations`,
  `ignoredAuthorizations`, `dispositions`, and `pendingDriverAuthorizations`
  from its reconstruction — additive fields only, every pre-existing field
  (`eventCount`, `assignmentRefs`, `quorum`, etc.) is computed exactly as
  before, unchanged.
- **`replaySession` failure never breaks `show`'s pre-existing view.** Unlike
  `readSessionEvents` (documented as "unvalidated beyond parse"),
  `replaySession` fails closed on any cross-event inconsistency (duplicate/
  dangling/foreign/out-of-order ref). Adding an unconditional call would be a
  real behavior change: a session `show` could previously read (even if
  internally inconsistent) could now hard-fail. `showCoordinationUseCase`
  therefore wraps the `replaySession` call in try/catch: on success the four
  new fields render from its reconstruction; on failure they are `null` and a
  `coordinationStateError` field carries the message, while the manifest/
  quorum/phase/eventCount view keeps working exactly as it did before this
  cell. No existing `show` test needed to change as a result (verified: the
  pre-existing "corrupt session.json" CLI test fails at the earlier
  `readManifest` call, before this new code path is ever reached).
- **Two rendering constraints from the cell contract, both honored by
  construction:**
  - *Recheck lineage not presented as a hard edge.* This cell's renderer
    never joins `assignments[].authorizationId` →
    `authorizations[].targetArtifactRef` into anything resembling an
    original→recheck pointer. It renders `authorizations` and `assignments`-
    adjacent data as flat, independent lists (authorization id/operation/
    node/actor/consumed) — no lineage claim is made anywhere in the output.
  - *Disposition ref ownership check + post-terminal marking.* Store.mjs's
    own `assertDispositionRefOwnedBySession` (P01.1's precedent) is an
    unexported, write-time-only function; `store.mjs` is on this cell's Do
    Not Touch list, so it cannot be exported without touching a
    Do-Not-Touch file. `show.mjs` instead carries a byte-for-byte mirror,
    `isRefOwnedBySession` — same segment-by-segment walk, same
    cross-session-directory check, same `asgn_`-prefix existence+membership
    check — reimplemented as a boolean return instead of a throw (a
    render-time gate must mark a bad ref, not take down the whole `show`
    command over it). Every rendered `targetRef`/`evidenceRefs[i]` carries a
    matching `...OwnedBySession` boolean. Post-terminal marking:
    `replay.mjs` already neutralizes-and-separately-reports a post-terminal
    `operation-authorized` event (`ignoredAuthorizations`) but does **not**
    apply the same treatment to `driver-disposition-recorded` events (P00.1
    Gap #9, confirmed still true by direct read of `replay.mjs`'s dispositions
    push, which is unconditional). `show.mjs` computes this itself by
    walking the same raw `events` array `replaySession` already returns,
    tracking the same four terminal event types, and marking each rendered
    disposition `postTerminal: true` if a terminal event already appeared
    earlier in the log — mirrored logic, not new policy (the four terminal
    type strings are a local, commented duplicate of `replay.mjs`'s own
    private `TERMINAL_EVENT_TYPES`, for the same Do-Not-Touch/no-export
    reason).
- **`pendingDriverAuthorizations` reads the declared FlowDefinition directly.**
  For a declared-protocol session (`manifest.definitionRef` non-null),
  `show.mjs` calls the existing `loadCoordinationProtocol` (already used by
  `run.mjs`/`launch-master-loop.mjs`, `runner/definitions/` layer, not on the
  Do Not Touch list), walks `definition.spec.graph.nodes[].operations[]` for
  every binding declaring `activation.mode === 'driver-authorized'`, and
  reports the ones with no matching (`nodeId`+`operationId`) entry in the
  rendered `authorizations` list. `null` (not `[]`) for an agent-led session
  (no FlowDefinition to check at all) or if the definition can no longer be
  loaded (removed/renamed since the session opened) — degrades that one
  field rather than crashing the rest of `show`.

**Structural finding for a future Lead (new, worth carrying into `fgos-plan-loop` SKILL.md):** a follow-up coordination session that only dispatches driver-authorized `revise-candidate`/`*-recheck` positions (skipping the required first pass) can never auto-close via `closeSessionByQuorum` — `quorum.completed` only credits a role for its REQUIRED graph-position completion (`produce-candidate`/`review-candidate`/`red-team-candidate`), not the optional recheck positions, even though the recheck assignments genuinely ran and reported `done`. This is harmless (the session just stays `active` forever) but means a Lead should not expect `close.json` to work for a fix-round-only follow-up session — record the outcome in the cell trace instead of chasing a close.

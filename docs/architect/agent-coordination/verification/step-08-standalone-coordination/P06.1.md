## What R1-R4 implement

- **R1**: `manifest.partialPolicy` (`{minimumActors?, allowedOmissions?}`),
  declared immutably at `openSession` time only. `evaluateSessionQuorum`/
  `closeSessionByQuorum` classify every required actor (resolving
  `actor-replaced` chains) into completed/failed/late/missing; closing
  `'completed'` requires zero incomplete actors; closing `'partial'`
  requires a declared policy that names every incomplete actor and meets
  any `minimumActors` floor — an undeclared or under-covered partial
  close throws and the session stays `active`.
- **R2**: `retrySessionTask` dispatches a new Run for the SAME Assignment
  (never a new Assignment), backed by `recordRunRetry` (declares
  `run-retried` before dispatch, resume-safe/idempotent). `linkResult`
  gained opt-in `allowSupersede`, authorized only by a genuinely prior
  `run-retried` event, never deleting/rewriting the previous
  `result-linked` event or RunResult. `replaceSessionActor` replaces an
  actor under the SAME role (no `role` parameter exists at all —
  structural, not validated), recording provenance via
  `recordActorReplacement`.
- **R3**: every new multi-step write (retry declare→dispatch→link;
  bind-actor→record-replacement) is resume-safe via a durable on-disk
  claim file checked before re-declaring/re-binding; a genuinely
  ambiguous mid-crash state fails closed with named repair guidance,
  matching the P01.1/P01.2 precedent's own discipline. Pre-existing R3
  territory (Assignment-claim atomicity, manifest/event boundaries,
  concurrent fan-out/fan-in) is P01.x/P04.x's own proven ground,
  untouched here.
- **R4**: new `'cancelled'` status; `cancelSession` snapshots genuinely
  in-flight Assignments and transitions via the same absorbing
  `transitionSessionStatus` primitive every terminal status uses — never
  deletes/mutates evidence; a late-arriving result can still link after
  cancellation. `deriveSessionPhase` reports an inferred phase view,
  adding no new persisted status beyond `cancelled`.

## Review history (full rigor — this class of work matches P01.1's own
crash-safety/evidence-immutability precedent, held to the same 2-round
bar, and needed it)

**Doer → Reviewer (round 1):** Reviewer independently traced/empirically
verified the retry-accounting math (`recordRunRetry`'s
`fulfilledRetries`/`pendingRetries` formula) across 4 concrete event-log
sequences — clean, no bug. But found and reproduced **2 real HIGH bugs**:

- **H1**: `replaceSessionActor` let `newActorId` collide with an
  unrelated, independently-required actor — the collision silently
  dropped that actor's own required slot from quorum (`classifySessionQuorum`'s
  `replacementTargets.has(id) → continue` skip), letting a session
  falsely, permanently close `'completed'` while a required actor's real
  work was never verified. The function's own JSDoc claimed `newActorId`
  "must not already be bound," but the code silently treated any
  already-bound id as an OK resume.
- **H2**: `closeSessionByQuorum` computed quorum from an unlocked
  `replaySession()` read, then wrote the immutable terminal event via
  `transitionSessionStatus`, whose lock only re-checked `status !== 'active'`
  — never re-validating the classification about to be permanently
  written. A genuinely-completing actor's result landing in that gap
  could be falsely, permanently recorded as missing.

Both independently re-confirmed by the Coordinator reading the exact
cited source before any fix was authorized (not accepted on the
Reviewer's word alone) — `store.mjs`'s `openSession` writes actors
straight into the manifest with no dispatch, `transitionSessionStatus`
truly never re-validates its caller's classification, matching the
report exactly.

**Fixer round 1:** Fixed H2 completely — new `withSessionLock` (`store.mjs`)
+ `transitionSessionStatusLocked` (unlocked core) + a shared
`classifySessionQuorum` extraction so `closeSessionByQuorum`/
`cancelSession` now classify AND write inside one held lock, from a
fresh read taken after acquiring it. H1's fix only closed the sub-case
where the colliding actor already had independent dispatch activity on
record (`assignment-created`) or prior replacement involvement — the
Fixer itself flagged the residual gap honestly rather than claiming full
closure.

**Red-Team recheck (round 1):** Confirmed H2 genuinely fixed (verified no
lock re-entrancy since `replaySession` never itself acquires the events
lock; per-session lock granularity confirmed correct; the H2 regression
test independently confirmed to be a REAL cross-process race, not a
mocked stand-in — it takes the real `events.lock` via the exact hardlink
protocol `acquireEventsLock` uses, from a genuinely separate OS process).
Then **empirically reproduced the FULL, un-narrowed H1 bug** through
ordinary API use (no crash needed): confirmed `openSession` writes every
declared actor straight into `manifest.actors` with no `assignment-created`
required, meaning "required actor, undispatched" is the DEFAULT state
for any fresh required actor, not a corner case — round 1's fix never
covered this. Also found `docs/specs/runner.md` and `CHANGELOG.md` (both
part of this cell's own diff) overclaiming "never double-counts"/
"resume-safe" with no caveat, directly contradicted by the repro.
**Verdict: MUST-CLOSE-BEFORE-LANDING** — independently re-confirmed by
the Coordinator reading `openSession`'s exact source before authorizing
a second fix round.

**Fixer round 2:** Closed H1 properly via a `(oldActorId, newActorId)`-
pair-keyed on-disk claim file (`actor-replace-{old}--{new}.claim`,
exclusive-create, mirroring `retrySessionTask`'s own established
per-attempt claim precedent in the same file — an in-scope idiom reuse,
not a schema change) written strictly before `bindActor`. An already-bound
`newActorId` with no "definite collision" evidence AND no claim file for
this exact pair now throws instead of being silently treated as a
resume. Also corrected the `runner.md`/`CHANGELOG.md` overclaims to
accurately describe the mechanism (now true, not aspirational). Coordinator
independently re-read the fix logic and re-ran the focused suite (226/226)
before authorizing the final recheck.

**Red-Team recheck (round 2, final gate):** Reproduced round 1's exact
original scenario live — confirmed it now throws, and the previously-
absorbed actor (`c`) is confirmed to remain independently evaluated in
quorum afterward. Adversarial new-gap hunt: traced `proposeConsult`'s

### MEDIUM — silent data loss on a `__proto__`-keyed `baseStepMap` entry

`validateWorkflowProfile` (schema.mjs:283-289) builds
`spec.profile.work.baseStepMap` via `baseStepMap[stageId] = baseStepId`
on a plain object literal. When `stageId === '__proto__'`, this invokes
the object's `__proto__` accessor setter instead of creating an own
property; since the value is a string (not object/null), the setter
silently no-ops per the JS spec -- the entry vanishes from the validated,
frozen output with **zero error thrown**, directly contradicting this
module's own stated fail-closed invariant ("throws ... on the first
violation found"). Not classic prototype pollution (fresh local literal
each call, no cross-request/global-state leak -- confirmed by the
Reviewer and independently re-confirmed by the Coordinator).

**Coordinator's own independent reproduction** (not just trusting the
Reviewer's claim):
```
node -e '... validateFlowDefinition({ ... work: { baseStepMap: { "__proto__": "Execute" } } } ...)'
→ result.spec.profile.work.baseStepMap own keys: []
→ no throw occurred -- silent data loss confirmed: true
```
Matches the Reviewer's report exactly.

**Coordinator disposition: ACCEPTED, fixing.** Genuine, reproducible,
contract-adjacent (this module's own house rule, not a hypothetical) bug.
Fix direction: build `baseStepMap` on `Object.create(null)` (no prototype
chain to shadow) instead of a plain `{}` literal -- smallest fix, matches
the pattern already used elsewhere in the file for untrusted key names
(`Set`-based collections never doing dynamic bracket-writes on a
prototype-bearing object).

### LOW — `assertNoForbiddenFieldsDeep`'s cycle-guard is document-scoped, not branch-scoped

Correct and intentional for its stated purpose (prevent infinite
recursion on genuinely cyclic input); a shared-reference-but-not-cyclic
input (only possible via manual object construction, not JSON/YAML
parsing) could skip a legitimate second branch's forbidden-field scan.
**Coordinator disposition: documented, not fixed** -- low practical risk
per the Reviewer's own assessment (real input is always freshly parsed,
never shares object references across branches), and fixing it would add
real complexity (branch-scoped `seen` tracking) for a scenario this
track's actual callers cannot produce.

## Fix Evidence

instead of `{}` -- a null-prototype target has no inherited `__proto__`
accessor setter, so bracket assignment always creates a real own property
regardless of key name. Regression test added:
`'preserves a "__proto__" baseStepMap key as a real own property instead
of silently dropping it'` -- built via `JSON.parse` of a genuine JSON
string (not an object literal, which never creates an own `"__proto__"`

would not have exercised the bug at all -- correctly identified by the
Fixer). Also broadened the existing `missionId` negative test to a second,
deeper nesting point (`spec.actors[0].policy.missionId`), demonstrating
the "any depth" claim at more than one level.

- Fix (option (a) — monotonic re-derivation, one rule, no schema change): in `findLatestAssignmentRunResult`, a re-derived pair that advances Work ({done, reported|verified}) is accepted only when it does not ascend above the settle-time record; an honestly settled failed run (non-zero/timeout exit, dirty mutation) keeps failed/failed and the member stops per failed semantics (re-dispatch). Not chosen: binding exitCode via a hash inside result.json — the attacker edits both (same-file self-attestation is not binding; the S3 lesson). No legitimate stored-failed-later-legit shape exists for this rule to block.

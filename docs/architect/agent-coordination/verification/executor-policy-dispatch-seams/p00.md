## Process lesson

The first merge attempt was mistakenly run by switching the **shared main
checkout's** (`/home/vantt/projects/forgentX`) own HEAD to
`track/executor-policy-dispatch-seams` and merging there, instead of using
a dedicated worktree. This risked disrupting any other concurrent session
using that same shared checkout (`.fgos/events.jsonl`/`.fgos/state.json`
showed live concurrent modification throughout this cell). No data was
lost by this — a previously-untracked sibling plan directory
(`plans/260915-0455-test-suite-feedback-cost/`) that disappeared from the
main checkout during this window turned out to already be safely
committed on its own `test-suite-feedback-cost` track/worktrees, so it was
housekeeping by that concurrent session, not something this cell destroyed
— but the main checkout's branch was switched back to `main` immediately
and a dedicated `executor-policy-dispatch-seams-track` worktree was
created for the merge and post-merge verification instead. Every later
phase in this track should merge and verify from that dedicated track
worktree (or a fresh one per phase), never by checking out a branch
directly in the shared main checkout.

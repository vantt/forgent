## Gaps

- **R7 partial: full Run settlement across a genuinely diverged `--cwd`/repo-root is blocked by a dispatch-layer file, out of this cell's lease.**
  `bin/fgos.mjs`'s `coordination` case now threads a real `--cwd` into
  `ctx.cwd` (distinct from `--dir`/`ctx.repoRoot`), and `runCoordinationUseCase`
  genuinely opens the session and creates the Assignment CLAIM under the
  `--cwd` worktree's own `.fgos/coordination/` and `.fgos/assignments/`
  (empirically confirmed — see Commands). However, `src/runner/dispatch/
  assignment-runner.mjs`'s `executeAssignment` (line ~558-573) resolves the
  Assignment's own RUN-ARTIFACT directory (`runs/<n>/agent-result.json`
  etc.) from `opts.repoRoot` (`root = opts.repoRoot ?? resolveMainCheckoutRoot(cwd)
  ?? resolveRepoRoot(cwd)`; `fgosDir = fgosDirFromRoot(root)`), not from
  `opts.cwd` — the opposite of `store.mjs`'s own `resolveCoordinationPaths`
  (`fgosDir = fgosDirFromRoot(cwd)`). When `cwd` and `repoRoot` genuinely
  diverge (exactly the `--cwd` worktree case this flag exists for), the
  session/claim files land under the worktree but the executed Run's own
  result files land under the repo root instead, so `runCoordinationUseCase`
  fails with `"no result.json exists at <worktree>/.fgos/assignments/.../result.json"`.
  This file is under `src/runner/dispatch/**`, this cell's absolute
  Do-Not-Touch boundary (P01.1's exclusive lease) — not fixed here.
  `test/cli/coordination.test.mjs`'s two `--cwd` tests were designed around
  this: the "run --cwd" test only asserts the session/claim genuinely open
  under the worktree (real, direct filesystem assertions, not a `run`
  success/exit-code check); a separate "show --cwd" test proves the pure
  read-side wiring is correct in isolation (via a session opened directly
  through `store.mjs`, no Assignment dispatch involved). Full end-to-end
  `--cwd` proof (a mutating step that also SETTLES) needs this
  dispatch-layer fix, which is P01.1's shaped fix or a follow-up cell —
  named here rather than silently worked around or asserted away.
- **New, non-baseline full-suite failure confirmed environment-caused, not
  introduced by this cell:** `test/runner/coordination-static.test.mjs:61`
  fails on the full suite in this worktree. Its own `FORBIDDEN_IMPORT_SUBSTRINGS`
  check includes the literal string `"worktree"` and matches it against each
  import's fully RESOLVED ABSOLUTE PATH, not just the specifier/filename —
  so it false-triggers whenever the repo itself is checked out under a path
  containing the substring "worktree" (this dispatch infrastructure's own
  `.claude/worktrees/agent-<id>` convention). Confirmed not caused by this
  cell: none of the files it lists (`cohort-planner.mjs`, `headless-adapter.mjs`,
  `replay.mjs`, `schema.mjs`, `session-engine.mjs`, `store.mjs`,
  `deliberation/schema.mjs`) appear anywhere in this cell's `git status
  --short`/`git diff --stat` (verified). This will reproduce for ANY cell
  whose worktree happens to be dispatched under a `.claude/worktrees/`-style
  path — a pre-existing, repo-wide test fragility worth the Coordinator
  filing as its own work item, not something in this cell's own file
  ownership to fix.
- **R6 named-performance note (not a cache, per R6's own instruction):**
  `chainCoordinationUseCase` re-reads and re-replays every matching
  session's full event log on every call (via `readManifest` +

  `chain` invocation. Correctness over speed for v1, exactly as R6

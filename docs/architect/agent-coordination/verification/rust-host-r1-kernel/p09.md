## The node_modules detour

Before trusting anything, the Lead ran the phase's own full-suite gate
(`FULL_TEST`'s first step) and got **343 failures** — vastly more than
anything P09's own narrow Files scope (a new script, a new test file, a
doctor-registrations append, a one-line doc change) could plausibly cause.
Rather than assume a real regression, the Lead investigated:

- Reproduced the same 343 failures in an isolated re-run (deterministic,
  not flaky).
- Confirmed the SAME failures occur identically on the track branch's
  pre-P09 tip (`6c7fcc4c`) in a separate worktree — conclusively not
  P09's diff.
- Traced the root cause: `src/runner/definitions/protocol-loader.mjs`
  loads YAML protocol definitions via `createRequire(import.meta.url)
  .require('yaml')` (CJS resolution, walks up from the *importing file's
  own location*) — and this worktree (`rust-host-r1-kernel-p09`, created
  via `git worktree add`) had **no `node_modules` at all**, unlike other
  worktrees created earlier tonight. Every `CoordinationProtocol` lookup
  silently failed to resolve, cascading through every test that spawns a
  real `fgos coordination run`/workflow/`executeAssignment` subprocess.
- Fixed by symlinking `node_modules` to the main checkout's
  (`ln -s /home/vantt/projects/forgentX/node_modules node_modules`,
  matching what functioning worktrees already carry) — the exact same
  343 failures dropped to 0 in the affected file, confirming the
  diagnosis. Documented as a durable memory
  ([[project_worktree_missing_node_modules_symlink_mass_test_failures]])
  so a future cell's worktree setup checks for this proactively instead
  of re-diagnosing it.

With a clean environment, the full suite showed exactly the documented
pre-existing `cohort-planner` flake plus (at that point) one real,
P09-attributable failure — see Round 1 below.

## Round 1 (reviewer `op_059` + red-team `op_060`, against the uncommitted doer state)

Reviewer, independently re-verifying everything (including cross-checking
which of the 343 environment-gap failures were actually P09-attributable
— correctly narrowing it to exactly one file): "no Doer commit exists...
Core engineering is sound... Do not merge as-is: 3 HIGH findings, 6
MEDIUM, 6 LOW."

- **HIGH-1** — the four new `registerCheck` calls broke
  `test/setup/checks.test.mjs`'s exact-id-list assertion (58 expected vs.
  62 actual, delta exactly the four new ids). **Fixed**: added the four
  ids to that test.
- **HIGH-2** — `rust-host-binary-present`/`legacy-node-payload-present`
  hard-failed `fgos doctor` in *any* project with a `package.json` (i.e.
  nearly every Node project), not just this repo's own checkout — fgOS
  runs globally against other projects (AGENTS.md D-ADR0035), and R4
  explicitly forbids a `registerFix` for these checks, so a user hitting
  this had no remediation path at all. **Fixed**: replaced the
  "any directory with a `package.json`" dev-checkout signal with the Rust
  workspace marker unique to this repo (`apps/fgos/Cargo.toml`), and made
  both checks pass with a "not applicable, skipped" message (matching
  `command-routes-drift`'s own existing graceful pattern) when neither an
  active release nor this repo's own checkout is present.
- **HIGH-3** — the builder silently absorbed a non-empty pre-existing
  `--out` directory's content into the staged tree and its
  `artifactDigest`, breaking the "reproducible from a virgin directory"
  property P11/P12 will stage and verify against. **Fixed**: refuse a
  non-empty pre-existing `--out` (an *empty* pre-existing directory, e.g.
  from `fs.mkdtempSync`, is still fine — that's the test suite's own
  usage pattern).
- MEDIUM-1 — R2's absolute-path refusal wasn't reachable for declared
  *source* entries (only already-staged ones), so `files:
  ["/etc/passwd"]` silently dropped instead of refusing. **Fixed**.
- MEDIUM-2 — a declared `files[]` entry that doesn't exist was silently
  skipped rather than failing the build, so R1's "exactly the declared
  set" wasn't actually enforced (latent, not live: no globs, everything
  exists today). **Fixed**: throws now.
- MEDIUM-3 — `manifest.json` is deliberately excluded from its own
  `files[]`; R2 says `files[]` should include "the manifest itself,"
  reviewer called this "needs a decision, not a blind fix" given the
  genuine self-reference impossibility (files[] is itself part of what
  `artifactDigest` hashes). **Ratified, not reversed**: ratified as the
  correct design (manifest's identity IS `artifactDigest`, not a
  self-entry), strengthened the code comment explaining why.
- MEDIUM-4/5/6, LOW-1..6 — **deferred**, documented below.

Red-team, working from the same uncommitted state, found two MORE real
HIGH findings the reviewer's pass didn't cover:

- **HIGH — `../`-relative traversal in declared `files[]` entries.** Not
  absolute (so round-1's `isAbsolute` guard didn't catch it), but
  `path.join` still resolved it outside the source checkout;
  `files: ["bin", "../outside-payload"]` staged real content from outside
  the synthetic checkout. **Fixed**: added a containment check requiring
  the resolved path stay under the source checkout root.
- **HIGH — doctor's manifest-driven paths had no containment check.** A
  manifest naming `entries.fgos: "/bin/sh"` (or
  `legacyNode: {root: "/etc", entry: "passwd"}`) made both doctor checks
  pass against an arbitrary system binary/file, not the actual fgOS
  release. **Fixed**: added `resolveConfinedManifestPath()`, shared by
  both checks, refusing any manifest path that resolves outside the
  active release root.

Both HIGH findings verified fixed by direct adversarial reproduction
(synthetic `../` entry refused; synthetic `/bin/sh`/`/etc/passwd`
manifest refused) before committing as `531215b9` (round-1 reviewer
findings) and `6df888a4` (round-1 red-team findings).

## Round 2 (session `rust-host-r1-kernel--p09-review2`, against `6df888a4`)

Reviewer: **genuinely clean** — independently reconstructed and
reconfirmed all five previously-fixed HIGH findings as closed via its own
adversarial constructions, re-ran every verification command itself. Only
three LOW/informational residuals, none blocking:

- LOW — the release-tree test's own `artifactDigest` recomputation
  imports the builder's own `canonicalJson`, so a serializer regression
  would be invisible to that specific assertion (the reviewer closed this
  gap manually with an independently-written serializer and confirmed the
  digest is correct — proof strength only, not a correctness gap).
- LOW — doctor's manifest confinement was lexical only (`path.resolve`),
  not realpath-aware — a symlink inside the release tree could still
  escape. Reviewer flagged this as needing write access to the release
  store (a higher bar than a crafted manifest alone) and deferred it to
  P11/P12's store-integrity ownership.
- LOW — `manifest.target` is a hardcoded `{linux,x64,glibc}` literal, not
  derived from the build host. Correct for R1's only approved target;
  matters only once a second target is approved.

Red-team, working independently against the same commit, treated the SAME
symlink-confinement gap as HIGH (not LOW) and found one more real MEDIUM:

- **HIGH — doctor confinement is bypassable through a symlink inside the
  release root.** Confirmed via a direct reproduction:
  `release/bin/fgos` symlinked to `/bin/sh` still passed
  `rust-host-binary-present`, since the round-1 confinement fix only
  checked the lexical resolved string, never resolving symlinks.
  **Fixed**: `resolveConfinedManifestPath()` now also resolves the real
  path (when the target exists) and re-confirms containment against the
  release root's own real path.
- **MEDIUM — the builder accepted an in-root dot-segment `files[]` entry
  that broadened the payload to the whole checkout root.**
  `files: ["bin/.."]` lexically resolves to exactly the checkout root,
  which the round-1 containment fix's `!==` exception explicitly
  permitted — staging (and packaging) the entire source tree, including
  unlisted workspace state, rather than just the declared entry.
  **Fixed**: removed the exception; a declared entry must now resolve
  strictly inside the checkout root, never equal to it.

Both verified fixed by direct adversarial reproduction (a real symlinked
`bin/fgos -> /bin/sh` release; a synthetic `files: ["bin/.."]`
`package.json`) before committing as `886b8bc9`.

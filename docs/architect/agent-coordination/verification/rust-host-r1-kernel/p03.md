## Round 1 (red-team half of session `rust-host-r1-kernel--p03`, against the real commit `134cedc9`)

- Red-team: 1 HIGH — `input_value` alone cannot represent `-0`: JSON has no
  literal that round-trips as IEEE754 negative zero through the FIXTURE
  FILE's own `JSON.stringify`/`JSON.parse` (distinct from the envelope
  serialization under test, which correctly captures the real `-0`
  in-memory). A Rust consumer reconstructing `input_value` from disk would
  get `+0`, never able to test their own serializer's `-0` handling. 1
  MEDIUM — `timestamp_predicate` had no upper bound; an absurdly future
  timestamp (`9999-12-31`) satisfied the regex, `Date.parse`, and
  `min_year` alike. 1 LOW (drift guard correctly caught a manual edit —
  not a defect, confirms the mechanism works).
- **Disposition: accepted, fixed** (commit `c45dac89`): added
  `negative_zero_paths`, a sign-preserving companion field naming every
  `-0`-valued dot-path/bracket-index a consumer must override with a
  literal `-0.0` before re-serializing; added `max_year: 2100` to both
  envelope vectors' `timestamp_predicate`, with a real assertion (not an
  unused field) that a timestamp above it fails range checking.

## Infra notes for future cells (not P16-specific findings)

This cell's own dispatch history is itself informative: 4 of 7 sessions
failed on pure infrastructure (a dispatch-briefing race, a stale
string-identity per-cwd lock that cannot self-heal via pid-liveness, two
separate host-OOM kills of the coordination wrapper under real shared-
machine memory pressure, and a codex agent-startup timeout) — none
related to the actual docs content, which needed only 3 real,
substantive fix rounds once review actually ran. The stale-lock class is
now understood precisely: `dispatchLockFile`'s identity
(`${pid}:${Date.now()}:${random}`) is a string, and
`main-checkout-lock.mjs`'s self-recognition path only probes liveness for
a *numeric* identity — a string-identity lock can only ever clear via its
own TTL (`ttlMs: timeoutMs`, the dispatch's own configured timeout, up to
35 minutes for a herdr-spawn assignment), never by detecting its own
holder process is dead. Removing the lock file directly, after
confirming via `herdr pane list`/`ps` that no other session genuinely
held the cwd, was the correct and fast resolution both times it
recurred.

## Round 1 (session `rust-host-r1-kernel--p08-review`, against `e4c625bc`)

Reviewer, independently re-running every verification command: all
requirements met, boundaries clean, byte-for-byte envelope parity
reconfirmed. Findings:

- **HIGH — `format_iso8601` used wrong Howard Hinnant civil-date
  constants.** `(doe - doe/1024 + doe/1461 - doe/142401) / 365` instead
  of the canonical `(doe - doe/1460 + doe/36524 - doe/146096) / 365`.
  Replicating the exact integer arithmetic: 2010 of 40000 days
  (1970-01-01..2079-07-07) were wrong; the canonical constants give zero
  mismatches. In any given year 2024-2040, 3-5 days -- all in late
  February -- jumped a full year forward, sometimes into a date that does
  not exist (a real 2026-02-28 rendered as `2027-02-31T...Z`). Undetected
  because the existing tests checked only string shape (length-24,
  separator positions, ends-with 'Z'), and the golden-vector tests pin a
  literal expected `generated_at` rather than computing today's date
  through the function -- and the day this bug was introduced and
  reviewed happened to be one the broken constants render correctly by
  coincidence, so even the live parity check against Node passed.
  `data_hash`/`data` were unaffected -- only the envelope's own timestamp
  field was wrong. **Fixed**: restored the canonical constants; added a
  table-driven regression test covering the epoch, a non-leap late-February
  date, a leap day, and the 2100 century-non-leap-year boundary (divisible
  by 4 but not by 400, so not a leap year).
- **MEDIUM — `cargo test -p fgos-distribution` ran against a different
  `serde_json` feature set than production.** `fgos-distribution`'s own
  `Cargo.toml` resolved `serde_json` with default features only (a sorted
  `BTreeMap` for `Value`'s object type), while `apps/fgos` (the crate that
  actually builds the envelope) carries `preserve_order` +
  `arbitrary_precision`. The crate's own vector-parity test passed only
  because `BuildShowOutcome` is a fixed-field struct with no floating
  numbers, not because the proof was general. **Fixed**: mirrored the same
  two features onto `fgos-distribution`'s own `Cargo.toml`.
- **MEDIUM — the performance report had no committed producer.** The Lead
  had run its measurement as a one-off, so R9's numbers weren't
  reproducible from the repo itself; the reviewer independently
  re-measured and got real, close values (both still well within
  budget), confirming the numbers were honest, not fabricated -- a
  reproducibility gap, not an honesty one. **Fixed**: committed
  `scripts/measure-p08-performance.mjs` and re-ran it after the HIGH/MEDIUM
  fixes above (legacy exec overhead p50 0.263ms, native version p50
  6.183ms -- both still comfortably within budget; the point estimate for
  the overhead figure is noted as having real run-to-run variance in LOW-4
  below, irrelevant against the 25ms budget either way).
- LOW-1 -- `cli_projector.rs` ignores its own `operation_id_str`/`args`
  parameters and always builds a `distribution.build.show` request;
  `main.rs` has a matching hardcoded fallback. Unreachable today (exactly
  one native route exists and it always carries this operation id) and
  already documented in-code as an R1 shortcut. **Deferred**: debt for
  whichever future phase adds a second native route.
- LOW-2 -- four `fgos-distribution` tests hardcode `"0.1.0"` and/or
  `verbs.len() == 73`; production code is genuinely non-hardcoded (R2 is
  met), but these tests will go red on the next version bump or route
  addition. **Accepted**, not fixed -- ordinary test brittleness, not a
  spec violation.
- LOW-3 -- the compile-time `include_str!` of `package.json` (R2's own
  explicit requirement) means a version bump without a rebuild leaves
  Node and Rust disagreeing until the next build. **Accepted** as a known,
  plan-directed parity caveat, not a deviation.
- LOW-4 -- the committed legacy-overhead figure is a difference of two
  ~370-430ms measurements with real run-to-run spread larger than the
  point estimate itself; sound methodology, imprecise single number.
  **Accepted** -- irrelevant against a 25ms budget; the report records p50
  only, no dispersion.
- LOW-5 -- `resolve_product_root`'s multi-strategy fallback (env var,
  then `current_exe`-relative, then cwd-if-package.json) is a
  reimplementation of `version.mjs`'s fixed `resolve(dirname, '..', '..')`
  rather than a literal mirror, reachable only in undescribed deployment
  layouts; the debug binary's own real run landed on the correct root and
  matched Node byte-for-byte. **Accepted**, noted as a caveat on R3's
  "mirrors version.mjs's own logic exactly" language.

Fixed as commit `ad43f491`: civil-date constants, table-driven regression
test, `fgos-distribution`'s `serde_json` features, and the committed
performance-measurement script with a re-measured report. Verified: `cargo
test --workspace` (65 passed, up from 64), `cargo fmt --check`, `cargo
clippy -D warnings`, byte-for-byte envelope parity reconfirmed after the
fix (only `generated_at` differs, both real timestamps).

## Gaps

- **Proof 1's settled `status` is `"failed"`, not `"done"`** — this is a
  real, live-proof-only finding, not a proof-authoring mistake and not a
  Non-Goals-violating source defect: `renderAssignmentPrompt`

  `{status, summary}` minimum shape `validateAgentResultClaim`
  (`assignment.mjs:723-767`) actually requires of `agent-result.json` — a
  declared operation's own TaskSpec markdown documents that schema, but a
  standalone inline contract (this proof's own shape, by design) has no
  TaskSpec to read it from. The executor did genuinely good, correct work
  (confirmed by reading `agent-result.json`'s content) but wrote its own
  reasonable application-specific JSON shape instead, and the generic
  evidence classifier correctly, honestly reported the schema mismatch —
  see `proof-1-standalone-inline-read-only.md`'s "Genuine finding"
  section for the full trace. No source change was made (Non-Goals). Worth
  a follow-up item: render the `{status, summary}` minimum shape directly
  into `renderAssignmentPrompt`'s "Result artifact" block for every
  Assignment, declared or inline, not just TaskSpec-documented ones.
- **`index.md`'s ADR-006 §3 row cites an existing, already-logged
  Follow-Up** (the `loop.mjs` planning-sweep dead-output gap) rather than
  a fresh live proof — inline Assignments carry no `resultKind`/`onAdvance`
  at all (ADR-007 §3's own non-driving rule makes this the correct, not

  tests already cover.

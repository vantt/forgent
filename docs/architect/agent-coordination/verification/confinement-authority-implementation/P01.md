**Structural findings for a future Lead (both new, worth carrying into `fgos-plan-loop` SKILL.md):**
1. A driver-authorized `authorize` step must declare `grantedContextRefs` matching whatever the paired `operation` step's own `contextRefs` will name — SKILL.md section 3's template omits this and will hit the same refusal any future fix round copies it verbatim.
2. Re-authorizing the same `(targetActorId, operationId, nodeId)` under a session with a NEW `authorizationId` after an earlier attempt for that same triple was recorded (even if that attempt's own operation dispatch failed) does not take effect — the engine keeps resolving to the first one. A stuck slot needs a fresh `coordinationId`, not a fresh `authorizationId` in the same session.
3. herdr-spawn panes are not reliably isolated to their assigned dispatch `cwd` — three separate rounds in this cell alone had a dispatched agent's writes land in the shared main checkout instead, twice colliding with a real concurrent session's uncommitted work there (`docs/architect/host-invocation-routing/**`, `docs/architect/packaging-distribution/runtime-identity-and-activation.md` — both left untouched, confirmed as someone else's real work, not cleaned up). This is a genuine platform gap, not fixable from inside this track; flagged for separate follow-up, not re-investigated further here per the user's own call.

**Blocking bug found and fixed before this cell's first real dispatch (see P00's own trace for detail):** `src/runner/dispatch/brief.mjs`'s herdr-spawn status vocabulary bug, fixed on `main` at `250a3edf`.

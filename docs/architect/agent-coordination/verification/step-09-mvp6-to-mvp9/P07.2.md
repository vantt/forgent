## Design notes (why this shape, not another)

- **No "claimed outcome" input.** The candidate contract's
  `aggregation-validated` event (P00.2.md §3) carries an `outcome` field,
  which could be read as "the caller asserts an outcome, and this module
  validates the assertion." That shape was rejected: it would require this
  evaluator to reason about *trusting* a caller-supplied claim, and the
  cell's own Bug Taxonomy explicitly warns against "classifying consensus
  from source-coverage alone" — a trust-the-claim design invites exactly
  that shortcut (e.g. accepting `outcome: 'consensus'` whenever coverage
  passes, without ever checking dissent). Instead `classifyAggregationOutcome`
  has no `outcome` parameter at all: the outcome is always *derived* from
  the evidence supplied. This makes "reject a claimed consensus outcome
  when hidden/unresolved dissent exists" true by construction — there is no
  code path that can *produce* `'consensus'` while hidden or unresolved
  dissent is present, so there is nothing to separately reject.
- **Dissent-surfacing convention: `disclosures.dissent`, reserved id.**
  `disclosures` is a generic `id -> value` map (P07.1's own shape); this
  cell treats `dissent` as a reserved disclosure id by convention (already
  used in P07.1's own test fixtures, e.g. `disclosures: { confidence:
  'high', dissent: 'none' }`). A value of exactly `'none'`, or the key's
  absence, means "nothing disclosed"; any other well-typed string value is
  a disclosed objection. This was chosen over inventing a separate
  top-level `disclosedDissent[]` input because it reuses the shape P07.1
  already established rather than adding a second way to say the same
  thing.
- **`dissentRefs[]` matched by `sourceOperationRef` (ref-level), not the
  finer per-source composite key.** `validateDisclosureValueShapes` and
  `validateSourceRevisionCurrency` report per-source-entry problems using
  the same `sourceOperationRef:assignmentId:runId` composite key P07.1's
  `missingDisclosuresBySource` already established (multiple contributors
  can share one `sourceOperationRef`). Dissent is conceptually a property
  of the *declared operation* being contested, not of one specific
  contributor's run, and the candidate contract's own field is
  `dissentRefs` (plural of a ref, not a composite key) — so hidden-dissent
  matching is done at the `sourceOperationRef` level: one dissent entry
  covering that ref surfaces dissent disclosed by any source under it.
- **Stale-revision input keyed by `artifactRef`, not `sourceOperationRef`.**
  P07.2-remainder's own contract text says "given a caller-supplied
  'current revision' reference map alongside the sources... reject any
  source whose `revision` doesn't match the corresponding current-revision
  entry" without naming the key. `artifactRef` is the field that actually
  identifies *which artifact* a revision belongs to (`sourceOperationRef`
  can be shared by more than one contributor's source entry pointing at
  different artifacts); keying by `sourceOperationRef` would silently
  conflate two different artifacts under one revision check. This module
  still has zero session/store access (P07.3 integration concern, per
  P07.1's own Gaps) — `currentRevisions` is a plain pure-function argument,
  never fetched.
- **Fail-closed on a missing `currentRevisions` entry.** The cell's own Bug
  Taxonomy names the exact failure mode: "accepting a stale revision
  because the 'current revision' input itself wasn't validated against
  anything (garbage-in-garbage-out silently accepted)." An empty or
  incomplete `currentRevisions` map must never let sources through as
  "current" by default — `validateSourceRevisionCurrency` treats a missing
  entry the same as a mismatched one (both add the source to
  `staleSourceKeys`), and `validateCurrentRevisions` (schema.mjs) rejects a
  non-object or a non-string revision value outright, so a garbage map
  fails at the shape level before it can be silently trusted.
- **Malformed-disclosure-value shape: non-empty string, nothing richer.**
  P07.1's Gaps section explicitly deferred "what a disclosure's value must
  look like" to a later cell. The minimal well-typed shape chosen here is
  "every disclosure value must be a non-empty string" — matches every
  existing fixture (`'high'`, `'none'`, objection-reason strings) and rules
  out the classes of malformed input closest to hand (numbers, arrays,
  nested objects, booleans, empty strings) without inventing per-disclosure-
  id semantics (e.g. a `dissent`-specific enum) that would go beyond what
  this cell was asked to define.
- **Deterministic three-branch rule, no scoring.** `classifyAggregationOutcome`
  is `if (coverage/disclosureShape/revisionCurrency/dissentSurfacing not ok)
  no-consensus; else if (any dissentRefs entry unresolved) qualified; else
  consensus` — a fixed evaluation order over boolean flags and
  `.length > 0` checks, matching plan.md's Non-Negotiable Deferrals ("No
  vote, weighted vote, rank tally, convergence engine, or prose-parsed vote
  in MVP7/MVP8") and this cell's own Bug Taxonomy warning against "any
  hidden numeric scoring/weighting that is actually a vote in disguise."
- **Same immutability discipline as P07.1's Fix Rounds.** `classifyAggregationOutcome`
  freezes its result at every level (top-level object plus each of the four
  nested sub-results, each already frozen by its own function), and a
  dedicated test deep-freezes all five inputs before calling it —
  reproducing P07.1's own "input mutation" test pattern rather than
  inventing a new one.

## Gaps

- `missingActors`/`failedActors` (candidate contract fields, P00.2.md §3)
  are still not modeled anywhere in this module — phase-07.md's own P07.1
  cell description names "missing/failed-actor accounting" as explicitly
  out of scope for both P07.1 and this cell; still open for a later cell.
- The `dissent` disclosure id's *value* is still just checked for
  well-typedness (non-empty string), not for any richer taxonomy (e.g. a
  fixed enum of objection categories). This cell's Malformed-disclosure
  requirement was scoped to "at least well-typed," and a stricter
  per-disclosure-id schema was judged out of scope (would start defining
  disclosure *semantics* beyond shape, which is a product decision, not a
  shape-validation one).
- No fixture exercises two DIFFERENT sources under the same
  `sourceOperationRef` where only one discloses dissent — the
  ref-level-matching design note above documents the intended behavior
  (one dissent entry covers the whole ref), but it is asserted by design
  reasoning, not a dedicated test. Left open since P07.1's own Gaps section
  already flagged multi-source-per-ref semantics as unresolved policy
  territory belonging to outcome classification (this cell) — the specific
  "two sources, one dissents" combination is a natural next fixture for
  P07.3 integration work if it turns out to matter there.
- No real `RunResult`/artifact fixture reused from
  `src/runner/dispatch/assignment-runner.mjs` — same gap P07.1 already
  named; unchanged by this cell.

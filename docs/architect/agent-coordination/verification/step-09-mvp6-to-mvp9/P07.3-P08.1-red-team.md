## Attack 1 — Terminal-transition authority bypass

**Held in isolation. Neutralized in practice by Finding 1.**

`aggregation-validated` is consumed in exactly one place:
`closeSessionByQuorum`'s optional `aggregationId`
(`src/runner/coordination/session-engine.mjs:2858`). A repo-wide grep for
`.aggregations` returns only that one read site plus its own comment. The gate is
strictly refuse-only: it throws on a missing record or a non-`consensus` outcome
and never selects a status, relaxes `partialPolicy`, or closes anything quorum
would refuse. No existing quorum/fan-in path auto-consumes the new event kind. So
the wiring itself does not drive or influence a transition, and the evaluator's
return value cannot reach `transitionSessionStatus`.

That said, "refuse-only" is only a safety property while the refusal cannot be
switched off. Finding 1 shows it can be.

### Finding 1 (HIGH) — `validateSessionAggregation` trusts a caller-supplied FlowDefinition

`src/runner/coordination/session-engine.mjs:3061-3069` takes `definition` as a
parameter and never resolves or checks it against `manifest.definitionRef`. Every
input the verdict depends on — which operations are sources, which graph bindings
each source operation has, and `requiredDisclosures[]` — is read off that
caller-supplied object. `resolveOperationOutcome` is then called with the same
object, so the attacker also chooses the cohort membership the all-of rule is
evaluated over.

This directly falsifies P07.3.md's own claim:

> "What the mediated path guarantees is that `validateSessionAggregation` — the
> only door that *derives* evidence — cannot be talked into a favorable verdict,
> because it takes no verdict as input."

It takes no `outcome`. It takes the declaration that determines the outcome.

**PoC** (`/tmp/rt-attack-terminal-bypass.mjs`): both researchers settle
(quorum is satisfied), then `researcher-a`'s settled `agent-report.md` is edited
after settle — the exact tamper shape P07.3's own staleness test uses. The
attacker calls the sanctioned door with a definition object identical to the real
one except that `research` is wired only to the untampered `researcher-b`:

```
CONTROL (real bound definition)    outcome = no-consensus
ATTACK  (caller-supplied definition) outcome = consensus | missingActors = undefined
        sourceResultRefs = ["asgn_coordinator_1_op_002"]
REPLAY  accepted agg_forged        = true | outcome on ledger = consensus
CLOSE   status = completed <-- session closed on a forged consensus
```

No raw store door. No hand-written `events.jsonl`. A real
`classifyAggregationOutcome` call, genuinely linked source refs, a correct driver
identity, and a session that terminates `completed` on a consensus its own
declared protocol would have refused.

Everything the cell claims to enforce is selectable this way: the all-of
partial-cohort rule (Attack 2), `validateSourceRevisionCurrency`'s tamper check
(above), `requiredDisclosures` coverage, and the hidden-dissent check (drop the
blocked contributor's binding instead of the tampered one).

This is the P06.2 pattern the cell contract warns about: a claimed trust boundary
that a sanctioned API reaches past. Replay cannot compensate — it is
definition-blind by design, which the trace correctly explains but then treats as
a reason the *mediated* door must be trusted, rather than as a reason the
mediated door must resolve the definition itself.

**Smallest fix.** Resolve the definition inside the function from
`manifest.definitionRef`, with the version-drift refusal, exactly as the four
other definition-consuming functions in this same file already do
(`session-engine.mjs:1362` / `1729` / `2279` / `2420`; the drift message at
`1366` is the model). `validateSessionAggregation` is the only one that does not.

**Do not fix by comparing `definition.metadata.id`/`version`** — the forged
definition in the PoC carries byte-identical metadata. Only loading from
`manifest.definitionRef` closes it.

Mitigating context, stated fairly: there is no production caller yet
(`grep` finds only tests), so nothing ships broken today. It is blocked because
the trace documents this door as the safe one, and a future P07.4 CLI wiring will
reasonably trust that documentation.

### Finding 1b (LOW-MEDIUM) — a single-source aggregation throws instead of recording `no-consensus`

`missingActors`/`failedActors` are accumulated at `session-engine.mjs:3113-3114`
and then discarded when `sourceResultRefs.length === 0` throws at `3146-3151`.
With one declared source operation — the likeliest protocol shape — any failed or
missing contributor means no source survives, so the driver gets an exception and
**no `aggregation-validated` event naming the gap is ever written**. The cell's
"named, never dropped" property holds only when a second source operation
survives to carry the event, which is why the Doer's own half-answered-cohort test
declares two. Reproduced as the `CONTROL` line in both PoCs above.

Fix direction: record a `no-consensus` event carrying the named
`missingActors`/`failedActors` instead of throwing, or state the single-source
limitation explicitly in the trace.

### Finding 1c (LOW-MEDIUM) — schema accepts `requiredDisclosures: []`; the evaluator throws on it

matching the reasoning already applied one line above it for `sourceOperationRefs`.

### Finding 2 (MEDIUM) — the "real provenance" requirement is presence-only, with no channel to make it real

`validateContributionShape` requires `assignmentId`/`runId`/`artifactRef`/`revision`
to be non-empty strings and checks nothing else about them
(`src/runner/deliberation/schema.mjs:130-135`). Concretely accepted today:

- `assignmentId: 'asgn_someone_else_op_777'` from a different coordination
  session, with an `artifactRef` under `.../coord_session_BRAVO/...`;
- `assignmentId: 'totally-made-up'`, `runId: 'not-even-a-runid-shape'`;
- `runId: 'run_asgn_coordinator_1_op_001_../../../../tmp/evil-marker'` — the exact
  malicious-suffix shape `store.mjs:1277 assertValidRunIdForAssignment` exists to
  refuse one boundary over (harmless here since this module joins no paths, but it
  is passed downstream as a ref).

This is the current-cell.md Bug Taxonomy item *"accepting a contribution with a
fabricated (non-real) Assignment/Run reference"*, unclosed. P08.1.md's Proof
Matrix row **"Real Assignment/Run provenance required"** cites a test that only
proves *missing* provenance is rejected — the row overclaims what it proves.

The structural half matters more than the wording: `context` accepts only
`{sessionId, declaredOperations, knownContributions}`, so a diligent P08.2 caller
has **no channel** to supply assignment provenance. The API shape itself forecloses
the fix.

### Finding 3 (MEDIUM) — "right type, wrong operation": `operationRef` is unbound to provenance

`validateOperationDeclaresType` (`deliberation/schema.mjs:159-169`) checks that the
*claimed* `operationRef` declares the type. Nothing anywhere binds `operationRef`
to `assignmentId`/`runId`. A contributor whose run answered `proposal-round` may
label its contribution `operationRef: 'objection-round'` and post an `objection`;
it validates.

This is precisely the P06.2 bug class one boundary over — "an Assignment that
merely shares an actor or a claim key answers nothing" — which the coordination
layer needed the reserved `protocol-operation:` stamp channel to close
(`session-engine.mjs:1117-1136`). The deliberation module has no equivalent
channel, and its `context` shape cannot express one.

**Smallest fix (Findings 2+3, one change):** extend `context` with an optional
`knownAssignments: Map<assignmentId, {sessionId, operationRef}>`, and when
supplied, require the contribution's `assignmentId` to resolve, to belong to
`sessionId`, and to carry the claimed `operationRef`. Populating it stays P08.2's
job; declaring the channel is P08.1's, since P08.2 cannot add it without changing
this module's public signature. Independently and for free: assert
`runId === \`run_${assignmentId}_<digits>\``, mirroring
`assertValidRunIdForAssignment` — self-contained, needs no new context, and closes
the traversal-shaped and mismatch cases. And correct the Proof Matrix row to say
what its test actually proves.

### Finding 4 (LOW) — inherited `allowedTypes` honored

`declaredOperations[operationRef]` (`deliberation/schema.mjs:161`) walks the
prototype chain, so a `declaredOperations` built with `Object.create(proto)`
legalizes types from `proto`. Caller-controlled and low impact. Fix:
`Object.hasOwn(declaredOperations, operationRef)`.

## Attack 5 — Mailbox / message-inbox smell

**Held.** `recipient`, `status`/`unread`, and free-form `body` are all rejected by
the field whitelist. More decisive than the whitelist: the contribution record has
**no author/actor field at all**, so "enumerate my contributions" is not answerable
from a contribution — only indirectly through `assignmentId`, which this module
neither resolves nor owns. The module exports validators only; `knownContributions`
is a caller-supplied `Map`, so no enumeration surface exists here.

`roundKey` and `visibilityWindowRef` are free strings and will accept
`'to:researcher-b'` / `'inbox:researcher-b'`, but they are opaque provenance keys
this module never interprets, and no delivery, unread, or mutation semantics
attach to them. Not a mailbox. `respondsTo`/`anchors` give a threading graph,
which is exactly the typed lineage the contract asks for and explicitly not
message delivery.

No vote/rank/weighted-scoring/convergence machinery entered either module:
`validateSessionAggregation` contains no arithmetic, threshold, or tally, and
`rank` in P08.1 is only an enum member with no counting attached.

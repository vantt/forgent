## 3. EXACT Contract Assertions for Phase 01 Implementation

Phase 01 (`phase-01-two-mode-facade.md`) must turn the following three explicit contract assertions into automated tests in `test/setup/skill-wrappers.test.mjs` and `test/architecture.test.mjs`.

### Assertion 1: Mode-Selection Rule (R2)

- **Source References:**
  - [`docs/architect/agent-coordination/verification/code-panel-multicell-facade/index.md`](file:///home/vantt/projects/code-panel-multicell-facade-p00/docs/architect/agent-coordination/verification/code-panel-multicell-facade/index.md) §3 (Ownership Boundary table, Mode Selection row)
  - [`plans/260915-code-panel-multicell-facade/phase-00-contract-and-baseline.md#L13-L18`](file:///home/vantt/projects/code-panel-multicell-facade-p00/plans/260915-code-panel-multicell-facade/phase-00-contract-and-baseline.md#L13-L18)
  - [`plans/260915-code-panel-multicell-facade/phase-01-two-mode-facade.md#L11-L16`](file:///home/vantt/projects/code-panel-multicell-facade-p00/plans/260915-code-panel-multicell-facade/phase-01-two-mode-facade.md#L11-L16)
- **Contract Specification:**
  1. **Direct Single-Cell Selection:**
     - Any request for a concrete code change without a plan execution target selects `direct-single-cell`.
     - Crucially: A request that merely **cites or references** a plan or phase path in passing (e.g. *"fix the bug described in plans/260915-foo/plan.md"*, *"check tests according to plans/bar/phase-01.md"*) without an explicit instruction to run or resume the plan/track is NOT multi-cell; it STAYS `direct-single-cell`.
  2. **Planned Multi-Cell Selection:**
     - Planned mode requires the plan or phase path (`plans/<name>/plan.md` or `plans/<name>/phase-NN-*.md`) to be the **actual execution target** of the request (e.g. `plans/260915-foo/plan.md`), OR
     - The request contains an **explicit run/resume instruction** directed at the plan/track (e.g. *"run this implementation plan"*, *"resume track plans/260915-foo/plan.md"*, *"execute this code implementation track"*).
  3. **Anti-Guessing / Ambiguity Refusal:**
     - Genuinely unresolved or ambiguous user intent (e.g. contradictory directives or multiple unresolvable targets) MUST be refused or prompt the user for clarification.
     - The system must NEVER silently guess or default to either mode.
- **Concrete Expected Outcomes & Tests for Phase 01:**
  - `classifyCodePanelRequest("implement fix for auth bug in src/auth.mjs")`
    - Expected: `{ mode: "direct-single-cell", target: "src/auth.mjs" }`
  - `classifyCodePanelRequest("fix the bug described in plans/260915-foo/plan.md")`
    - Expected: `{ mode: "direct-single-cell", passingCitation: "plans/260915-foo/plan.md" }` (passes citation test: does not enter planned mode)
  - `classifyCodePanelRequest("run this implementation plan: plans/260915-foo/plan.md")`
    - Expected: `{ mode: "planned-multi-cell", planPath: "plans/260915-foo/plan.md" }`
  - `classifyCodePanelRequest("resume track plans/260915-foo/plan.md")`
    - Expected: `{ mode: "planned-multi-cell", planPath: "plans/260915-foo/plan.md" }`
  - `classifyCodePanelRequest("plans/260915-foo/plan.md")`
    - Expected: `{ mode: "planned-multi-cell", planPath: "plans/260915-foo/plan.md" }`
  - `classifyCodePanelRequest("maybe do something with plans/260915-foo/plan.md or fix bar")`
    - Expected: Refusal / throws `AmbiguousIntentError` / prompts for clarification.

### Assertion 2: Delegation Boundary

- **Source References:**
  - [`domains/coding/skills/fgos-code-panel/SKILL.md#L24-L74`](file:///home/vantt/projects/code-panel-multicell-facade-p00/domains/coding/skills/fgos-code-panel/SKILL.md#L24-L74) (Code-panel ownership and non-goals)

- **Contract Specification:**
  1. When in `planned-multi-cell` mode, `fgos-code-panel` MUST delegate track execution to `fgos-plan-loop`'s driver **exactly once** per track invocation.
  2. `fgos-code-panel` MUST NOT contain or execute any of the following lifecycle orchestration logic:

     - Composing or executing cell open requests (`open.json`).

     - Recognizing input and selecting mode.
     - Materializing the 3-tier coding test-policy overlay (`FOCUSED_TESTS`, `AFFECTED_TESTS`, `FULL_TEST`, `FULL_TRIGGERS`).
     - Invoking `fgos-plan-loop` with the plan target and policy overlay.
  4. `fgos-plan-loop` remains the sole, generic owner of multi-cell track execution and contains no coding-domain branches (`trackKind: code`).
- **Concrete Expected Outcomes & Tests for Phase 01:**
  - Delegation Test 1: In `planned-multi-cell` mode, execution spy on `fgos-plan-loop` verifies it is invoked with `{ planPath, testPolicyOverlay }` exactly once.

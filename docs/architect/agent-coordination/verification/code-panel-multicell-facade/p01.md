Deliver the two-mode facade implementation for `fgos-code-panel`:

4. **No-Duplication Discriminator (Assertion 3):** Ensure `fgos-code-panel` does not reimplement the multi-cell orchestration loop from `fgos-plan-loop`.

## 2. Independent Recheck Findings & Resolution (op_027 Fix Round)

Following independent review (`claude-reviewer`, op_025) and adversarial analysis (`codex-cli`, op_026), eight concrete, nameable defect items were addressed and verified:

### (1) [R-M4 / NEW-1] Hermetic CE1 Track Resolution
- **Issue:** The CE1 test previously resolved `resume the dispatch-operability-implementation track` only because the host machine's gitignored `.fgos/coordination/sessions` directory existed; on a fresh clone or in CI, the test threw `AmbiguousIntentError`.
- **Fix:** Added an explicit options hook to `hasLiveCoordinationSession` and `classifyCodePanelRequest` (`options.hasLiveSession(candidate)` and `options.sessionsDir`). Updated the CE1 test assertion to resolve primarily via a committed `plan.md`'s own `Track:` header (`code-panel-multicell-facade`), while testing the live session path hermetically via the options hook and fixture directory.

### (2) [R-H1 / NEW-2] Track-by-Name Negation Handling
- **Issue:** Negation regex previously only matched single tokens ending in `.md` or the literal `track` immediately after the verb. Negation on a track referenced by name (`never run the code-panel-multicell-facade track, just fix src/x.mjs` or `don't resume the dispatch-operability-implementation track`) failed negation matching and fell through to step 11, incorrectly executing the track.
- **Fix:** Extended `negationOnPlanMatch` to cover `(don't|do not|never) (run|resume|execute) (the )?<name> track`, `track <name>`, and `open the next cell for <name>`. Both path and track-name negations now route through the affirmative alternate target branch or throw `AmbiguousIntentError`.

### (3) [NEW-7] Recursive Dispatch Whitespace Trimming
- **Issue:** `coordinationId` or `workRef` with trailing newlines or spaces (as commonly produced by `echo` or file reads) failed the un-trimmed regex `cellIdPattern` (`/.+--[a-zA-Z0-9_-]+$/`), causing the guard to fail open.
- **Fix:** Trimmed `coordinationId` and `workRef` strings before evaluating `cellIdPattern`.

### (4) [NEW-8 / R-M2] CE5 Path Shape Restriction
- **Issue:** The explicit run instruction regex accepted any `.md` file (`run docs/README.md`, `execute CHANGELOG.md`), promoting general markdown runs to `planned-multi-cell`, which contradicted CE5 prose restricting the rule to `plan.md` or `phase-NN-*.md`-shaped files outside `plans/`.
- **Fix:** Restricted the path-matching group in `explicitRunPlanMatch` to `(?:plans/[^\s,;]+|[^\s,;]*(?:plan|phase-\d+[^\s,;]*)\.md)`. Non-plan markdown runs remain `direct-single-cell`.

### (5) [NEW-9 / R-M3] Clause-Level Conditionals & Hedges
- **Issue:** Conditionals without commas (`if CI is green run plans/X/plan.md`) and trailing conditionals (`run plans/X/plan.md if the tests pass`) bypassed the line-anchored/comma-requiring check and promoted to planned mode.
- **Fix:** Evaluated instructions at the clause level (`trimmed.split(/[;\n]+/)`). Any clause containing a plan/track reference and a run verb co-occurring with conditional keywords (`if`, `unless`, `in case`, `provided`, `assuming`), hedges (`should`, `would`, `could`, `might`, `can`, `shall`, `may`, `wonder if`), speculative markers (`maybe`, `perhaps`), past tense (`I/we ran`), or question marks throws `AmbiguousIntentError`.

### (6) [NEW-10] CE3 Phase of Track Resolution
- **Issue:** Phrase `run phase-02 of the <track> track` previously captured `the` as `planPath`, returning a non-path string.
- **Fix:** Updated the phase target parser to strip track preambles/suffixes and resolve bare track names via `resolveTrackNameToPlanPath(candidate, repoRoot)`. Unresolvable track names throw `AmbiguousIntentError`.

### (7) [NEW-5] Semicolon Statement Splitting in Discriminator
- **Issue:** The statement splitter previously split only on `[.!?\n]`, treating `Do not skip verification; repeat this process for every cell until all are closed.` as a single statement shielded entirely by the leading negation.
- **Fix:** Added `;` to the statement boundary delimiter (`.split(/(?<=[.!?\n])\s+|;\s*/)`), ensuring affirmative statements following a semicolon are checked independently.

### (8) [NEW-6] Quote-Stripping Apostrophe Collision
- **Issue:** The quote-stripping regex treated single apostrophes as quote delimiters, causing contractions and possessives (`plan's`, `That's`) to strip large spans of normal prose (~51% of canonical `SKILL.md`), blinding the fragment detector.
- **Fix:** Replaced quote-stripping with double-quote-delimited spans only (`skillContent.replace(/["\u201c][^"\u201d]*["\u201d]/g, '')`). Single apostrophes are preserved, allowing contractions without discarding text.

## 3. Scope Boundary & Limitations Note for Assertion 3 (Item 9)

Both independent reviewers (op_025 and op_026) noted that semantic duplication detection in natural language prose is fundamentally heuristic. A sufficiently adversarial rewrite (novel synonyms, dense compound sentences, split sections with arbitrary headings) can evade static regex pattern matching.

**Accepted Scope Boundary:**
> This discriminator (`validateCodePanelNoPlanLoopDuplication`) is a **BEST-EFFORT LINT** that catches naive/accidental duplication (verbatim or near-verbatim copies using `fgos-plan-loop`'s own anchor phrasing). It is **NOT** a comprehensive security boundary against a deliberate, adversarial rewrite, which only human code review can reliably catch. This is the accepted, documented scope boundary for Assertion 3, not a gap to keep closing.

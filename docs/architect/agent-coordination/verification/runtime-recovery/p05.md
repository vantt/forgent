# P05 — Deterministic Standalone-Run Recovery Planner and `dispatch recover` Door — Cell Trace

**Track:** runtime-recovery
**Coordination session:** `runtime-recovery--p05`
**Merge commit:** `fed6301f` (merges `runtime-recovery--p05`, tip `fa0a739c`) directly into `main`

## What landed

- `src/runner/dispatch/recovery-planner.mjs` (new): pure `plan(snapshot, evidence, requestedIntent) -> RecoveryRecommendation`. No fs/adapter/network imports — consumes already-read facts. Deterministic modulo `actionKey`/`expiresAt`. `actionKey` is derived from `(snapshotHash, controlEpoch, action, expiresAt)` so a still-unconsumed key cannot be replayed against a different action or a re-declared expiry.
- `src/verbs/dispatch/recover.mjs` (new): `dispatch recover <runId>` — without `--action`, a read-only, ephemeral recommendation (no session event, no mutation). Applying requires all five of `--action`/`--expected-snapshot`/`--expected-control-epoch`/`--expected-expires-at`/`--action-key`; the write path re-derives current state under a short CAS critical section, fenced against the Run's real P01 `run-lock.mjs` control-epoch generation (never a shadow `run.json` field), with the settled-status recheck sequenced as the very last read immediately before the write.
- Never imports from `src/runner/coordination/` and never appends a coordination-session event — standalone Assignment-owned Run recovery stays outside session authority, per the contract.
- Registered in `bin/fgos.mjs`/`src/cli/command-registry.mjs` beside the existing `dispatch show-run` door.
- New tests: `test/verbs/dispatch-recovery.test.mjs` (36 cases covering determinism, missing-expectation refusal, stale/expired-plan refusal, action-key idempotency and cross-binding, concurrent single-winner races, control-epoch fencing, and the settle-vs-apply race).

## Fix rounds (3 rounds)

1. **Fix-1**: HIGH finding (both reviewer and red-team) — `expectedControlEpoch` was a shadow field read from/written to `run.json` directly, never the Run's real P01 control epoch tracked by `run-lock.mjs`'s `control/generations/`, so a live controller takeover between plan and apply was never actually fenced. Fixed by routing the epoch check through `run-lock.mjs`'s own real generation primitive. Also fixed in this round: a CAS-vs-settle-writer race (F5, first pass), a snapshot-hash blindness to settled runs (F1), `actionKey` not binding to the action/expiry it was issued for (F3), a dead-PID `.recovery.lock` with no reclaim (M1), and missing `docs/architecture-manifest.json` rows (M2).
2. **Fix-2**: independent recheck showed F5 (settle-vs-apply race) was only narrowed, not closed — 74/100 real out-of-process trials still applied a `resume-driver` action after settlement, because the settled recheck ran *before* the CAS/write section rather than as its last step. Fixed by reordering: acquire the real control-epoch CAS, then re-read settled status as the final check immediately before the write. Reduced the reproduction rate to 0/100 (both reviewer and red-team independently confirmed with their own unmodified 100-trial harnesses). A genuinely architectural residual remains (a settle write landing in the few-millisecond window after the generation link but before the ledger append still records one harmless ledger line) — confirmed unavoidable within this cell's lease, since no settle-writer path takes `.recovery.lock` and none is part of this cell's leased files. Also added a `settledSignal` park check to the read door (R3) and fixed a flaky test asserting inequality on now-deterministic `actionKey`s (R1).
3. **Fix-3**: the fixer's own new F5 stress test (added in fix-2) was itself deterministically broken — it raced a worker thread against a synchronous apply call with an unreliable timing assumption, so it always reported the (correct) applied result as a safety violation. Fixed with a deterministic injection instead of a wall-clock race; the reviewer mutation-tested the fix by reverting the production reordering in a scratch copy and confirming the test then correctly fails 20/20.

Final recheck (reviewer): **PASS** — F5 test genuine and deterministic (10/10 green, mutation-tested), focused lease 36/36, no new regression beyond pre-existing unrelated failures (architecture-manifest rows for other files, `coordination-research-fan-out` R5).

## Deferred / accepted as non-blocking

- **F5-residual (LOW)**: a settle write landing in the narrow window after the control-epoch generation link but before the recovery ledger append still records one benign ledger line (never a false "safety enforced" claim, never a duplicate real effect) — confirmed architectural: no settle-writer path in the codebase (`assignment-runner.mjs`'s `markRunSettled`/`reconcileRun`, `cli.mjs`'s `closeRun`, the worker's own `outbox/result-N.json`) takes `.recovery.lock`, and none of those files are in this cell's lease.
- **N2 (LOW)**: a held recovery CAS is invisible to a real driver's own liveness/control probe for the ~6ms hold duration — not re-measured after the reordering fix, unchanged from the original finding.
- **R4 (LOW)**: an empty `.recovery.lock` from a crash between `open` and the pid write is a microsecond window, never reclaimable by design (pid can't be read), backstopped by the same P01 CAS so it never causes a duplicate effect.
- **R5/PRE-ARCH/PRE-R5**: pre-existing, unrelated failures confirmed identical on the parent commit — `docs/architecture-manifest.json` missing rows for `read-evaluators.mjs`/`cli-spawn-supervisor.mjs` (P04/P02L's files, not this cell's), and `coordination-research-fan-out.test.mjs`'s R5 concurrency test.

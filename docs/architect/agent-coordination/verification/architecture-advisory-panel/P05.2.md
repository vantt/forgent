## Prerequisite infrastructure work (not originally scoped, evidence-forced)

Getting from "register 3 executors" to a real, completed 9-phase
session through the actual product path surfaced five real,
previously-undocumented platform gaps, each filed as its own work item
rather than silently worked around:

- **`tsk-1o4` (resolved as part of this cell)** — `claude-bwrap`,
  `agy-bwrap`, `codex-readonly` were never registered in
  `.fgos/config.json`'s executor registry, so naming them in
  `actors[]` silently fell back to the unconfined global default.
  Registered all three, live-verified safe again after registration
  (repeated attack-probe testing against a real target repo — see
  Confinement re-verification below) and functionally correct for
  legitimate work.
- **`tsk-31d`** — `agy -p` (headless print mode) ignores the invoking
  OS process cwd for *relative* path resolution and defaults to a
  stale internal scratch workspace, confirmed both confined and
  unconfined (not a sandboxing side effect). Real, usable workaround
  found and used throughout this cell: absolute paths in every
  dispatched prompt, for both the material being read and the result
  artifact being written.
- **`tsk-63z`-adjacent, disclosed inline in `claude-bwrap`'s own
  config comment** — the coordination engine expects
  `agent-result.json` at the *run's own directory* under this repo's
  `.fgos/assignments/`, not at the target project's cwd, regardless of
  which project is being advised about. A fully read-only bwrap mount
  left a real dispatch with a real, correct, schema-valid answer
  unable to report it at all (`no-evidence`) until a single, fixed,
  additive writable exception (`.fgos/assignments`, not the target
  project) was added to the mount.
- **`tsk-1ed`** — `renderAssignmentPrompt`'s own auto-generated prompt
  tells a worker *where* to write its result but never *what shape*
  the JSON must take (the allowed status enum, required fields). A
  real dispatch with no `taskSpec` produced a substantive, correct
  answer that failed schema validation on a plausible-but-wrong status
  string borrowed from an unrelated convention. Worked around by
  embedding the exact schema in every dispatched objective; the
  platform gap itself remains open.
- **`tsk-oed`** — `aggregateBounds` carries a third, undocumented
  bound (`wallTimeMs`, default 3600000ms/1 hour) beyond the two named
  in SKILL.md/the how-to guide (`maxRounds`, `maxAssignments`). A real
  session with unused round/assignment budget still hit a permanent
  wall-time refusal purely from real-world delay (two OOM kills from
  unrelated system memory pressure), forcing a fresh session.
- **`tsk-3yo`** — the coordination engine's own mutation-detection
  (`evidence.json`'s git-diff before/after) is not causally isolated:
  it attributes *any* change to the cwd's git tree during the dispatch
  window to the dispatched executor, with no way to distinguish a real
  confinement breach from an unrelated concurrent editor (a different,
  legitimate Claude Code session was independently, verifiably active
  on herdr-gateway at the time — confirmed via `who`, process
  timestamps, and the mutated content being entirely unrelated to
  anything the dispatch's own prompt discussed) touching the same repo
  during the same wall-clock window. Two real assignments were falsely
  marked `failed` this way despite correct `agentClaim`s; both were
  recovered by opening a fresh session/attempt with the same content.

None of these five were fixed in-cell beyond what was needed to get a
real, working P05.2 session — matching this track's own established
scope discipline (a proof cell files gaps, it does not fix the
platform).

## Real implementation of both accepted recommendations

Not simulated, not left as a TODO — implemented and verified against
the real herdr-gateway repository, on the person's own explicit
instruction:

- Landed the panel's own drafted fixture corpus
  (`web/test/fixtures/terminal-blocks.ts`) and confusion-matrix scorer
  (`web/test/block-classify-corpus.test.ts`). First real (not
  hand-traced) run: **false wrap 4/13 = 30.8%**, exactly matching the
  panel's own hand trace. Fixed all four real gaps
  (`stableGutters`'s min-width scan bug; missing `git log --graph`,
  `git diff`, and compiler-underline detectors). Second real run:
  **false wrap 0/13 = 0.0%**.
- Named the module's own Claude-specific boundary in place (no
  `harness/` subsystem, no adapter interface, no registry — exactly
  the smaller of the panel's own two options) and, going further than
  the panel's own explanation could (no shell, no live pane
  access), **captured two real coding-agent panes through herdr**
  (`herdr agent start`/`herdr agent read` against a real `codex` and a
  real `agy` process) to settle the disclosed-but-unverified glyph
  question live:
  - Codex's real menu (`› 1. Yes, continue`) used a different cursor
    glyph (U+203A) than Claude's (U+276F) for the identical concept,
    exactly as the panel's documentary evidence predicted — and it
    really did wrap incorrectly before the fix. Fixed:
    `MENU_CURSOR_ITEM`/`MENU_ITEM` now recognize both verified
    glyphs.
  - Agy's real menu used no cursor glyph and no enumerator at all —
    ASCII `>` plus foreground color alone, a shape this classifier
    cannot and should not key on from plain text (color is
    deliberately never read; a bare `>` is too common in prose).
    Left wrapping, disclosed in both a source comment and a
    real-capture-shaped regression test, not silently dropped.

Both commits landed in herdr-gateway (`8812463`, `abcde87`; version
bumped 0.1.20→0.1.22 through the repo's own convention), 268/268 tests
passing, typecheck clean, both scratch panes closed after capture.

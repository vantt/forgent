- **Self-contained coordinator prompt.** One pasteable `text` block carrying
  INPUTS, DOCUMENT AND DECISION AUTHORITY (7-level order, person's decision at
  the top), THE SYSTEM UNDER ADVICE, BOUNDS, SCOUT BEFORE ASK, ROLE ROUTING,
  manual-visibility disclaimer, PERSISTENT STATE, RECOVERY HANDOFF, the
  nine-phase loop, THE DIALOGUE TURN PROTOCOL, DRIVER DISPOSITION, STOP
  CONDITIONS, FINAL OUTPUT — plus a "What The User Pastes" section matching
  `master-coordinator.md`'s own Usage/Runtime-Boundary framing.
- **Nine-phase loop with justification.** Phases 2-9 are phase-01.md's eight
  Required Doctrine principles verbatim in intent. The ninth is a new **Phase 1
  — Intake and Framing**, placed *before* "Understand the person". Its
  justification is written into the prompt itself: the plan-level invariant that
  original human input / panel interpretation / recommendation / human decision
  stay separate artifacts is unenforceable unless some phase's only job is
  producing the first of those four, before any interpretation exists; and crash
  recovery needs a version of the question that predates the panel's opinion of
  it. It is the phase that makes the other eight auditable.
- **Scout-before-ask.** Six recorded preconditions (investigator dispatched and
  read; question survived investigation with a written trail; user-exclusive;
  material — name the options it eliminates; consolidated into one Decision
  Request; each question carries its reason and the panel's default). One narrow
  named exception, for facts about the person's obligations that cannot be
  defaulted safely.
- **Role routing.** Six-step per-actor selection order (proven-safe roster →
  minimum tier → diversity posture → persona → `dispatch.mjs decide` door →
  record derived provider/model and whether tier was material), with the
  `unavailable`/`in-process`/`out-of-process` responses spelled out and an
  explicit ban on falling back to the coordinator doing the role inline. The
  P00.1-proven roster (`codex-readonly`, `claude-bwrap`, `agy-bwrap`) with real
  tier→model derivation tables is recorded outside the prompt block so the prompt
  stays environment-independent, and P00.1's runnability Known Limitation is
  carried forward in both the prompt file and the doctrine.
- **Persistence and crash recovery.** Named on-disk layout, five persistence
  rules (write-before-act, `session.md` names one imperative next action,
  append-only artifacts, immutable prompt packages, per-artifact provenance) and
  a six-step RECOVERY HANDOFF procedure a fresh coordinator executes with zero
  chat history — including re-dispatching any actor with a prompt but no run
  result rather than reading meaning into its silence.
- **Decision Dialogue protocol.** Four layers kept structurally separate: the
  person's immutable words (`human/<n>-person.md`, verbatim, "nothing else goes
  in this file"), the lead advisor's interpretation (its own dispatch, its own
  artifact), the driver's authorization (`dispositions.md`), and the panel's
  response. Two hard rules: the driver may never author a human turn, and an
  authorization is never a decision.
- **Bounds.** Seven explicit prohibitions — Work read-only/optional, no git
  authority, no anonymization, no vote tallying or weighted scoring, no
  implementation-plan generation, no persistent council/chat surface, no
  fabricated human input.
- **Stop conditions.** Seven, plus four explicit non-reasons to stop.
- **Role doctrine for all nine named roles.** lead advisor, context investigator,
  system shaper, alternative shaper, constraint advocate, architecture critic,
  synthesizer, independent red-team, specialist. Each carries purpose, posture,
  what to notice, judgment heuristics, anti-patterns, handoff shape, and one
  concrete good example plus one concrete bad example of that role's own output,
  written against the track's real proof cases (vnflow / mdview) rather than
  invented ones. Each bad example is followed by a named diagnosis of what is
  wrong with it, so a Reviewer can point at a failure by name.
- **Driver-disposition doctrine.** All six dispositions with what each requires
  to be legitimate; an explicit "when the driver must NOT disposition alone"

  bad fill looks like*, because a section filled to satisfy its header is worse
  than a missing one.
- **Evaluation rubric.** All twelve of phase-01.md's own rubric items, each with

### Soft-inside discipline (plan.md "Trong Mem Ngoai Cung")

No artifact moves empathy, materiality judgment, reframing, alternative quality,
debate style, recommendation calibration, or explanation into an enum. The four
places that could most easily have become schema are deliberately prose:
materiality is a judgment the coordinator must argue ("state which candidate
options the answer would eliminate"), alternative quality is enforced by the
anti-pattern "designated loser" plus a worked bad example rather than by a field,
calibration is per-claim prose rather than a confidence enum, and the rubric has
four verdicts with no score precisely so a session cannot pass by being adequate
everywhere. The only enumerated things in the whole set are the six driver
dispositions and the three red-team verdicts — both of which are authority acts,
not judgments about architecture.

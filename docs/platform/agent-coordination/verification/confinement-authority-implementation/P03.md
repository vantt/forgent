**Two new structural findings for a future Lead** (beyond P01's `grantedContextRefs`/poisoned-slot/pane-cwd findings, all of which recurred here too):
1. **An executor can fail its own herdr handshake persistently, independent of system load.** `agy-herdr` failed 5 times in a row across genuinely different memory conditions; switching the SAME role to a different executor (`codex-herdr`) worked immediately. When a specific executor keeps failing at the handshake stage (not mid-task) across several fresh-taskKey retries, stop retrying the same executor and swap it for another already-proven-reliable one in the roster rather than assuming it is purely a memory/load symptom.
2. **A detached herdr pane can finish real work after its orchestrating CLI dies.** When a background `fgos coordination run` process is killed (e.g. by a system memory event), check `herdr pane list` for the affected assignment's pane before redispatching — if it shows `agent_status` other than a crash state, its `outbox/` may still fill in on its own. Read `outbox/result-1.json` directly once the pane goes idle rather than immediately opening a duplicate/conflicting dispatch.

## Deferred (not blocking — cap of 3 fix rounds reached; 0 HIGH remaining, all confirmed non-regressing)

- **NEW-1b/NEW-1c** (MEDIUM): the `enforced` attestation record's own body is still built from the original request rather than the actual prepared/executed invocation (`effectiveControls {}`, channels `'unverified'` with an `observe-mode` detail string, `receipt: null`) — the DECISION to label something `enforced` is now correct (round 3's fix), but the record's own descriptive content under that label is still thin; prepared claims (`drivers/bwrap.mjs`'s `claims = {...plan.coverage}`) are still never compared against what was actually executed.
- **M-1** (MEDIUM): the per-dispatch probe gate added in round 3 has no cache, no single-flight, and no timeout — spec §6.6 calls for exactly these — so concurrent required dispatches each pay a real ~180ms/9-bwrap-spawn cost with no coalescing.
- **M-2** (MEDIUM): the probe binary resolved for verification can differ from the binary actually used to spawn, when a machine registry entry omits `executable` — a real (if narrow) gap between what was proven and what runs.
- **M-3** (MEDIUM): neither round 2's nor round 3's fix shipped a regression test of its own (no test asserts the `confinement-coverage-unverified` refusal path, or the probe-driven `enforced` gate) — the next phase touching this code has no test net for either fix.
- **M-4** (MEDIUM): round 1's fix deleted the pre-existing `assessBwrap` unsupported-controls test rather than updating it to the new behavior — test coverage was net-reduced, not just changed.
- **L-1 through L-4** (LOW): `confinement-probe-failed` is not in spec §6.8's registered error taxonomy (nearest existing code: `confinement-violation`); `verifyRequiredProbe` hardcodes `backendInstance.type === 'bwrap'`, so a future container/remote driver inherits no probe gate at all; the probe fingerprint is a fixed 8-probe profile independent of which policy is actually being enforced (does not bind proof to the specific request); the CHANGELOG entry for this work is filed under "Added" rather than "Fixed"/"Changed" and does not mention the new per-dispatch probe gate's latency cost.
- **R4 (carried over from round 2)** (MEDIUM): the success-path temp-directory leak is unchanged and growing (47 directories observed at round 2's recheck, more by round 3) — cleanup removes only the recorded `home` child, never the parent `<dispatchId>/` directory; `reapOrphanedConfinementResources` (R5) still has zero production call sites.
- **R6 residual** (LOW, from round 2): `resolveAttestationStoreDir` honors a test-only `context.attestationStoreDir` override that is not in `buildConfinementRequest`'s own context whitelist — survives only when a caller mutates the request object after construction; production can only move the store via the `FGOS_CONFINEMENT_ATTESTATION_STORE_PATH` env var. No retention policy exists (record count grew from 5712 to 6602 across one focused suite run observed at round 2).
- **NEW-2** (LOW, from round 2): the store-overlap refusal (H1's own fix) throws a bare error before the normal refuse-branch runs, so that specific refusal path produces no `errorClass`, no `contract` token, and no durable refused-attestation record, even though the underlying mismatch was correctly detected.

All named explicitly so P04 (required enforcement, strict mode) and P05 (herdr convergence) do not have to rediscover them — several (the reaper's missing call site, the probe gate's missing cache/timeout) are exactly the class of hardening those phases exist to finish, not paper over.

**Pattern worth naming for a future Lead:** this phase's "No overclaim" boundary violations came in layers — each fix round closed the headline case and the recheck found the same shape of claim-without-proof one level deeper (adapter lookup → attestation template → flag-presence heuristic → per-channel derivation → fd inheritance / exception scoping). This is expected for an *observe-mode* attestation surface that is inherently trying to prove a negative ("nothing unconfined leaked"); P03's real backend/probe work is the natural place this converges, not further P02 fix rounds. The 3-round cap did its job here — diminishing severity each round (HIGH → MEDIUM → MEDIUM), never regressing to HIGH.

**Recurring infra collision** (5th and 6th occurrence in this track, see P01's trace for the first four): `--p02`'s produce and fix-round-1 dispatches were refused for writing into the shared main checkout, colliding with the same concurrently-active "rust-host-r1-kernel" session's real files (`docs/architect/packaging-distribution/runtime-identity-and-activation.md`, `plans/260910-1700-rust-host-r1-kernel/**`), all left untouched. Fix rounds 2 and 3, dispatched from a Lead session moved into its own dedicated track worktree via `EnterWorktree`, had **zero** collisions across 5 real dispatches — suggestive, though not proven causally (small sample), that Lead-session worktree isolation reduces (if not eliminates) this class of collision. Still flagged as an unresolved platform gap, not fixed from inside this track.

**New structural finding:** `aggregateBounds.wallTimeMs` defaults to 1 hour and is NOT enough headroom for a 3-4-dispatch fix round against real herdr executors (each real dispatch observed taking 5-30 min). It IS settable per-request at session-open (same immutability rule as `partialPolicy`) — `{"aggregateBounds": {"wallTimeMs": 7200000, ...}}` in the first request on a coordinationId. Any future fix round with more than 2 real dispatches should set this explicitly rather than rely on the default.

## Deferred (not blocking — cap of 3 fix rounds reached; all confirmed non-regressing, mostly fail-closed or latent-only)

- **MED-B** (round 2): capability identity is decided by the confinement config itself, so an unrelated capability sharing an executor with a `required`-policy capability can capture that name in a refusal/attestation. Fail-closed (over-refuses, no bypass); latent because no capability in the live catalog currently declares `confinement` — this is exactly what **P04's strict mode turns on**, so P04 must resolve this before flipping strict, not inherit it silently.
- **MED-1** (round 3, "inherited-fd channel"): the inherited-file-descriptor coverage channel is claimed `'covered'` off the same `isVerifiedBwrap` gate as the control checks, but bwrap does not close inherited descriptors — live-falsified (`FD9-INHERITED` visible even under `--unshare-all`). All three production executors currently attest this channel `covered` for something their argv does not cover.
- **MED-2** (round 3, "unscoped writable exception"): `hasWiderWritableRebind` only fires when a `--bind`/`--dev-bind` destination is exactly `/` — any other destination (e.g. `/home/vantt`, `/etc`) is silently accepted as a "scoped" exception while `hostWrite:'deny'` and filesystem `'covered'` still get claimed. Latent today (no registered executor re-binds anything but `.fgos/assignments`), but the control/coverage/channel triple is decided by flag *shape*, not by how much of the host the exception actually opens.
- **LOW-1/2/3** (round 3): a writable-exception grant can be silently dropped on a `path.basename` collision between two distinct binds; an argv without a `--` separator lets bwrap-option-looking payload tokens be trusted as real options (all 3 registered argvs use `--` today, so latent); `--tmpfs`/`--dev`/`--proc` writable mounts (e.g. `codex-bwrap`'s `CODEX_HOME` under `/tmp`) are not recorded as writable-exception grants even though they are writable.
- **INFO-1** (round 3): the round-3 fix's own new test hardcodes literal copies of the three production argvs rather than reading `.fgos/config.json`, so a future config change widening a real executor's bind set would not fail the suite; a pre-existing `M1` fixture was also amended to keep old assertions passing and no longer mirrors any registered executor.
- **LOW-A** (round 2, from op_029's INFO-1): the door's return shape still places raw adapter keys (`stdout`, `stderr`, `body`, `headers`, `tier`, `model`) at the top level alongside the union tokens, wider than spec §6.10's closed-shape description — not recorded in the phase file as R5 originally scoped it.
- **LOW-B/LOW-C** (round 2): a `homeDir`-based grant-target path is unreachable dead code (no producer wires a `homeDir` context key anywhere in `src/`); the facade's `doorResult?.result ?? doorResult` fallback would surface the union envelope itself (with a string `status`) if an adapter ever resolved `null`/`undefined` — not reachable with the two registered adapters today.
- **R8 test-scope gaps** (from P00's own carried-forward item, re-confirmed in round 1): the static call-site scan covers `src/**` only (not `bin/`, `core/`, `plugins/`), is comment-stripped by a naive `//`/`*`-prefix rule (a `/* */` block mentioning `EXECUTOR_ADAPTERS[` would false-positive), and hardcodes `sites.length === 1` so a second legitimate lookup inside `authority.mjs` itself would fail the test rather than being accounted for.

All named explicitly so P03 (backend/probes/attestation persistence) and P04 (required enforcement, strict mode) do not have to rediscover them — several (MED-B, the two round-3 MEDIUMs) are exactly the class of gap those phases exist to close for real, not paper over in observe mode.

## Verified facts binding for later cells

- Per-Run control fencing (`run-lock.mjs`) never reclaims a live PID on TTL alone — reclaim requires PID-dead proof, matching `plan.md`'s Cross-Slice Rules and `architecture-decision-lock.md` AD-10.
- Append-only generation records are never unlinked (only `.tmp-*` staging artifacts are).
- Settlement writes are fenced by the current control token, checked immediately before write, with token release only in `finally` after the write commits.
- Schema-1 callers are unchanged; schema-2 exact-retry declaration is additive.

## Deferred / accepted as non-blocking (2 LOW, both documented with a fix shape for a future pass)

- **R1**: an aborted-but-admitted retry generation is unmasked once its `runs/NN/run.json` exists, but if the *controller itself also crashes* in the narrow window before `result.json` lands, that generation can never be linked (permanent `invalid-predecessor`). This requires a second, independent fault stacked on top of an already-narrow abort race; every single-fault ordering tested (12-round hammer at 2ms cadence) recovered. Suggested fix (recorded, not applied): unmask only when `result.json` exists, not merely `run.json`.
- **R2**: the crash-free face of the same window — an `abortRunRetryDeclaration` call that returns `aborted` inside the gap between the admission-side aborted-marker check and the staging→`runs/NN` rename is not honored; the Run still materializes, executes, settles and links. Every tested ordering still recovers (a subsequent retry allocates correctly); this is an inconsistency, not a wedge. Suggested fix (recorded): re-check the aborted marker immediately before the rename.

## Process findings (added to P00's list, not repeated there)

- **A session's `aggregateBounds` (wall-time, max-rounds, etc.) is fixed at open and cannot be extended.** A cell expected to need several fix rounds on complex code should open with generous bounds; if it still runs out, open a continuation session against the same worktree/branch (produce a trivial acknowledgement step, then continue review/red-team/fix) rather than trying to mutate the exhausted session.
- **herdr-spawn completion detection can return before the pane's own file writes/commit are fully durable on disk.** A recheck dispatched immediately after a herdr-spawn fixer step "completes" can review a stale/incomplete worktree state. When this is suspected (an assignment's own reported commit hash doesn't match `git log` at review time, or reviewer/red-team reports mention edits "appearing mid-review"), the safe response is a fresh, clean recheck against the now-settled commit — not trusting the compromised one.
- **A committed diff can fail to parse even when the Assignment's own `confidence: "verified"` classification passed** (that classification checks for a non-empty git diff, not syntactic validity). Always independently `node --check` (or run the real test suite) on the actual worktree state before trusting a fixer's "done" self-report, especially for a role (`agy-herdr`/headless `claude`) that cannot run its own tests to catch this.

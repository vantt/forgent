## What landed

- `src/verbs/coordination/recover.mjs` (new) and `src/runner/coordination/recovery-planner.mjs` (new): `fgos coordination recover <coordinationId>` — without `--action`, a read-only `SessionRecoveryRecommendation` derived from the SAME shared pure evaluators (`read-evaluators.mjs`) the existing CoordinationSession write door uses, so read and write paths never diverge on what is legal.
- Applying (`--action <observe|collect|settle|close|park>` plus all five expectation fields: snapshot digest, event sequence, Run control epoch, expiry, action key) enters the existing CoordinationSession write door under a CAS critical section and appends exactly one new schema-2 event, `recovery-command-recorded`, carrying the action key for single-use enforcement.
- `dispatch recover` (P05) and `coordination recover` (P05S) stay strictly separated: the former owns standalone Run recovery and never appends a session event; the latter owns session recovery and cannot admit a standalone Run.
- Missing/replaced current driver returns `needs-input`. Terminal-parent continuation stays refused — no implicit close-after-steps.
- New tests: `test/verbs/coordination-recovery.test.mjs` (18 cases covering read/write parity, staleness on each of the five CAS fields, action-key idempotency, driver enforcement, the X11 premature-close hazard staying visible, and schema-1 sessions being completely unaffected).

## Fix rounds (1 real fix round, after a session-limit-interrupted first attempt)

The FIRST produce attempt (headless `claude`) wrote a complete, substantially correct implementation (~900 lines across all leased files) but was interrupted by the executing account's own Claude usage/session limit before it could run `git commit` — no code was lost (still sitting as uncommitted changes in the worktree), but the downstream reviewer and red-team each ran the full 35-minute wall-time ceiling with nothing new to review and timed out, leaving two orphaned herdr panes (closed). A fresh round was opened, switching the doer/fixer executor to `agy-cli` (Antigravity, headless `cli-spawn`, no persistent pane — chosen for lower memory footprint over `agy-herdr`'s live pane, per explicit user direction after this incident), instructed to verify/finish/commit the existing uncommitted work rather than restart. `agy-cli` succeeded — it has broader real tool access than the Bash-restricted headless `claude` executor, so it could run the actual test suite itself before committing (`a01b52a9`).

That round's independent reviewer found 1 MEDIUM (planner blind to already-recorded recovery commands, causing duplicate `recovery-command-recorded` events for the same Run) plus several LOW/INFO notes; its own overall dispatch result was separately flagged `failed` by the dispatch infrastructure's cross-worktree dirt check, but this was a confirmed FALSE POSITIVE — an unrelated, concurrently-running session on the same shared machine was independently editing docs files in the main checkout at the same wall-clock time, and the safety check cannot currently distinguish "this round's own agent leaked" from "unrelated concurrent activity on a shared machine." The reviewer's own report content was read and accepted on its merits after independently confirming (`git log`/`git status`) the flagged files were genuinely unrelated. Red-team independently found the same root-cause defect from a different angle (F-1: a `close` recommendation's eligibility reasoning didn't match the real `closeSessionByQuorum` quorum rules) plus a LOW residual (F-2: an unsalted `actionKey` can be re-minted with a new `expiresAt` — accepted as by-design, since every other CAS field is independently re-validated against real current state, mirroring P05's own already-accepted `actionKey`-is-a-CAS-binding-not-a-secrecy-boundary residual).

Fix-1 (agy-cli): unified the `close` recommendation's eligibility check to reuse the same evaluator the real write door uses for quorum/completion (closing the M1/F-1 root cause together), added already-recorded-command awareness to the planner to stop re-recommending an action once a command is already pending for a Run, and replaced an inline duplicate of `authorize()` in `store.mjs` with a direct call to the shared function (removing a drift risk).

Final recheck (reviewer): **PASS** — M1/F-1/L2 all verified fixed by live CLI reproduction against real dispatched sessions; focused suite 18/18, broad coordination+dispatch sweep 1061/1063 (only the pre-existing, already-documented `coordination-research-fan-out` R5 failure remains).

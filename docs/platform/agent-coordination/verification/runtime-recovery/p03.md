## What landed

- `src/runner/dispatch/recovery.mjs` (new): `resolveFallback()` — refuses a fallback candidate whose governance/provenance chain or compiled executor identity doesn't match the original plan (`candidate-not-governed`/`compiler-mismatch`), never silently substituting a different executor. `assess()` — determines post-delivery repeat eligibility from a confinement attestation.
- `repeatMode` is now an explicit, additive field on `PolicyPatch` (`src/runner/definitions/schema.mjs`), declared in operation YAML (`core/coordination-protocols/standalone-master-coordination-loop.yaml`'s `review-candidate`/`red-team-candidate` now declare `repeatMode: pre-delivery`), never inferred from `Assignment.mutation`.
- `mergePolicyStack` (`src/runner/dispatch/assignment-policy.mjs`) applies the same non-weakening, monotonic-rank discipline to `repeatMode` that `minTier` already had — a weaker scope can no longer silently downgrade a stronger scope's declared value.
- `repeatMode` is forwarded through the real `dispatchDeclaredOperation` seam in `session-engine.mjs` (~line 2670-2678), alongside the already-correctly-forwarded `minTier`, so a YAML-declared value actually reaches the compiled `DispatchPlan`/`runResult.policy` instead of silently resolving to a default.

## Fix rounds (2 rounds)

1. **Fix-1**: HIGH safety finding (found independently by both reviewer M1 and red-team F1) — `assess()` used a DENYLIST (`unknown|refused|failed`) to gate attestation outcomes, so an `outcome: 'unconfined'` attestation (which the local-bwrap-v1 support matrix explicitly says makes no enforced-confinement claim) or a real bwrap attestation whose actually-granted control was `networkEgress: 'allow'` both resolved `'eligible'` for post-delivery repeat — exactly the outcome this cell exists to prevent. Fixed by switching to an ALLOWLIST: eligibility requires `attestation.outcome === 'enforced'` AND the attestation's own actually-granted control (never the caller's merely-requested policy) shows `networkEgress` as `'filtered'` or narrower. Also fixed in this round: `repeatMode` merge-order downgrade (F3), a fallback executor-identity check gap (F4), and the first (incomplete) attempt at the `repeatMode` wiring gap (F2).
2. **Fix-2**: F2 (the `repeatMode` wiring gap) was pinpointed twice at the same exact lines by independent review and red-team recheck after fix-1 missed it — `session-engine.mjs`'s declared-operation dispatch seam forwarded `minTier` but omitted `repeatMode` from the same policy-forwarding block. Fixed with a narrowly-scoped second round targeting only those lines; confirmed via a real `dispatchDeclaredOperation` repro across multiple scope combinations (cli/assignment/role/project-tier) that the compiled plan now carries `repeatMode: 'pre-delivery'` instead of `null`.

Final recheck (reviewer): **PASS** — real `dispatchDeclaredOperation` repro confirmed the compiled plan/`dispatch-plan.json` now carries the declared `repeatMode`.

## Findings

### 1. MEDIUM — a window with an empty `opensAfter.operationRefs[]` is permanently open, and the promoted text neither names it nor tests it

- **File/line:** `src/runner/definitions/schema.mjs:143-147` (`assertStringArray`
  accepts `[]`) + `src/runner/coordination/session-engine.mjs:1289`
  (`sources.every(...)` on an empty array is `true`); promoted text at
  `docs/architect/agent-coordination/contracts/flow-definition.md`, the
  `opensAfter.operationRefs[]` row of the field table.
- **Failing scenario:** a definition author declares a window they believe gates
  synthesis, but leaves `operationRefs` empty. The window is open from session
  open, with zero work done, and the gate is a no-op.
- **Requirement violated:** current-cell Acceptance bullet 1 ("the promoted
  contract text describes `visibilityWindows[]`/`contextAccess.visibilityWindowRef`
  accurately against the shipped schema") and the Bug Taxonomy's own named risk
  of a fixture/definition that "declares a window and gates nothing" — the same
  vacuity the new fixture's header comment explicitly guards against, arriving
  through a different door.
- **Evidence** (empirical, run by me — the committed fixture with only
  `opensAfter.operationRefs` emptied, loaded through the real project tier):

  ```
  SCHEMA: empty opensAfter.operationRefs ACCEPTED
  RUNTIME: open = true | sources = 0 | ZERO cohort work has been done
  GATE:   authorization SUCCEEDED with no source work at all
  ```

  The field table currently says only "The window is open only when **every**
  listed operation is satisfied" — vacuously true for zero listed operations,
  and a reader has no way to learn that from the contract.
- **Smallest fix:** one sentence in the `opensAfter.operationRefs[]` row naming
  the degenerate case ("an empty list satisfies vacuously and yields a
  permanently open window; a definition that means to gate must list at least
  one source"), plus one negative test in the new suite asserting it. A schema
  minimum-length check would be the real repair, but that is a P06.1 change and
  correctly outside this cell — naming it is inside.

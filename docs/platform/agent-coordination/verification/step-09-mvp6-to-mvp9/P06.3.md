## The fixture

`core/coordination-protocols/independent-research-fan-out-fan-in-gated.yaml`
(id `core.coordination-protocol.independent-research-fan-out-fan-in-gated`) —
a real core-tier protocol, discovered and normalized by the ordinary
`discoverCoordinationProtocols`/`loadCoordinationProtocol` path, and validated
on every `fgos doctor` run by the pre-existing
`coordination-protocol-fixtures-valid` check (which walks every discoverable
definition — no registration work was needed, and none was invented).

It is the ungated `independent-research-fan-out-fan-in.yaml` plus exactly
three things: a `post-independent-pass` window opening after
`independent-research`, and `activation: {mode: driver-authorized}` +
`contextAccess: {visibilityWindowRef: post-independent-pass}` on the
`synthesize-findings` binding.

**Why a new file rather than extending the shipped one** (the contract left
this to the Doer): the runtime gate lives on the driver-authorized grant
door — see Limitation 3 below, which this cell verified empirically rather
than assumed. Proving the window therefore requires `synthesize-findings` to
become `driver-authorized`, which would change the ungated fixture's own
already-tested dispatch path (`synthesizeResearchFanIn`, `test/cli/coordination.test.mjs`'s
real fan-out run). Adding `contextAccess` to the ungated fixture WITHOUT
that change would have produced a fixture that declares a window and gates
nothing — precisely the vacuous positive the Bug Taxonomy warns about. Cost
of the new file, paid openly: `flow-definition-protocol-loader.test.mjs`'s
exact core-fixture id list gained one entry (3-line diff, test name updated
to match).

## Finding for the Coordinator (not patched — Do Not Touch honored)

**A `required` binding declaring `contextAccess.visibilityWindowRef` is
schema-legal and runtime-inert.** Both gates sit inside the driver-authorized
path: `authorizeDeclaredOperation` refuses any non-`driver-authorized`
binding outright, and `dispatchDeclaredOperation`'s window check is inside
its `if (isDriverAuthorized)` block (`session-engine.mjs:1958`). Verified
empirically on a purpose-built definition and then locked in as the
`SCOPE BOUNDARY` test: with the window provably closed, a required binding
carrying the window ref dispatched to `status: done`.

Judgment, offered rather than assumed: this is **not** a defect against
Phase 06's own written requirement — P06.2's requirement 4 is about granted
refs, and a `required` binding has no grant, so there is nothing to refuse.
But `P06.2.md`'s Design Notes describe the gate more broadly ("a binding
whose `contextAccess.visibilityWindowRef` is set may not be
authorized/dispatched AT ALL unless its window is open"), which is wider than
what shipped. Left unpatched per this cell's Do Not Touch list and named as
Limitation 3 in the promoted text so nobody reads the contract as promising
more than the code does. If the Coordinator wants the wider shape, it is a
follow-up cell in `session-engine.mjs`, and this cell's characterization test
is the one that would then change deliberately.

Four separate edits to `flow-definition.md`, all in the Visibility Windows
section:

- **(a) "the sole door" → "the sole MEDIATED door."** The absolute form is
  contradicted by the file's own residual: the unmediated
  `createSessionAssignment` door can write the reserved stamp itself, which
  the Red-Team confirmed empirically with a forged-stamp Assignment that
  opened the window. Within the mediated module the claim is exactly true
  (one stamping call site, `assertNoReservedOperationStamp` on the rest), so
  the qualifier is the whole repair. Also narrowed "it is the only channel
  consulted" to "the only channel consulted for *which operation an Assignment
  performed*", since the bound actor genuinely is consulted — as the branch
  selector (`resolveBindingOutcome` filters on `payload.actorId` as well as
  the stamp).
- **(b) The trust-boundary caveat moved into the same paragraph as the claim.**
  It previously sat ~40 lines below, where a skim picks up the guarantee
  without the boundary. The paragraph now states the boundary in the same
  breath and points forward to the residuals.
- **(c) "any accepted actor-replaced lineage" → no implied read-time check.**
  Nothing accepts or validates an `actor-replaced` event at derivation time
  (`replay.mjs` declines to enforce any cross-event rule on it). The sentence
  now says the derivation follows the lineage **as recorded in this session's
  own log** and applies no acceptance check of its own.
- **(d) A THIRD named residual for the raw `recordActorReplacement` collapse.**
  Written in the same style as the existing two, with the Red-Team's own

  `src/runner/coordination/session-engine.mjs:3156-3166`, whose comment names

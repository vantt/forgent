### 2. MEDIUM — "frozen at every nesting level" claim is false; verified live

**File:** `src/runner/team-cognition/aggregation-evaluator.mjs:118`
(`missingDisclosuresBySource: Object.freeze({ ...disclosures.missingDisclosuresBySource })`)
**Requirement violated:** the cell's own Design Notes claim
(`P07.1.md:151-155`): *"Frozen return values. `evaluateAggregationCoverage`
returns `Object.freeze(...)` at every nesting level so a caller cannot mutate
the verdict and re-trust it..."* — and the "Must not own"/"never rewrites
evidence" framing this is meant to reinforce.

`Object.freeze({ ...obj })` only freezes the top-level object; the array
values inside `missingDisclosuresBySource` (`missing` from `.filter(...)` in
`validateRequiredDisclosureCoverage`) are never frozen. I verified this live:

```js
const result = evaluateAggregationCoverage({
  sourceOperationRefs: ['op-research'],
  sources: [{ sourceOperationRef: 'op-research', assignmentId: 'a', runId: 'r',
              artifactRef: 'x', revision: 'v', disclosures: {} }],
  requiredDisclosures: ['confidence'],
});
const arr = result.disclosureCoverage.missingDisclosuresBySource['op-research:a:r'];
Object.isFrozen(arr); // false
arr.push('mutated');  // succeeds — array is now ['confidence', 'mutated']
```

The test named to prove this
(`test/runner/team-cognition-aggregation-evaluator.test.mjs:110-119`, "result
is frozen") only checks `Object.isFrozen(result)`,
`Object.isFrozen(result.sourceCoverage)`, and
`Object.isFrozen(result.disclosureCoverage)` — it never descends into
`missingDisclosuresBySource`'s values, so the test is weaker than its own name
and the Design Notes claim.

**Risk in practice:** low — this mutable array is diagnostic output
(which disclosure ids were missing for a given source), not the evidence/
RunResult/artifact-ref data itself, so mutating it does not violate the
"never rewrites evidence" hard constraint in a way that corrupts real state.
It is nonetheless a real gap between the stated guarantee and the code, and
between the test's name and what it actually checks.

**Smallest-fix direction:** freeze each array value before assembling
`missingDisclosuresBySource` (e.g. `Object.freeze(missing)` at the point the
per-source entry is built in `validateRequiredDisclosureCoverage`), or map
values through `Object.freeze` when copying in `evaluateAggregationCoverage`;
extend the "result is frozen" test to assert on one nested array.

### 3. LOW-MEDIUM — Named Bug Taxonomy item has zero test coverage: input-mutation

**File:** `test/runner/team-cognition-aggregation-evaluator.test.mjs`,
`test/runner/team-cognition-schema.test.mjs` (absence)
**Requirement violated:** `current-cell.md`'s P07.1 Bug Taxonomy explicitly
names: *"Evaluator silently mutating an artifact ref or RunResult."*

No test in either team-cognition test file asserts that the `sources[]`,
`sourceOperationRefs[]`, or `requiredDisclosures[]` inputs are left
byte-identical (or even reference-identical) after being passed through
`validateSourceCoverage`, `validateRequiredDisclosureCoverage`, or
`evaluateAggregationCoverage`. I read the implementation and confirmed by
inspection that none of these functions mutate their inputs today (they only
read `source.sourceOperationRef`/`source.disclosures[id]` and build new
Maps/objects) — so this is a coverage gap, not a live bug. But it is a named
Bug Taxonomy risk for this exact cell, and per review priority #5 ("any
rejection case named in the phase file/current-cell.md that has no test at
all") it should have its own test, not just be true by accident.

**Smallest-fix direction:** add one test that deep-freezes (or deep-clones and
compares) the input `sources` array/object before calling
`evaluateAggregationCoverage`, then asserts it is unchanged afterward.

## Requirements (from phase-07-mvp7-evidence-preserving-aggregation.md, P07.1 + P07.2)

- Establish the minimal Team Cognition module/port boundary.
- Validate structured source coverage and required disclosures against
  immutable RunResult/artifact refs.
- Never rewrite evidence, alter confidence, dispatch work, or transition a
  session.
- Cover all outcomes this skeleton actually exposes with deterministic
  validation (source coverage, disclosure coverage — full
  consensus/qualified/no-consensus classification is out of scope here).
- Reject missing sources (a declared source operation with no supplied
  source) and a source ref that does not resolve to a declared operation.
- Reject a missing/malformed required disclosure.
- Do not integrate with shared session files yet.

## Design notes (why this shape, not another)

- **Input contract, not fetched/dispatched data.** The evaluator's three
  inputs (`sourceOperationRefs[]`, `sources[]`, `requiredDisclosures[]`) are
  the closest real analog to phase-07's candidate contract fields
  `completion.aggregation.sourceOperationRefs[]` and
  `completion.aggregation.requiredDisclosures[]` — but P00.2.md §3 is
  explicit that these are frozen candidate names, not accepted contract
  text, so this skeleton treats them as its own internal parameter names
  (documented in JSDoc), not as a claim that FlowDefinition already carries
  these fields. No file under `src/runner/definitions/` or
  `src/verbs/coordination/` was touched to wire them in — that is P07.3.
- **`revision` required on every source, not optional.** "Immutable
  RunResult/artifact refs" (current-cell.md's Goal line) needed a concrete,
  checkable shape signal. A `runId`/`artifactRef` pair alone does not prove
  immutability; a `revision` pin does. This module cannot check the pin is
  *current* (no store access), only that it is *present* — documented
  explicitly as a non-goal in both the module header and this trace, so a
  future reader does not mistake "revision present" for "revision proven
  fresh."
- **Two split validators (`validateSourceCoverage`,
  `validateRequiredDisclosureCoverage`) plus one combining entry point
  (`evaluateAggregationCoverage`).** Matches the cell's own bug taxonomy
  framing (source coverage and disclosure coverage are named as separate
  checks) and keeps each half independently testable/positive/negative,
  while `evaluateAggregationCoverage` is the one pure function a future
  P07.3 integration would actually call.
- **Self-contained `schema.mjs`, not an import of
  `coordination/schema.mjs`.** `coordination/schema.mjs`'s
  `CoordinationError`/`assertNoForbiddenFieldsDeep`/whitelist-field style
  was read as pattern precedent (per current-cell.md's "Must Read") and
  mirrored, but not imported — per P00.2.md §2, this is a brand-new
  authority boundary with nothing moved from `session-runtime`; importing
  from it would create exactly the kind of accidental coupling the
  `team-cognition-static.test.mjs` forbidden-import check now guards
  against permanently.
- **Frozen return values.** `evaluateAggregationCoverage` returns
  `Object.freeze(...)` at every nesting level so a caller cannot mutate the
  verdict and re-trust it as if the evaluator itself had re-validated —
  reinforcing "never rewrites evidence" at the API surface, not just in
  the module's own body.

## Gaps

- No exercise of what happens when the SAME `sourceOperationRef` is
  satisfied by more than one source entry (e.g. two actors both contributed
  evidence for one declared operation) — `bySourceOperationRef` already
  collects all of them into an array per ref (visible in
  `validateSourceCoverage`'s return shape), but no test asserts a specific
  policy for "is 2 sources for 1 declared ref a pass, or does something
  downstream need exactly 1?" This is left open because phase-07.md's
  outcome-classification semantics (P07.2/P07.3, per current-cell.md's own
  Non-Goals) are what would define that policy — this skeleton only proves
  coverage exists, not how many contributors satisfy it.
- `disclosures` values are checked for presence (`!== undefined && !==
  null`), not for their own shape/type per disclosure id — there is no
  disclosure-id-to-value-shape registry yet (e.g. what a `"dissent"`
  disclosure's value must look like). Left open per the same Non-Goals
  boundary; a later cell that defines disclosure semantics owns that shape.
- No fixture reuses a real `RunResult`/artifact shape from
  `src/runner/dispatch/assignment-runner.mjs`'s actual on-disk RunResult
  format (`status`/`confidence`/`workerArtifacts`/`changedFiles`) — this
  skeleton's `sources[]` entries are a smaller, evaluator-local shape
  (`sourceOperationRef`/`assignmentId`/`runId`/`artifactRef`/`revision`/
  `disclosures`), not a 1:1 mirror of that dispatch-side RunResult object.
  Read `assignment-runner.mjs` (not in this cell's "May Inspect" list, but
  consulted for background) to confirm no field name collision was
  accidentally introduced; reconciling the two shapes (if RunResult ever
  needs to feed this evaluator directly) is P07.3 integration work.

### 2. Immutability: unfrozen sub-function results + unfrozen nested array (Reviewer #2 + Red-Team Finding 1)

**File:** `src/runner/team-cognition/aggregation-evaluator.mjs`.

- `validateSourceCoverage` (was line 64, now ~91): return value is now
  `Object.freeze`d at the top level; `missingSourceOperationRefs` and
  `unresolvedSourceRefs` arrays are frozen; `bySourceOperationRef` is no
  longer a plain mutable `Map`. Empirically, `Object.freeze(map)` does
  **not** block `.set()`/`.delete()`/`.clear()` (those bypass ordinary
  property assignment via internal slots — verified live, see Commands
  below), so a plain-object-style freeze would not have actually closed
  Red-Team's "overwrote a Map entry (succeeded)" repro. Added
  `freezeCoverageMap()`, a small `Proxy` wrapper (lines ~34-59) that freezes
  every array value the Map holds and throws `TypeError` on `set`/`delete`/
  `clear`/property-assignment/property-deletion, while still allowing every
  read path (`.get`, `.has`, `.size`, iteration) to work unchanged.
- `validateRequiredDisclosureCoverage` (was line 106, now ~133): return
  value is now `Object.freeze`d at the top level; each per-source `missing`
  array is frozen (`Object.freeze(missing)`) before being assigned into
  `missingDisclosuresBySource`, and `missingDisclosuresBySource` itself is
  frozen.
- `evaluateAggregationCoverage`'s own remaining gap (Reviewer's Finding #2,
  the unfrozen nested array inside `missingDisclosuresBySource` at the old
  line 118): resolved as a side effect of the fix above — since
  `validateRequiredDisclosureCoverage` now freezes each `missing` array
  before handing it back, and `evaluateAggregationCoverage`'s
  `{ ...disclosures.missingDisclosuresBySource }` spread preserves those
  array references rather than cloning them, the nested arrays reaching the
  combined entry point's frozen output are already frozen. No change to
  `evaluateAggregationCoverage` itself was needed.

**New/extended tests** (`test/runner/team-cognition-aggregation-evaluator.test.mjs`):
- Extended "nested missingDisclosuresBySource array is frozen too" — asserts
  `Object.isFrozen` on the nested array and that `.push(...)` throws
  `TypeError` (reproduces the Reviewer's exact repro shape).
- New: "validateSourceCoverage: result and every nested value (arrays, Map)
  are frozen/mutator-blocked" — asserts the top-level result, both arrays,
  and the `bySourceOperationRef` Map's array values are frozen; asserts
  `.set()`/`.delete()`/`.clear()` on `bySourceOperationRef` all throw
  `TypeError`; asserts reads (`.get`, `.size`) still work.
- New: "validateRequiredDisclosureCoverage: result and nested

### Fix: deep-frozen source snapshots, not caller-owned references (Red-Team recheck Finding 1, new gap)

**File:** `src/runner/team-cognition/aggregation-evaluator.mjs`.

Red-Team's recheck offered two fix directions: (a) `Object.freeze(source)`
the caller's actual object in place, or (b) freeze a defensive shallow-copy
so the caller's original object is never touched. Took (b): freezing the
caller's own object in place would itself be a form of input mutation — the
exact thing Fix Round's item 4 (input-mutation tests) exists to rule out —
so `validateSourceCoverage` now builds an independent, deep-frozen snapshot
of each source before storing it in `bySourceOperationRef`, via a new
`freezeSourceSnapshot(source)` helper (`aggregation-evaluator.mjs:40-52`):
`Object.freeze({ ...source, disclosures: Object.freeze({ ...source.disclosures }) })`.
The one call site that pushes into `bySourceOperationRef`
(`aggregation-evaluator.mjs:107`, inside the `for (const source of sources)`
loop) now pushes `freezeSourceSnapshot(source)` instead of the raw `source`
reference. `disclosures` is the only nested object in the
`AggregationSource` shape (`schema.mjs`'s `AGGREGATION_SOURCE_FIELDS`), so a
one-level-deep freeze of the copy plus a frozen copy of `disclosures` covers
the whole shape; every other field is a plain string.

Verified empirically under real ESM strict mode (matching how the test
suite runs, not a sloppy-mode `-e` script where a blocked assignment fails
silently instead of throwing):
```
revision mutate throws: TypeError
disclosures mutate throws: TypeError
entry.revision after attempt: v
entry.disclosures.d1 after attempt: orig
original caller source unaffected: v orig
caller source still not frozen by us: true
```

**New test** (`test/runner/team-cognition-aggregation-evaluator.test.mjs`,
"`validateSourceCoverage`: `bySourceOperationRef` holds deep-frozen
snapshots, not the caller's live source objects (red-team recheck repro)"):
reproduces the red-team's exact tamper attempt —
`entry.revision = 'TAMPERED-REVISION'` and
`entry.disclosures.confidence = 'TAMPERED-DISCLOSURE'` both now throw
`TypeError` and leave the values unchanged — and additionally asserts the
caller's own original object is untouched: not frozen, its `revision` field
still directly assignable by its own owner after the call. This closes both
the fix and the coverage gap the recheck named ("the gap is untested, not
just unfixed").

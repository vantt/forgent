### Round 1 (Doer): CRITICAL path-traversal on `coordinationId`

Zero charset validation on `coordinationId` — a `../../../tmp/evil` id
created a real directory outside the intended sessions directory,
empirically confirmed by the Doer before fixing. Fixed via
`assertSafeCoordinationId` (whitelist regex `/^[A-Za-z0-9_-]+$/`) applied
at `resolveSessionPaths` (the shared choke point) and `openSession`'s
explicit-id branch. **Independently live-tested by the Coordinator**
(constructed the exact traversal payload, confirmed `CoordinationError`
thrown and no directory created) before the Reviewer round.

### Round 2 (Reviewer → Fixer → Red-Team): the round-1 foreign-evidence
fix was itself incomplete, plus a second real bug in P06.1's own code

The Doer's own initial `linkResult` guard only checked that a `runId`
**started with** `run_<assignmentId>_` — a malicious suffix
(`run_<assignmentId>_../../../../tmp/evil-run-dir`) still passed, and
the identical weakness existed in the read-time counterpart
(`readLinkedRunResultFromDisk`'s `attemptStr = runId.slice(prefix.length)`,
unvalidated, fed straight into a `path.join`). The Reviewer
**live-reproduced the full exploit chain**: accepted write, planted a
forged `result.json` outside the sandbox, then `evaluateSessionQuorum`
returned the actor as falsely `completed` with forged evidence. The
Reviewer also found a second real HIGH bug, in P06.1's own
`replaceSessionActor` (in scope for R6/R8's "full matrix" requirement):
`oldActorId`/`newActorId` had zero charset validation before a
`path.join`, live-reproduced creating a real file outside the sessions
directory.

Both independently re-verified by the Coordinator (reading the exact
cited source) before authorizing a fix. Fixed: a single shared
`assertValidRunIdForAssignment(assignmentId, runId, context)` helper
(full-shape, properly-escaped regex `^run_<escaped>_\d+$`), used by BOTH
`linkResult` (write-time) and `readLinkedRunResultFromDisk` (read-time
defense-in-depth) — one validation to maintain, not two independently-
drifting copies; and `assertSafeCoordinationId` generalized with an
optional `{label}` param, reused (not duplicated) for `replaceSessionActor`'s
`oldActorId`/`newActorId`, guarded before any path construction.

**Red-Team's own final adversarial pass** (round 2's closing gate):
mathematically proved and empirically tested that `escapeRegExpLiteral`
covers all 14 JS regex metacharacters, that cross-assignment runId
collision is structurally impossible under the anchored full-shape
pattern, and grepped every `path.join` call across
`src/runner/coordination/**` confirming no remaining unguarded
caller-supplied path segment. No new bypass found.

  session with zero declared actors (vacuous completion) — unreachable
  via both production-blessed entry points (`openStandaloneSession`/
  `openDeclaredProtocolSession`), which structurally guarantee non-empty
  required actors (independently confirmed by both the Doer and the
  Reviewer reading the exact validation). A product-scope decision for a
  future cell if a new session-opening entry point is ever added, not
  blocking now.
- **LOW, informational**: R7's static export-surface scan is a
  substring-on-lowercased-name check; a differently-worded future export
  could theoretically evade it. Matches this codebase's own established
  `coordination-static.test.mjs` convention elsewhere — not a new
  weakness introduced by this cell, named for future awareness.
- **LOW, informational**: `replaceSessionActor` (P06.1's own function,
  hardened again in this cell) still has zero production callers
  anywhere in `src/` — its correctness is proven by direct test/adversarial
  coverage, not yet by real integration. Whoever wires a first real
  caller (a future retry-policy engine or Cohort-Planner integration)
  inherits an already-hardened function, not a fresh one.

## Round 0 (Lead's own catch, before any review counted)

The Doer's commit (`e5575f79`) claimed "Verified clean Node-against-Node
parity" but the Lead's own re-run of the phase's stated verification command
FAILED: `coverage-isolated-write-init-then-add` failed on every run because
the isolated-write case's fs-delta normalization regex assumed
`.fgos/events/<digits>-<timestamp>.jsonl`; the real filename is
`<session-id-uuid>-<timestamp>.jsonl` (hex+dashes, not digits), so
normalization never matched and every run's fresh session-id/timestamp
produced a spurious "Created delta mismatch". **Fixed** (commit `95c26a33`):
match by directory instead of trying to mirror the naming scheme. Re-verified
11/11 pass, twice.

## Round 1 (session `rust-host-r1-kernel--p02-review`, against `95c26a33`)

- Reviewer: 1 HIGH (comparator rubber-stamps two entries that both fail to
  launch — every spawn error was collapsed into the same `exitSignal:
  "TIMEOUT"` bucket as a real timeout, so two identically-broken `bin:`
  targets compared equal; verified empirically by the reviewer itself), 3
  MEDIUM (child-process evidence exists only for `node:` entries, not
  `bin:`; the `signal` comparison mode and its committed fixture were
  exercised by no case or test; the isolated-write case compares filenames
  across entries, never content), 5 LOW.
- Red-team: 2 HIGH corroborating the same two core weaknesses independently
  (fs-delta compares changed paths but not bytes; `bin:` entries bypass the
  Node child-process spy), 2 MEDIUM (timestamp predicate edge cases; signal
  case doesn't exercise a signal).
- **Disposition: all HIGH and MEDIUM accepted, fixed** (commit `56bb993a`):
  `launchError` field distinguishes a real spawn failure from a timeout;
  `compareResults` treats it as an unconditional hard difference before any
  other check. A PATH-shim mechanism (`buildPathShim`) gives `bin:` entries
  child-process evidence for commands this harness has observed (`git`),
  with `child-process-spy.cjs` skipping the same commands via
  `FGOS_HARNESS_SHIMMED_COMMANDS` so `node:` entries are never
  double-counted. `diffDirectorySnapshots` now returns `{path, hash}` for
  created/modified; `compareResults`'s fs-delta mode compares hashes. A
  real end-to-end signal-mode test was added (SIGKILL against
  `signal-trapping.mjs`, since SIGTERM is trapped by the fixture and never
  reaches OS-level termination). 2 LOW fixed (dead `generated_at` branch;
  unquoted `NODE_OPTIONS` path). The isolated-write case's own bespoke
  comparison stayed path-only, documented in place: its `state.json`
  embeds a volatile event-log filename+timestamp inside its own JSON body
  (confirmed empirically), so naive hashing would reintroduce the exact
  flaky-content failure Round 0 fixed.

## Round 2 (session `rust-host-r1-kernel--p02-review2`, against `56bb993a`)

- Reviewer: 3 MEDIUM (PATH shim's `node -e` logger loses evidence and leaks
  `node`'s own stdout when a shimmed command's first arg looks like a node
  flag, e.g. `git --version`; shim is `git`-only and `node:` entries still
  see a deeper process tree via NODE_OPTIONS inheritance, but the header
  comment read as fully closed; neither HIGH fix from Round 1 had a
  regression test), 4 LOW.
- Red-team: 1 MEDIUM (`PATH_SHIM_COMMANDS` missed `npm`, which
  `bin/fgos.mjs` also spawns for preflight/uninstall), 2 LOW (a contrived
  falsy `launchError` input could slip past a truthy check; no real
  double-counting or signal flake observed under 30 concurrent runs).
- **Disposition: all MEDIUM accepted, fixed** (commits `05236533`,
  `f777ee5e`): shim logger uses `--` before `"$@"` so node never consumes a
  flag-shaped arg; added `npm` to `PATH_SHIM_COMMANDS`; `launchError` check
  switched from truthy to `!= null`; header comment now states the real
  asymmetry (shim is `git`+`npm`-only, `node:` NODE_OPTIONS inheritance
  still deeper) instead of reading as fully closed; added two regression
  tests (`compareResults`'s `launchError` early-return; a real `bin:`
  fixture — new `bin-git-caller.sh` — proving PATH-shim evidence with no
  `node:` double-count). LOW-2 (doc comment contradicted code) fixed.

- LOW-4 (reviewer round 2): one full `node` startup per shimmed call — 5.5s
  suite total, not a real cost yet.

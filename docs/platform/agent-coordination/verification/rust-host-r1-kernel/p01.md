## Round 1 (session `rust-host-r1-kernel--p01-review`, against `d2a9d328`)

- Reviewer: **1 HIGH** — the raw-text duplicate-key scan in
  `loadAnnotations` split on a flat regex with no nesting awareness, so a
  SECOND annotated selector's own nested `operation_id` key was mistaken for
  a duplicate top-level key, false-failing the generator the moment a real
  migration needed to flip a second selector to native. 2 MEDIUM: R7's
  unlisted-selector test never drove the guard through `generateCommandRoutes`
  itself (a mutation removing the wired-in guard call would still pass all
  8 tests); native `owner_path` silently defaulted via a dead
  always-identical ternary, defeating the "canonical implementation
  boundary" contract `legacy-cli-transition.md` §2 requires. 4 LOW: dead
  locale-sensitive sort comparator, `compatibility_tests` placeholder
  (informational only, no fix needed), crash-time temp file inside the
  committed `contracts/` tree, and the duplicate-key scan being
  regex-not-tokenizer (folded into the HIGH fix).
- Red-team: 1 LOW — `__proto__`/`constructor` selector names hit a
  `TypeError` in `explain-command-route.mjs` instead of the clear
  unknown-selector message.
- **Disposition: all real findings accepted.** Fixed directly by the Lead
  (commit `6e52a172`): depth-aware character-scanning duplicate-key
  detection replacing the flat regex; explicit `owner_path` required on
  every native route (annotations file updated to declare it); the
  unlisted-selector guard now also exercised through `generateCommandRoutes`
  via a duplicate-registry-name case; single sort comparator; temp file
  renamed + `.gitignore` entry; `explain-command-route.mjs` uses
  `Object.hasOwn`.

## Round 2 (session `rust-host-r1-kernel--p01-review2`, against `6e52a172`)

- Reviewer: 1 MEDIUM (both round-1 fixes shipped with no regression test —
  a revert to the old broken code would still pass all 9 tests), 3 LOW
  (JSON escape sequences dropped rather than decoded in the new scanner —
  unreachable today since no real selector name needs escaping, but flagged
  for completeness; the same index-truthiness pattern the HIGH fix corrected
  in one file was left in two sibling spots; the new guard test asserts the
  aggregate count branch, not the per-selector branch).
- Red-team: **1 HIGH** — the exact escape-dropping bug the reviewer's LOW
  flagged is exploitable, not just theoretical: a unicode-escaped selector
  key (`version`) is treated as different from `version` by the raw
  scanner while `JSON.parse` collapses both to the identical key
  `version` (last one silently wins) — the duplicate-key guard's entire
  purpose defeated by exactly the class of input it exists to catch.
  1 MEDIUM — the inverse failure: two genuinely different keys (`ab` and
  `a\"b`) both collapse to `ab` in the scanner and get falsely flagged as
  duplicates.
- **Disposition: all accepted, fixed** (commit `af1f06d9`): the scanner now
  decodes standard JSON escapes and `\uXXXX` into the actual character
  before comparing keys, instead of dropping escaped input; 5 new regression
  tests added (14 total, was 9) covering both new fixes and the two
  round-1 fixes that had none; `assertAllSelectorsListed` also switched to
  `Object.hasOwn` for consistency with `explain-command-route.mjs`.

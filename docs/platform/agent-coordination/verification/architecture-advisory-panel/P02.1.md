## Requirement-by-requirement disposition

- **Role-level cognitive needs vs. concrete executor/tier/persona choices.**
  Confirmed as two genuinely separate layers in the real code: `schema.mjs`'s
  `ACTOR_FIELDS` (`id`, `role`, `persona`, `policy`) names WHO is bound at
  the session level; `cohort-planner.mjs`'s `deriveProviderFamily`/
  `resolveExecutorConfig` (imported from `dispatch/resolve.mjs`) derives
  the concrete provider/model at DISPATCH time, from tier + the executor's
  own `providerModel` config — never from a portable definition naming a
  local executor directly. This is the correct shape per the phase's own
  requirement ("reject both a single global model assumption and portable
  definitions pinned to local executor names") — no schema change needed,
  this is already how it works.
- **`actors[].model` gap.** Confirmed real: `ACTOR_FIELDS` has no `model`
  field, and a repo-wide grep for `actor.model`/`actors[].model` in
  `src/runner/` returns zero hits outside comments. Recorded here as a
  gap, not claimed as an existing channel. Whether V1 needs a general
  model-override channel or per-actor executor+tier+persona (with model
  derived via `providerModel`/`modelPolicies`) is sufficient is a decision
  this audit defers to Phase 03/04 — no Phase 01 behavior actually
  demanded a model override that `providerModel`/tier derivation could
  not already satisfy (P00.1's own real fix, adding `providerModel` to
  `codex-cli`, worked entirely within the existing channel).
- **N+1 reauthorization probe.** Answered directly, live: `activation.maxInvocations`
  is the actual enforcing mechanism, at both the authorization door
  (`authorizeOperation` in `store.mjs`) and the dispatch door
  (`createSessionAssignment`, defense in depth against a forged
  authorization). `topology.edges[].maxRounds` and `aggregateBounds.maxRounds`
  are real, but distinct, session/actor-wide counters — neither is what
  refuses a specific `(node, operation, actor)` binding's own N+1th
  invocation. Phase 03 may claim bounded selective reopen through this
  named mechanism.
- **Selective reopen through predeclared bounded bindings and append-only
  revisions.** Re-diagnosed by this audit, live evidence in hand: the
  mechanism WORKS CORRECTLY end-to-end in one continuous session — a
  passing live test (`coordination-run-live-proof.test.mjs`) drives
  produce → review → red-team → authorized revision → reject →
  authorized recheck ×2 → accept, all in one `fgos coordination run`
  call, with real driver events and a full replay reconstruction. The
  ONLY failure mode found is BL1: declaring `partialPolicy` at open
  causes the session to auto-close to a terminal status the instant the
  FIRST required pass finishes, before a fix round can ever be
  authorized on that same session — which is what actually blocked
  P01.1 and P00.1, not a graph-reachability defect. Phase 03 may claim
  bounded selective reopen works TODAY, for any session that does not
  declare `partialPolicy`; it may not claim it works when `partialPolicy`
  is declared until BL1 is fixed.
- **Distinct provenance for human input / interpretation / recommendation /
  decision.** Proven to hold across 3 real dialogue turns (P01.2 x2, P01.3
  x1) as pure file-naming/authoring convention (B8) — soul-doctrine
  placement, not hardened, and this audit does not recommend hardening
  the 4-layer split itself. The one real gap is layer 1's AUTHENTICITY
  (BL4), already assigned to Phase 03.1 and re-confirmed live here rather
  than only theorized.
- **Real request + RunResult proving distinct actor bindings.** This audit
  relies on the existing, passing `coordination-driver-authorization.test.mjs`
  suite (67/67, including the "does NOT authorize the SAME actor at a
  DIFFERENT binding" test) as the executable evidence, rather than opening
  a new coordination session for this cell (out of the phase's own Files
  scope). No shared-dispatch gap was found for actor bindings specifically —
  the gap this audit DID find and record is executor-name registration
  (BL2), a different kind of gap (config, not binding logic).
- **No schema field for a judgment heuristic.** Reviewed the manifest/event
  field tables in full (`schema.mjs`) — no field encodes materiality,

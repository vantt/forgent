## Design

Before implementation, an independent design consultation (kongming,
real read access to the actual coordination-engine source) was run to
answer: what is the smallest honest hard mechanism here, and is BL4's own
refusal wording ("distinguish an authentic human-submitted turn from
anything the coordinator process itself could write") even achievable?
Verdict: not achievable as prevention — the coordinator is the same
OS-user-privilege process that would author any ledger it's asked to
cite, so in-process prevention of fabrication (T6 below) is structurally
impossible, and any hook/HMAC/signature machinery pretending otherwise
would be security theater. What IS achievable and worth building: make a
driver-authored artifact structurally unable to occupy a human-decision
position (closed), and make any fabricated human turn an explicit,
immutable, cross-checkable false attestation rather than an invisible one
(detectable + attributable, not prevented). This became the implemented
design: one additive event kind (`human-turn-recorded`), one ref
namespace (`human-turn:`), one request-step type — no hooks, no
signatures, no new subverb.

**BL4 wording correction, per this cell's own report to the person:**
plan.md/phase-03's literal refusal-case wording overpromises prevention.
The honest restatement — implemented and now what the contract doc
actually claims — is detect/attribute, not prevent. Flagged to the
person as an FYI in the batched question that authorized this work; not
treated as a blocker.

## Review (independent Reviewer, `code-reviewer`)

Read the diff and design cold — no access to the Doer's own report.
**6 findings: 1 HIGH, 3 MEDIUM, 2 LOW.**

- **HIGH (R-P03.1-01):** `show.mjs`'s `isRefOwnedBySession` — documented
  in its own header as a mandatory rule-for-rule mirror of the write
  door — was not updated for either of the two new `human-turn:`
  namespace rules. Reproduced both directions: a bare `turn_1` ref (write
  door refuses) rendered `owned=true`; a valid `human-turn:<id>` ref
  (write door accepts) rendered `owned=false`.
- **MEDIUM x3:** replay missing 1 of 4 `attributedTo` refusals (a
  `driver-authored-ref-shape` check present at the write door, absent at
  replay — contract doc's T1 row overclaimed it was re-checked); no
  `turnId` shape guard at the store door (`contributionId` has one,
  `turnId` didn't); replay never re-validates a human turn's own
  `respondsToRefs` ownership.
- **LOW x2:** no workspace containment on `artifactRef`; a test-quality
  gap tied to the HIGH finding (existing show test used a ref shape that
  couldn't have caught it).
- Reviewer explicitly looked for a phantom test (one that would still
  pass with its refusal deleted) in the original submission and found
  none — the original test suite's realness was itself checked, not
  assumed.

## Threat model, final (T1-T8; full table in the contract doc)

Closed: T1 (driver/actor authority in the human-decision slot), T2
(silent edit/overwrite), T3 (turn replay/duplication), T4 (ordinal
gaps/reuse/post-terminal insertion), T5 (disposition citing a
never-recorded or premature turn), T7 (crash/race leaving a partial or
duplicated entry — proven under real concurrent load, not just reasoned
about). Narrowed-not-fully-closed: T8 (a hand-crafted `events.jsonl`
mirroring every real shape exactly — same disclosed residual class as
`aggregation-validated`/`specialist-authorized`, not new or worse).
**Open by design, cannot be closed in-process: T6** — the coordinator
process fabricating the underlying artifact bytes and a matching false
`externalRef`. Same privilege level as every other write this process
makes; no mechanism inside this process's own trust boundary can close
it. This is disclosed plainly in the contract doc, not papered over.

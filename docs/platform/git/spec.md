## 1. Purpose and boundary

Git decides what Git state exists, performs typed authorized mutations, and reconciles their interrupted effects. Rust is the live core now; Node transports typed inputs/results and owns no Git policy. There is no public `git(args)` port and no dual-run writer. Workflow, Execution Core, Work, business workflows, setup and Event Store are consumers, not parallel Git cores.

Git owns local object/ref/index/worktree mutations, worktree registration, the local side of fetch/push, and operation recovery. It owns neither business approval nor Work lifecycle, claim/state transaction, reducer, event envelope/union, seal schema, coverage or consumer cache. Holder-lock owns locks/fences; Process owns containment/signals; Session Identity owns writer identity. A read-only request never silently commits, builds, creates a worktree, configures a remote or repairs a repo.

Required component-boundary row on acceptance: **Git — foundation; owns repository facts, typed Git operations and recovery WAL; consumers Workflow/Execution/Work/Event Store/setup; dependencies holder-lock/process/session-identity; no consumer imports.** Remove “pure git integration” from Workflow's ownership. This row is required follow-up, not installed by this text.

| Mutation layer | Owner / success boundary |
|---|---|
| Local objects/refs | Git; expected-old publication says nothing about checkout or network |
| Local index/worktree/admin | Git; scoped commit/sync/land/restore/create/remove/relocate |
| Remote send/receive | Git transport port; explicit ref mapping and separate remote acknowledgement |
| GitHub API merge | GitHub adapter under consumer authorization; never a local land and never a policy bypass |

A network failure cannot undo local success. API timeout is outcome-unknown until queried; do not blindly issue another merge. GitHub transport must retain consumer approval/Iron Law and record the actual merge commit. This spec authorizes no external send by itself.

Git never imports a consumer. Verify/build/npm/`worktreeSetup.commands` are **not** Git operations (G-030/G-031). Execution provisions after `worktree-create` returns, **outside every Git lock**. Git may spawn only `git` (plus Process containment of those children). Consumer verification evidence is bound by digest; Git does not claim tests ran.

## 2. Shared entities and outcomes

| Entity | Contract |
|---|---|
| RepoHandle | Validated canonical common-dir and trusted main/root identity/topology; never worker `.git` authority |
| WorktreeHandle | Registered gitdir/backlink, canonical path, branch/detached OID, creation identity; revalidated at mutation |
| Oid | Full object-format-aware identifier; validated commit/tree/blob type, no fixed SHA-1 assumption |
| RefName / ExpectedTip | Full validated namespace-qualified **direct** ref; expected `Absent` or exact OID, never wildcard absence. Symbolic refs are refused in owned and mirror namespaces (C1). |
| Scope | Canonical RUL84 entries, matcher version and explicitly expanded generated grants |
| Custody token | Whatever Execution presents as live exclusive worktree right (generation-bound). Git **validates**; it does not mint a second lock. Mechanism is owner-open (section 6). A text session/writer id is not custody. |
| Candidate | Immutable source/target OIDs, exact result tree, parent/mode, **policy evidence digest**, pin |
| OperationId | Repo-scoped idempotency key bound to kind, repo identity, **canonical resource set**, expected values and authority domain; same id with different request digest refused; same id must not bind two disjoint resource sets |
| Receipt | Structured effect receipt (below). Operational evidence, not a consumer event |

Receipt (panelist 1 / C3) — effect is not completion:

```text
operationId, requestDigest,
localEffect {expected, publishedOid?, observedTip, publicationState},
checkout {notApplicable | pending | reconciled | recoveryRequired},
durability {processCrash | stableMedia, capabilityEvidence},
remote {notRequested | acknowledged | unknown | rejected},
consumerSettlement {notOwnedByGit},
attribution {thisInvocationWonCas | effectObservedOnly | uncertain}
```

`publicationState` distinguishes “currently at candidate” from “this invocation's CAS was observed successful.” Seeing `ref == next` after a crash proves the desired state exists; it does **not** prove which actor installed it. Do not manufacture writer attribution from equality. ABA (target returned to expected after a possible successful CAS) does not justify generic retry.

Results distinguish `unchanged`, `created`, `committed`, `landed`, `conflicted-open`, `conflict-aborted`, `busy`, `stale`, `refused`, `cancelled`, `failed`, `published-checkout-pending`, `committed-but-contract-violation`, `remote-outcome-unknown`, `recovery-required`. Include operation id, typed cause, retryability, actual effect/OIDs, exit/signal and bounded redacted stderr. An ancestry query returns yes/no/error; path-at-revision present/absent/error. Corruption, permission and unknown protocol never become “absent”. Cancellation after CAS reports the published effect. Local commit, reconciled checkout, remote ack and durable consumer settlement are separate facts.

## 4. Publication port: refs/fgos/*

Event Store's crate-internal driver (event-store spec §3/§20) moves behind this port **without a protocol change**. Node reaches publication through an **N-API addon of `fgos-git`** with **no exception** to the exec guard under the `state` lock. Git is forbidden under state 60. Event Store bounded append/read inside state remains its own in-process/open-log path; no DAG walk or Git call there.

**One Node load (requirement; mechanism open under Q1).** A Node process must reach one in-process instance of `fgos-git`. Event Store's signed design (event-store spec §12, §17, §21) ships its own N-API addon of crate `fgos-event-store`, which links `fgos-git` in Rust; two independent Rust cdylib addons cannot share one in-process crate instance without a defined mechanism. The admissible topologies are (a) one combined native addon crate exporting both the Event Store and Git facades, (b) separate addons where Event Store's seal/sync publication calls cross into `fgos-git`'s addon through the JS facade, or (c) the host route `fgos internal git <op>` for every Git operation outside the state gate with Event Store as the only in-process Rust linker. Topology (c) satisfies the brief's N-API requirement for publication only if Node never calls the publication port except through Event Store's addon: Event Store's N-API addon is then the sole Node entry to publication, and no separate direct Node-to-`fgos-git` publication call exists (RT2-F2). Until Q1 selects one, duplicate doctor ABI rows and two paths to the same refs are refused and the dual-load test (§15) fails closed. Rust consumers (observe, `fgos-work-state`) link `fgos-git` in-process.

Operations: writeBlob(bytes), writeTree(literal entries/modes/OIDs), writeCommit(tree, ordered parents, identity/message), readRef/Object, walkCommits(tips,cursor,bounds), compareAndSwap(ref,expected,next,operationId), fetchRefs and pushRefs. No index, worktree, HEAD, main-checkout lock, or consumer semantics.

**C1 — distinct execution policy.** Publication operates on direct namespace-qualified refs. It refuses symbolic refs in owned and mirror namespaces, validates the destination, and uses a backend mode that cannot follow a symbolic ref outside the grant even if the ref changes after preflight. A plain textual prefix check is insufficient. Object writes and reads do not enable replace-object or alternate-object authority from worker input. Worker-supplied alternate-object, replace-ref and shallow authority (`GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_REPLACE_REF_BASE`, `--reference`-style overrides, config injected through the scrubbed env context of G-001/G-183) is always refused. Repository-owned layout in the trusted common dir (`.git/objects/info/alternates`, shallow, promisor remotes) is a compatibility profile: until E5 establishes which of these configurations `fgos-git` supports, an operation that needs an object unavailable under that layout refuses by name rather than fetching implicitly, and the refusal names the layout feature.

Publication's private Git calls **cannot execute repository hooks**, including the **reference-transaction** hook, nor inherit worker-provided external commands. “No hook-running commit porcelain” is not enough. This does not disable guards on ScopedCommit or checkout mutations. Transport helpers and credential providers are Remote capabilities, not implicit privileges of writeBlob/readObject/CAS.

Use explicit trusted common-dir plumbing. Validate object types and refs. Event Store provides the seal/merge manifests and parent order; Git never computes event union or business conflict outcomes.

Namespace grants are explicit: own events/local-events/branch-events and authorized one-time legacy import; mirrors only fetch-written; Git operation pins reserved to Git. CAS distinguishes absent from exact OID and returns actual tip on loss. No event segment deletion follows a Git receipt alone: Event Store still verifies coverage and durably records its own sealed receipt.

Required unchanged Event Store protocol:

1. Seal/sync owns event-seal 58; event-append 70 protects rotation only and is released before Git.
2. Write trees/commits, journal intent, CAS `refs/fgos/events/<machine-id>`; retain segments on CAS loss. Event Store retries by its section 10 rules.
3. Walk both parents of a DAG with visited set and bounded continuation. Only Event Store decides certified coverage pruning. Incomplete traversal never claims complete coverage.
4. Fetch `+refs/fgos/events/*:refs/fgos/remotes/<remote>/events/*` and the existing legacy mirror mapping. `+` is allowed only for mirror refresh as Event Store §14 requires. Never overwrite own ref by fetch.
5. Push only own events and authorized legacy ref; never force-push, mirrors, local/branch streams or Git pins. Non-FF triggers Event Store fetch/reconcile using a two-parent commit then ordinary push. No Git-side event reconciliation.

CAS implementation may use `update-ref --stdin` to move the **target ref and the operation pin** in one transaction. The pin is reachability against GC, not the receipt. The file WAL record remains the authority for intent, phase and attribution.

**Non-publication Node→Rust route** (commit-scoped, land, worktree): brief item 1's N-API sentence sits in the publication topic; Event Store §17's in-gate rationale does **not** extend. G0 default until the owner answers Q1: the same `fgos-git` addon, used **outside** state 60, still never an exec-guard exception. Panelist 2's host route `fgos internal git <op>` remains a live option for out-of-gate ops, decided by Q1 + E3. Do not ship both.

## 5. Layering and unchanged 4.3-R locks

Reuse Holder-lock's registry, existing paths/ranks, kernel drivers, description borrowing, predecessor domain and fences **unchanged**. No TTL/heartbeat/PID-based authority, inode deletion/recreation or new lock map.

Every mutating request declares a canonical resource set and the **existing** authority required for that set. Normal execution and recovery acquire the same resource authority. Publication of an Event Store stream uses event-seal; branch land uses merge-slot and, where needed, worktree-admin/main-checkout; worktree effects require the applicable admin/main authority and continuous Execution custody. A supervisor recovery lock may serialize the supervisor; it **never** substitutes for these authorities and is not a repository-wide journal mutex. Recovery determines needed resources before acquiring locks. Unsupported or missing authority refuses mutation.

A fresh Rust scope must not hide the Node caller's held locks. Sharing an opaque LockScope through N-API is a **requirement to prove** (fd inheritance / mapped slot), not a bitmap declaration. `heldRanks` is B's host-route device; it is not G0 default. Unknown mutation posture fails closed. Holder-lock §9 defines LockScope as a Node object that acquires kernel locks by spawning `fgos internal lock-fd` with the fd in stdio slot 3; it defines no cross-language handle. If N-API is chosen for lock-taking operations (commit-scoped, land, worktree), one of two architected options must be adopted before any such operation ships: (a) Rust `fgos-git` acquires 20/40/50 in its own Rust LockScope and receives the Node caller's held ranks and lease descriptors as explicit, kernel-verifiable parameters (functionally candidate B's `heldRanks` plus a slot-3 lease borrow), or (b) Holder-lock is amended to define a cross-language LockScope handle. Publication is unaffected: under seal 58 it never acquires 20/40/50.

| Rank | Resource / rule |
|---|---|
| 20 | Existing per-target merge-slot; reserve before expensive land work; no-wait handled here |
| 30 | Existing `dispatch-cwd` lease. **Not** a Git lock. See N7. |
| 40 | Existing worktree-admin. Holder-lock §16/D8 currently wraps **`git worktree add` only**. |
| 50 | Existing main-checkout, only short actual main index/tree/HEAD mutation/recovery |
| 55 | Git-native index.lock, never an fgOS implementation |
| 58 | Event Store event-seal; publication cannot acquire 20/40/50 beneath it |
| 60 | Consumer state; no Git, child, verify/build or lower-rank acquisition |
| 70 | Event Store event-append; no Git while held |
| 80 | Existing leaves such as recovery, only after all needed lower ranks; release before later state 60 settlement |

The common order remains 20→40→50→60. Operations take only needed locks. Verify/build never runs under 50/60. Publish revalidates under appropriate locks and performs no arbitrary Node callback. Consumer settlement follows release. Recovery requiring main takes 20/40/50 before recovery 80; publication recovery without checkout takes no main/admin and remains compatible with caller seal 58. No invented publication lock rank.

**worktree-admin wrap set (honest).** G-042 requires dirty-check through destroy under one ownership. Current Holder-lock §16 does **not** promise remove/relocate/prune. G0 Git callers **must not invent a second admin lock**. Expanding the wrap set is a **Holder-lock spec amendment** (follow-up owned by Holder-lock). Until that amendment lands, Git remove/relocate/prune are Git operations that still require rank 40 **only if** Holder-lock grants it; otherwise they remain the G-042 gap, named, not papered over. Read-only listing is not a globally serialized exclusive operation.

**Rank-30 vs rank-20 legality (required table; empty of a closed N7).** Rank 30 sits between merge-slot 20 and worktree-admin 40. If the runner's LockScope still holds 30 and Git (same scope, N-API) needs 20, that is lock-order inversion. Commit-scoped needing 50 while holding 30 is legal. Land needing 20 while 30 is held is not. G0 cannot freeze until this table is filled by the N7 owner decision. None of A/B/P1/P3 wrote it.

Borrow via existing `run_borrowed` only: exact child fd mapping, CLOEXEC restored, inode/description try-lock borrower check, close-only release, gc/maintenance auto off, wait for child domain empty. Text env/PID grants do not confer authority. Hook strangers probe once and never wait while holding index 55. Activity beacon is advisory, never a lock.

Monotonic bounded wait budget covers retries. Retry only named contention, not lock-order/corruption/unknown protocol errors. Cancellation/timeout uses Process containment. Git installs no process-wide handler that kills Node. Post-effect cancellation records/reports pending recovery. Platform guarantee and macOS containment limits inherit Holder-lock; unsupported Windows/filesystem posture is a named failure until its driver is actually activated/proven.

## 6. N7 and RUL84

**N7 — ownership closed; mechanism open.** Execution owns continuous custody from producer start through attempt exit, runner commit, receipt and handoff. Worker exit never releases custody. Git validates it and owns the mutation, not attempt scheduling. Successor producer/reset/sync/remove/commit is refused until current generation handoff is proven. Missing/stale custody fails closed. Read-only workflows require no writable custody.

Owner-named: Execution holds, Git validates. **Do not claim N7 closed by a Git `Custody` entity or by a Git-only lease extension.**

- A's new entity is a second custody token beside an existing lease (design principle 1 objects).
- B's “extend `dispatch-cwd` across commit” amends holder-lock §19, owned by the **run supervisor**, not Git.
- Predecessor-domain emptiness on Linux/macOS is **not** an existing guarantee (holder-lock §19). Any sentence “refuse until predecessor domain empty” is vacuously true or unimplementable today; state that assumption as currently **false** until the attempt lock exists.

No claim of concurrent commit safety until the real route supplies the contract. Owner question 2.

**RUL84.** The lowest shared **write-scope foundation leaf** owns the grammar/matcher/expansion; Execution owns granted paths; Git enforces them. One Rust implementation and one port; no Node matcher plus a Rust copy. It may initially be a leaf module of the Git package but imports no operations or consumer. Replace `src/runner/dispatch/write-scope.mjs` with a thin facade in the same switch, preserving exports/golden semantics. Packaging (leaf vs independent crate) follows the route decision; it does not give Git ownership of Execution's grant policy.

Preserve grammar: canonicalize declaration trim/dot/separators/consecutive whole `**`; reject absolute/`..`/backslash/NUL/leading colon/embedded `**`. Only `*` within segment and whole-segment `**` glob; all other metacharacters literal; plain entries cover subtree by full segments. Query path bytes are not trimmed; both rename ends are checked. `.fgos` is excluded even by `**`. Generated grants use the same expansion primitive. Byte paths not representable by existing string grammar are refused with lossless encoded path, never lossy-matched.

## 7. Hardened Git backend, parsers and hook contract

One private CLI driver; no shell interpolation. Runner policy scrubs inherited `GIT_*` and constructs explicit typed per-call overrides. Preserve currently supported author/committer identity/date and trusted config-file policy; worker-controlled config env is not trusted input. Disable fsmonitor; merge rerere and autoStash off; borrowed automatic gc/maintenance off. Gitdir authority comes from trusted common-dir registered backlink and real path/identity, never worker `.git`. Revalidate symlink/inode substitution before effect.

**Two named env contexts, one backend owner (C6 / G-001 vs G-183):** (1) scrubbed runner calls; (2) validated hook context that retains Git-supplied index/worktree/gitdir so guards inspect exactly the commit index (including temporary index). Never scrub that authority away. Worker cannot request hook context by arbitrary env bag. Resolve hooksPath relative to trusted main; setup writes absolute owned path when filling an empty slot, preserves custom hook path and diagnoses missing enforcement.

No hardcoded trunk: explicit consumer target, remote default, then validated main attached branch; ambiguity/missing target is named. Full refs/end-of-options prevent tags/options/ranges from changing meaning. Validate commit type. Batch object/path-at-revision returns error distinct from absence.

NUL-delimited lists everywhere including worktree list; literal paths/no trim; status explicit untracked; diff `--no-relative`; scope lists `--no-renames` or return both ends. Stage literal NUL pathspec stdin, never glob argv. Stream outputs or preserve explicit equivalent ceilings (64MiB path lists, 50MiB review diff; blob guards stream); overflow is typed refusal, never silently incomplete.

Hook ordering (surviving guards; PID-grant and event-monotonicity steps **superseded**): stale-index guard; tracked `.fgos` deletion (non-event; event-file deletion only in authorized cutover grant); worker `.fgos` exclusion; root-file guard; warning-only convention; at-home check; main branch restriction; 4.3-R borrower/stranger probe; identity/beacon; beacon written last. Remove only the retired event monotonicity guard at Event Store cutover. Merge skips root allowlist exception only, not safety guards. Identity/index/blob/unknown-protocol failures close; corrupt advisory beacon warns. Physical trusted hook home and platform path equivalence are tested. Hook diagnostics retain underlying reason. Custom hook directory lacking mandatory guards is an explicit doctor gap.

**G-062:** preserve original hook failure evidence. Do not claim diagnostic replay is harmless. If compatibility requires replay, restrict it to a known safe guard invocation and identify it; arbitrary user-hook replay is not automatic recovery.

## 8. Scoped commit and sync

Before producer, check trusted linked worktree/custody, no foreign staged entries even in scope, no foreign MERGE_HEAD; capture source baseline, existing dirty paths/content and ref. Worker may not stage or commit. After producer, exact authorized path selection includes both rename sides/deletions; revalidate authority/state and stage only selected literal paths. On failure unstage only this operation's entries and preserve bytes/foreign changes/cause. No-op differs from failure. Verify actual committed set/tree after hooks. If hook changed it, return `committed-but-contract-violation` with real OID; preserve effect, do not retry producer as though nothing happened. Resume commit-only retains captured intent/custody.

Sync merges pinned target OID into producer using no-commit/no-ff. Source-side non-event tracked `.fgos` stays source-side; workers receive no store grants. Clean sync records two exact parents.

**G-071 effective (C6), not A's “abort all out-of-scope”.** Only the operation's scopable conflicts receive a **temporary** resolver grant; original producer `writeScope` remains unchanged; non-event `.fgos`, unscopable and forbidden paths do not gain grants. Continue refuses leftover conflict markers (seven or more `<`, `>` or vertical-bar characters followed by whitespace/end; skip binary/non-regular files) without staging, and validates parents/MERGE_HEAD/index/custody, detects manual completion/abort as done/not-started/lost, stages only owned conflict paths. Hook rejection retains cause. Sync-only without conflict work never spawns a producer.

**G-202 recommended closure, not a frozen catalogue obligation.** Catalogue §7 Q16 still records catchup-vs-sync as an **open design decision**. Recommended (P1/P3, not “the catalogue required it”): catchup uses the same isolated scoped resolver **when custody exists**; otherwise abort only owned merge. Land candidate conflicts **abort**. Owner question 5. If adopted, scoped session without custody is forbidden (resolver on a worktree the runner does not own).

## 9. Land: candidate, verification, publication

Consumer supplies source/target OIDs, merge or squash, and **policy evidence bound to those OIDs/target/tree**. Work owns lineage/dependencies/approval/Iron Law; Git enforces the frozen binding and never imports Work. Workflow calls the same port. Squash creates a real one-parent commit; ordinary merge exact target/source parents; a staged squash index is not success.

Honest verification contract (not “nothing unverified is published” via tree equality):

- Consumer produces evidence bound to exact OIDs/tree (runs verify/build in the candidate worktree through Process, **outside Git**).
- Git binds that digest and refuses publish on mismatch, missing evidence, or dirty candidate (`write-tree` ≠ candidate commit tree, or digest mismatch).
- Git does **not** claim tests ran. A lying consumer can publish an unverified tree that matches the candidate. Tree proof is identity, not verification. V-VERIFY must not be marked passed by tree equality alone.

1. Reserve target merge-slot 20; inspect true topology, source/target and target checkout status/index/MERGE_HEAD. Reject foreign state.
2. Create detached operation candidate under admin 40, release admin, construct merge from pinned target. Land conflict aborts candidate only; source and target preserved. Consumer transformations of non-event `.fgos`/decision documents produce declared candidate bytes, not Git-owned state meaning.
3. Consumer verifies/builds outside 50/60. Freeze tree/evidence before and after; any changed candidate/dependency setup invalidates evidence. No post-verify strip/renumber can publish bytes that do not match the bound digest. Pin candidate/bases against normal GC.
4. Reacquire required admin 40/main 50 in order; revalidate target/source, evidence and candidate; re-run the own-file-set clean gate (G-098/G-102: union of committed diff and declared footprint, normalized; whole-repo scope for land, subtree scope for return; `.fgos` never counts; fail-safe to every non-`.fgos` path when the set is absent; a staged rename blocks when either half is own) and return `main-checkout-dirty-mid-merge` without moving the ref when it fails. Never use main dirty bytes as merge input. Detect foreign linked checkout holding target; v1 refuses publication into it unless it is an explicitly supported operation-owned checkout with custody. Never move a branch behind another index.
5. Durable intent/prepared pins precede exact-old target CAS. CAS loser returns stale and cannot reuse verification against a new target. When the main checkout holds the target, the winner runs non-destructive `read-tree -m -u HEAD` under main 50; non-overlapping dirty paths are tolerated and the checkout is left lagging per D-ADR0042 (G-099), recorded in the receipt as checkout-lagging rather than failing the land; ref success is never reported as checkout synced. No blind `reset --hard`.
6. Read back actual ref/tree/index, durably record receipt, release locks; consumer records actual `mergedSha`/`mergedInto` by operation id. Settlement failure is landed/consumer-settlement-pending, not permission to merge again. Land and cleanup remain separate.

Raw external Git ignores fgOS mutex. It is outside concurrency guarantees; pre/post drift is detected and preserved as recovery-required, never silently overwritten. A hook early probe is not full exclusion against raw checkout/reset/read-tree.

## 10. Journal: durability, schema and ownership

**One recovery authority: the file WAL.** Location: `<git-common-dir>/fgos/git/operations/<operation-id>/`, outside worktree/runtime scratch, shared by linked worktrees, no config/env override. Operational state for recovering effects under L7, not product event truth. Consumers still publish business history through Event Store. L1/L3 are not changed.

Do **not** run a dual-write protocol. Pins under `refs/fgos/git-operations/<id>/` are reachability only. A multi-ref transaction may update target + pin together; the pin is not the receipt. E1 decides whether git `core.fsync=objects,reference` would suffice for a **future** ref-only journal (B). Failed E1 does not license two authorities “until then.” B itself says failed E1 reopens A.

**C2.** Operation records are **evidence, never lock authority**. Each mutation and its recovery identify the existing serialization resource and pass its live opaque scope/handle. No operation-directory creation, PID, TTL or journal generation constitutes ownership. Same-id requests have one immutable request digest and one transition writer under that context. Concurrent identical request returns busy or the established receipt; different request is refused. The same id cannot be used on two disjoint serialization resources (P-WAL-ID).

Versioned immutable numbered records carry canonical digest/predecessor digest; write exclusive temp, fsync file, atomically install without overwrite, fsync directory **and parent-dir durability**. Parse/hash/version/chain error is corrupt, never empty.

Discriminated payload (panelist 1) — A's universal `target.next` + candidate parents cannot express delete / worktree move / config / pre-OID scoped commit:

```text
Intent {
  version, operationId, requestDigest, repoIdentity,
  kind, resourceSet, authorityBinding, writerIdentity,
  payload: RefUpdate | RefDelete | Land | ScopedCommit | Sync |
           WorktreeCreate | WorktreeMove | WorktreeRemove |
           Restore | ConfigChange | RemoteTransfer | PublicationCas,
  previousDigest: null
}
Record {version, operationId, sequence, previousDigest, phase,
        observedFacts, effectReceipt?, error?, digest}
```

Each payload specifies preconditions, irreversible boundary, snapshot/pin needs, recovery observations, and terminal outcomes. The phase graph is operation-specific. `intent → prepared → ref-published → checkout-reconciled → complete` is the **Land** graph, not universal. Publication-only skips checkout. Nested pin writes are prepare substeps, not recursively new top-level WAL operations. An object write with no published ref is not a completed publication.

Before durable prepared, unreferenced objects may disappear and must be rebuilt/reverified; they are never acknowledged publication. Read-back is mandatory; a record alone is not proof of effect.

| Actual state on recovery | Required action |
|---|---|
| ref=expected, prepared candidate intact | Retry only with valid custody/evidence/snapshot; else preserve/refuse. ABA: equality is not “safe to retry.” |
| ref=next, publication-only | Validate objects/parents; report effect-observed; claim this-invocation only with WAL evidence |
| ref=next, checkout/index=next | Complete missing receipt; markers may lag effect |
| ref=next, checkout/index exactly captured old | Guarded finish under locks/custody then verify |
| ref=next, mixed state/user edits | Preserve snapshot/current bytes; recovery-required, no blind read-tree/reset/abort |
| ref neither expected nor next | Never roll back another writer; ancestry/reflog as evidence only; retain pins; report supersession/uncertainty |
| corrupt journal/missing required object | Fail closed with evidence location; never reconstruct intent by guess |

Child death/timeout around CAS is unknown until read-back. Startup mutation checks pending entries touching its resources; **bounded scan returning incomplete knowledge is not clearance to mutate** (C4). Doctor is read-only. Explicit repair/supervisor uses the same crate/locks; no separate Node repair core.

Unresolved records/pins/snapshots never expire by TTL. Doctor reports pending count, retained bytes, oldest unresolved operation and consumer acknowledgement debt. New preparation may refuse with a named storage-capacity cause; it must **never** recover capacity by deleting unknown evidence. Compaction retains request digest and durable terminal receipt needed to reject same-id reuse; consumer ack does not make the id reusable. WAL compaction never authorizes event segment deletion.

**C4 ENOSPC/fsync.** ENOSPC, inode exhaustion, permission failure and failed fsync **before** the effect refuse; **after** the effect return observed/pending durability, not ordinary no-effect failure. Must not report durable success without advertised persistence of objects, ref **and** journal. Process-crash read-back is not power-loss durability: stable-media claims require measured fsync/filesystem support, reported by doctor. Failed support narrows stated capability or reopens design.

## 11. Filesystem repair and safe cleanup

Native index.lock/ref.lock/packed-refs locks are not Holder-lock files. Existence/age/PID guess never suffices to unlink. Uncertain live ownership yields busy/recovery-required. Quarantine only exact owned dead-child artifact under corresponding exclusion with operation identity and immediate inode/state recheck; preserve contents/provenance. Unknown external lock requires inspected repair, never force. Do not write Linux `/proc` as the portable ownership test (`holders()` is `unlistable` on macOS/Windows).

Under the applicable admin authority, in one transaction validate worktree canonical identity, not main/root/live cwd, custody, staged/unstaged/untracked state, pending operation, delivery/content proof and current tip. Dirty/uncertain trees are preserved/relocated with warning; remove failure never falls through to rm-rf (supersedes G-046 `finally` force-remove and live `integrate.mjs` `fs.rmSync` fallback). Missing directory alone does not justify prune: inspect registration/backlinks/ownership. Interrupted create/relocate journals paths/registration and reconciles before consumer session registry settlement.

SafeRestore checks full locked status, target commit and ancestry then creates durable binary/untracked/mode-preserving snapshot before destructive effect. No retry reset/clean discards producer writes. Cleanup requires consumer harness/retrospective gate separate from land; patch-id fallback is reported as limited evidence. Unknown proof preserves branch. Delete is expected-tip CAS and refuses in-use branch. Cleanup warning never negates completed land. G-193: preserve valuable bytes and session identity; legacy force is not a data-loss bypass.

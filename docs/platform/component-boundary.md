## 1. Purpose

This document is the platform-wide anchor for component boundaries.

It answers:

- which major components exist;
- which parent/child responsibilities belong together;
- which component owns a decision or state write;
- which areas depend on each other through explicit contracts;
- when a design changes the whole-system boundary map.

## 3. Update Rule

Any design discussion or documentation rewrite must check this boundary map when it changes:

- a platform component;
- a parent/child component relationship;
- ownership of a state write, decision, runtime authority, or contract;
- a cross-area dependency;
- the boundary between platform core, platform support, domain layer, host surface, or extension/plugin layer.

If the boundary changes, update this document or the current detailed source listed above. If it does not change, record `No component-boundary change` in the implementation alignment, verification note, discussion summary, or PR note.

| Session Identity (Writer Identity) | Foundation authority for "who is the writer of this process" (`{id, source}`). One implementation, the Rust crate `fgos-session-identity` (`packages/session-identity/rust`, native verb `fgos identity`); Observe calls it in process, Node through the facade `src/util/session-identity.mjs`. Also mints the writer id of an attempt (`att-<attemptId>`, route `fgos internal identity mint-attempt`) and carries the launcher's env scrub the gate applies. Owns no state and depends only on `fgos-host-runtime`; Observe depends on it; the run supervisor's controller half calls the mint. Grants no lock or claim authority. | [session-identity/spec.md](session-identity/spec.md) |
| Terminal-control (L2) | Foundation component for "which pane does this key run in" on a terminal multiplexer, usable without a run. Rust crate `fgos-terminal-control` (`packages/terminal-control/rust`) with a key-addressed upper port and a driver port with declared capabilities (herdr first; Windows declares none). Writes only the allocation record; closes only panes it allocated, never a tab; Node reaches it through the internal route `fgos internal terminal-control`, no user verb. Dependency one way: run supervisor → Terminal-control (the supervisor holds the key, the attempt id, never a pane). Node migration done; setup adds the `terminal` config section and `<stateRoot>/terminal`, doctor runs `terminal-control`, `terminal-config` and `terminal-allocations`. | [terminal-control/spec.md](terminal-control/spec.md) |
| Process Facts & Control (L0) | Single authority for "is this process tuple `{host, bootId, pidNs, pid, startTime}` alive, dead or unknown" (`judge`, one shared vector file for Rust and Node), for signalling a process by identity (`pidfd` on Linux, never a bare pid), for spawning with an explicit fd mapping, and for the domain primitives `domain_is_empty`/`domain_kill_all` the predecessor rule of holder-lock needs. Never spawns to read facts, never kills by bare pid, never reads mtime, knows no run, lock or pane. Rust crate `fgos-process` (`packages/process/rust`), one driver per OS; the Node leaf `src/runner/dispatch/process-identity.mjs` reads the same vectors, and reconcile imports only `facts`. The gate primitives (subreaper, PDEATHSIG, PID namespace, tty) stay with the run supervisor; the containment port lives in this crate (row below). Depends only on the OS. | [process/spec.md](process/spec.md) |
| Holder-lock (L1) | Single authority for "who holds which resource", as the kernel sees it: kernel locks on open file descriptions behind one OS-neutral port (`acquire`, `release`, `run_borrowed`, `probe`, `holders`, `guarantee`), the lock registry (`packages/holder-lock/contracts/lock-registry.v1.json`: every lock's kind, scope, rank, path, legacy shape and fence), lock order inside one `LockScope`, the description rules, the predecessor-domain rule, the single state-root resolution and the cutover fences. Never reads writer identity, never takes a lock from a live holder, never derives a decision from a pid, TTL or mtime. Rust crate `fgos-holder-lock` (`packages/holder-lock/rust`) plus the internal routes `fgos internal lock-fd|state-root|quiesce-scan|lock-borrow-vectors`; Node only through the facade `src/holder-lock/`, which never exposes an fd. Depends on Process Facts & Control and the kernel. Owns the cold locks (gateway, runner, sessions, advance, reconcile, recovery, full-suite, provider account/state, dispatch cwd) and the main checkout mutex (one door `withMainCheckout`, git children and the pre-commit hook borrow the lock through the description, no pid or TTL), the merge slot and `worktree-admin`; `fgos lock fence` is the one door for a hung live holder. `advance` follows Shape C (D-ADR0070 (workflow guide + admission ledger), owner 2026-10-19, [workflow.md](../specs/workflow.md)): a conductor case holds it for one reserve or one release/settle; the Playbook proposer holds it for the life of its loop, so its holder is the proposer's liveness, as today; a dispatch naming a live playbook case from inside its own Unit is refused by name. `answer` never appends directly: it writes the gate-answer file and tries `advance` once. The worktree binding is one exclusively created file per worktree, not a registry row. No new lock row; rank stays 80; no re-rank for an Event Store cutover. It does not own the state store's hot mutex (`state`, `porting-events`: `withStateTx` in `src/state/hot-lock.mjs`, which replaced `events.lock`, `claims.lock` and `porting/events.lock`): the state store owns that mechanism, a temporary one until the store moves to Rust, and takes only its cleanup lock and the fences from this component. The main door's `.fgos` checkpoint is a detachable adapter, so the lock core knows nothing of the event log. | [holder-lock/spec.md](holder-lock/spec.md) |
| Containment port (L0) | Single authority for "which processes belong to this attempt, and are there any left": an OS-neutral process domain per attempt (`create`, `spawn_in`, `is_empty`, `kill_all`, `guarantee`) with one driver per OS (`bwrap-pidns` and `linux-pgroup` on Linux, `windows-job`, `macos-tree`), each reporting a guarantee level (`kernel` or `best-effort`) and its named escapes. Knows no attempt beyond the id that names a domain, and no envelope, lock or pane. Module `containment` of the Rust crate `fgos-process` (`packages/process/rust`), contract `packages/process/contracts/containment.port.v1.json`; depends only on the OS. | [process/spec.md](process/spec.md#10-containment-port) |
| Git (foundation) | Single authority for repository facts, typed Git operations and their recovery WAL: every fgOS mutation of local objects, refs, index, worktrees and worktree registration, the local side of fetch and push, and operation recovery, through typed ports (Inspect, Refs, Worktree, ScopedCommit, Sync, Land, SafeRestore, RepositoryConfig, Remote, Recovery, Publication); no public `git(args)` port. Its Publication port is the only door to `refs/fgos/*`, and Event Store is the only production writer of event refs through it. Owns no business approval, Work lifecycle, event semantics or lock mechanism. Consumers: Workflow, Execution Core, Work, Event Store, setup. Depends on Holder-lock, Process Facts & Control and Session Identity; imports no consumer. Rust crate `fgos-git` (`packages/git/rust`, planned); Node reaches it only through the one combined N-API addon that also links `fgos-event-store`. Not implemented: today's Node git writers stay until the Git plan replaces them in one release per caller family. | [git/spec.md](git/spec.md) |
| Event Store (foundation) | Single authority for how an fgOS event becomes durable, is sealed into git objects on per-machine `refs/fgos/*`, is shared across machines and is read back: the v4 envelope and stream registry, the per-stream open logs and their `event-append`/`event-seal` locks, seal and recovery, the reader with coverage, causal order and cursor, sync, and the store side of the `fgos events` verbs (`src/verbs/events/`). Planned consumers: Work, porting, observe, decisions; each owns its types, gate, reducer and view, and the store imports none of them (`packages/event-store/contracts/consumers.v1.json` is the only registry). Depends on Git's Publication port (the only door to `refs/fgos/*`), Holder-lock and Session Identity. Rust crate `fgos-event-store` (`packages/event-store/rust`); Node only through the facade `src/event-store/` over the one combined N-API addon shared with `fgos-git`. Dormant on main: store layer proven (2026-10-20), no consumer registered; the Work cutover is the WORK lane. | [event-store/spec.md](event-store/spec.md) |
| Run Supervisor (L4) | One Rust process per attempt that owns the attempt after the controller handed it over: holds the attempt lock and the cwd lease, creates the containment domain, starts the launch gate, watches the soft deadline and idle, publishes the receipt and the per-step receipts, runs the post-receipt steps and owns the adopt door (`fgos internal adopt`, one door for resume, recover, scan and home cleanup). A supervisor that dies leaves the agent running; adopt settles it. Never knows a pane or a terminal, never picks a provider or retries, never judges the work (Run Result Evaluator inside the Node `settle-attempt` step). Crate `fgos-run-supervisor` (`packages/run-supervisor/rust`), routes `fgos internal supervise\|gate\|adopt\|attempt-step` (protocol 1, not in help), Node client and steps in `src/run-supervisor/`. Depends on Containment port, Process Facts & Control, Holder-lock and agent-protocol. Two launch modes: `direct` (headless process) and `terminal` (an agent in a terminal-control pane, addressed by the attempt id; the supervisor listens on an attempt socket, drives the pane through the agent protocol and ends with a `release-slot` step). Depends also on Terminal-control (in process, by key). | [run-supervisor/spec.md](run-supervisor/spec.md) |
| Launch gate (L4, part of the run supervisor) | The process root of the agent inside the containment domain (pid 1 of a fresh PID namespace on Linux): owns the agent's IO (capture files, stdin; in `terminal` mode the pane's tty, with the agent as foreground group), refuses to run the agent without GO (in `terminal` mode GO arrives over the attempt socket with the attempt lock and cwd lease as `SCM_RIGHTS`, the peer uid is checked, and the gate runs in the pane, so the gate holds the attempt lock and outlives a dead supervisor), applies the environment scrub and the attempt writer id, reaps every orphan with `waitpid(-1)` for the whole attempt, enforces the hard ceiling (SIGTERM, `dispatch.gateKillGraceMs`, SIGKILL) on its own clock and publishes `gate-exit.json` once the domain is empty. `fgos internal gate`; same crate and spec as the supervisor. | [run-supervisor/spec.md](run-supervisor/spec.md#5-supervisor-and-gate) |
| Agent protocol (L3) | Pure per-CLI adapters (claude, codex, agy, pi, omp) that read what an agent CLI showed (capture tail, exit, outbox) and name the result (`completed`, `blocked(login\|trust-dialog\|usage-limit)`, `needs-human`, `exited`); decide stdin policy and the activity source for idle. Never builds argv (that stays with the executor configuration through `resolveExecutorCommand`), never retries, no dependency on terminal-control, locks or attempts. Direct and terminal adapters; the terminal ones read the pane through `AgentIo` (`screen`, `inspect`) wired by the supervisor to terminal-control. Crate `fgos-agent-protocol` (`packages/agent-protocol/rust`). | [agent-protocol/spec.md](agent-protocol/spec.md) |
| Agent Mailbox (L4, signed at G0 on 2026-10-20; implementation not started) | Single authority for "how a message from one agent session is placed into the context of the right live head of a CLI on this machine, with an honest delivery report, and never as the user's input": the envelope, the delivery state machine (`recorded`, `in-flight`, `offered`, `refused`), the registry of heads (name, per-process generation, process `Record`), the channel-protection policies, the peer frame, and the per-CLI hook payload shape and non-terminal wake channels (the Claude Code scoped socket, `codex queue`). Recipients are independently started interactive heads, never a runner Unit attempt, a subagent or a teammate. Owns one runtime-state record per project at the main checkout's `.fgos` (not event truth, never replayed, never pushed). First slice imports only `fgos-process`, `fgos-holder-lock`, `fgos-durable-file` and `fgos-session-identity`; its core crate `fgos-mailbox-core` depends on serde alone. Never owns writer identity (Session Identity), process liveness (Process Facts & Control), the main-checkout `.fgos` resolver (the host), pane access (Terminal-control), typing or screen reading (Agent protocol; a later part), hook installation (the setup installer), locks (Holder-lock), communication authorization or case budgets (coordination foundation), or steering a Unit attempt (the runner). Rust crates `fgos-mailbox-core` and `fgos-mailbox` (planned: `packages/mailbox/rust`). | [agent-mailbox/spec.md](agent-mailbox/spec.md) |

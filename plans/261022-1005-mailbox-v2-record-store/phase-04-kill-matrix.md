# Phase 4: Kill matrix at every write step

## Context

- Plan: decision 8 (observed holds), outcome item 4.
- Spec §6.4 ("atomically visible and process-crash safe", not "durable"; "a holder that dies is expected to release it with the process; V2 proves this on the mailbox's own path"), §10 rows "The mutex holder dies mid-mutation" and "A crash in the middle of a snapshot write", §11 Core suite "snapshot install atomic under a kill during write (V2)".
- Precedent for real child processes: `packages/distribution/rust/tests/activation_lock_multiprocess.rs:20-60` (the test binary re-executed with a role in its environment; a ready file installed by rename; `Child::kill`).
- `durable-file` boundaries: `ReplacePoint::{Written, Synced, Renamed, DirectorySynced}` (`lib.rs:179`).

## Requirements

`Step` (public, in `record/mod.rs`) names every boundary, in order:

| Step | Where | Snapshot a reader sees after a kill here |
|---|---|---|
| `Locked` | lock acquired, nothing read | old |
| `Read` | snapshot read and parsed | old |
| `Mutated` | closure returned, bytes differ | old |
| `BodyInstalled` | send only: body installed and its directory synced | old; one unreferenced body |
| `Written` | temp written | old; one temp |
| `Synced` | temp fsynced | old; one temp |
| `Renamed` | rename done | new |
| `DirectorySynced` | parent fsynced | new |
| `Collected` | dropped bodies deleted (and, in a send, the sweep done) | new |

`Step`, `hold_observed` and `send_observed` exist since phases 2-3; this phase adds only the kill rows. An observer error leaves the same on-disk state as a kill at that step (same table): before `Renamed` it is `Err(RecordError::Observer(step))`, from `Renamed` on it is `Ok(Held { wrote: true, warning })` (the commit-point rule, phase 2 test 7d).

## Tests first — `tests/record_crash.rs` (owning file for crash safety and for "a dying holder releases the lock")

One parameterised test per hold kind, each row a separate `#[test]` generated by a small macro so a failure names its step:

| # | Test name pattern | Child does | Parent asserts after SIGKILL |
|---|---|---|---|
| 1 | `a send killed at <step> leaves a whole snapshot` (9 steps) | `send_observed`; at `<step>` the observer installs a ready file and blocks reading a pipe that never gets data | (a) `LockScope::seeded(vec![])?.acquire("mailbox", &paths.lock_params(), Wait::Try)` succeeds immediately (the dying holder released it); (b) for steps before `Renamed` the snapshot bytes equal the bytes before the child started; from `Renamed` on the snapshot parses, differs from the old bytes, and holds exactly the change the child made (one more header to the named recipient for a send, the new binding for a registration). The parent cannot recompute the new state byte for byte because ids come from `OsIds`; it never tries <!-- Updated: Red Team -->; (c) every header with `body_kept` has a readable body; (d) the next `send` leaves no orphan temp or body (directory listing equals the known set plus referenced bodies) |
| 2 | `a registering hold killed after its closure leaves a whole snapshot` (one wiring case, `Mutated`; the other steps share row 1's write path) <!-- Updated: Red Team --> | `hold_observed` running `register` | (a), (b) |
| 3 | `an observer error at <step> leaves the same state as a kill there` | in-process `send_observed` whose observer returns `Err` at `<step>` | same (b)-(d) as row 1; the result is `Err(observer)` before `Renamed` and `Ok(Held { wrote: true, .. })` from `Renamed` on |

Notes for the implementer:

- The child is the test binary itself, re-executed with `--exact child_entry` and the role, the `.fgos` path and the step in its environment (the precedent's pattern). The role variable is read only by the `child_entry` test function in the test file, never by the library: no test switch in production code.
- Ready files and pipes live in a scratch directory beside the temporary `.fgos`, never inside the record directory (the sweep would delete them, and (d) compares that directory's listing) <!-- Updated: Red Team -->.
- Every test file that spawns children declares its own `#[test] fn child_entry()` that hands the role to `tests/common/record.rs`; the runner re-executes `std::env::current_exe()`, which is that file's own test binary <!-- Updated: Red Team -->.
- The parent waits for the ready file with a deadline and fails on child exit; it never sleeps to synchronise. Kill with `Child::kill` (SIGKILL on Unix), then `wait`.
- The test is `#[cfg(unix)]`, like the precedent.

2. Expand to every step and rows 2-3. Fix any step that leaves a state outside the table (expected: none, given phase 3's order).

## Done when

Every row is green on a fresh main merge, three runs in a row (`cargo test -p fgos-mailbox --test record_crash` x3) with no flake.

## Risk and rollback

- A flake means a synchronisation bug in the test, not a reason to retry: fix the handshake.
- Power loss is out of scope; the test names say "process-crash", never "durable".

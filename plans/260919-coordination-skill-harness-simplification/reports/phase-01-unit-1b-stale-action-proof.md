- Outcome: `passed` (Repaired & Fully Verified)

## 1. Executive Summary

Unit 1B proves that the `actionKey` generated by `coordination-actions.v1` is an atomic precondition over the session's exact state, and never an unverified display token. A shared atomic seam (`executeUnderActionPrecondition` in `src/runner/coordination/action-precondition.mjs`) executes under the existing `withSessionLock` file lock:
1. Acquires the coordination session file lock (`.fgos/coordination/sessions/<id>.lock`).
2. Loads the session manifest and event log freshly under the lock.
3. Enforces mandatory driver authority against `manifest.provenanceRoot.writerId`.
4. Handles inactive sessions: reconstructs idempotent close from the authoritative terminal event log or rejects stale action keys.
5. Projects legal actions using `projectCoordinationActions` directly under the lock.
6. If the action key is currently legal: validates required inputs and protocol-declared allowed values, then executes `mutationFn`.
7. If the action key is no longer currently legal: reconstructs prior execution strictly from authoritative session records (`events.jsonl`, `assignment.json`):
   - Same action key + identical normalized input payload -> returns cached idempotent result without re-executing `mutationFn`.
   - Same action key + conflicting input payload -> throws `CoordinationError('payload-conflict')`.
   - Otherwise -> throws `CoordinationError('stale-action-key')`.

### Critical Invariants Enforced
- **Zero TOCTOU race window**: State re-projection, precondition verification, and mutation callback execution all occur inside the critical section of `withSessionLock`.
- **Zero `.action-keys.json` sidecar files**: Completely eliminated `.action-keys.json`. Idempotency is reconstructed strictly from the authoritative event log and assignment records, satisfying Platform Law L3 and resolving audit findings F-05 and G5.
- **Mandatory Driver Authority**: Every mutation requires valid driver authorization matching `manifest.provenanceRoot.writerId`. Any missing or mismatched identity is refused with `unauthorized` before any mutation is invoked.
- **Pure log-backed idempotency**: Tested with failure injection (throwing mutations do not corrupt log or record success, lock is released cleanly, subsequent caller succeeds).

## 3. Findings Resolution from Phase 2 Readiness Audit

| Finding | Severity | Description | Resolution in Unit 1B |
|---|---|---|---|
| **F-03** | HIGH | Driver authority was optional when identity was omitted. | Enforced mandatory driver verification against `manifest.provenanceRoot.writerId` in `executeUnderActionPrecondition` and `assertActionPrecondition`. Missing or mismatched identity is rejected with `unauthorized`. Retrying closed sessions with mismatched driver throws `payload-conflict`. |
| **F-04** | CRITICAL | Stale-action atomicity and TOCTOU races between validation and mutation. | `executeUnderActionPrecondition` executes completely inside `withSessionLock`, loading fresh manifest/events, projecting actions, validating preconditions, and running `mutationFn`. Proved with two real OS processes racing concurrently on the same initial action key: exactly one succeeds, second fails with `stale-action-key`. |
| **F-05** | CRITICAL | `.action-keys.json` sidecar was a second truth store and created crash/durability split. | Completely removed `.action-keys.json` sidecar. Idempotency is reconstructed from authoritative records (`events.jsonl` and `assignment.json`). Crash and failure injection tests verify zero sidecars created and pure authoritative recovery. |

## 4. Production Door Integration

- **`closeCoordinationUseCase`**:
  - Keyed requests (`requestObject.actionKey` present): routed directly through `executeUnderActionPrecondition` under `withSessionLock`, calling `closeSessionByQuorumLocked`.
  - Unkeyed requests (`actionKey` omitted): maintains backward-compatibility path for existing CLI and test callers.
  - Repeated keyed close invocation with identical payload returns `{ idempotent: true, cached: true, closed: true }`.
  - Repeated close invocation with conflicting driver identity throws `payload-conflict`.

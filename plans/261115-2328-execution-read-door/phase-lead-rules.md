  `fgos worktree remove <path> --delivered-to origin/execution-read-door/integration --discard-ignored </dev/null`.

## Proof rules

- Red first: commit and push the failing test before the fix.
- One owning proof per behaviour (design principle 8). A behaviour that moves to Rust gets its owning proof in the
  Rust crate (golden vectors under `packages/execution/contracts/`); a boundary above it keeps at most one wiring
  proof. A retired Node test names its new owner in the commit message and in your report's table
  "retired test -> owner now". Deleting a mechanism retires its tests in the same change.
- No env switch, flag or test-only branch to make a test pass.
- Twins: where this plan declares a Node twin (D7), the Node twin reads the same vector file as the Rust owner; never
  copy vectors into a Node test.

## Tests and gates

- Node tests only through `node scripts/run-tests.mjs <file.test.mjs> ...` (logs to `/dev/shm`, one file per run). Run
  your phase's gate list plus every test that imports or reads a file you change (`rg -l "<basename>|<symbol>" test`).
- Ask the big lead before a full `npm test` or `cargo test --workspace`; at most one full `npm test` on the machine; a
  COOK `HOLD suite` board line means no test process at all. Never SIGKILL a gate; no focused run in a worktree while
  its full suite runs. Quiet window rule of the day applies when the board says so.
- Every phase gate includes `test/setup/git-mutation-census.test.mjs`, `test/architecture.test.mjs`,
  `test/scripts/doc-health.test.mjs`, `test/scripts/check-decision-citation-drift.test.mjs`, and
  `node scripts/git-one-door-scan.mjs --root .` (count not above the base).
- Rust touched: `cargo fmt --all --check`; `cargo clippy -p <crates> --all-targets -- -D warnings`;
  `cargo test -p <crates>`; `cargo check -p <crates> --target x86_64-pc-windows-msvc` and
  `--target aarch64-apple-darwin` (macOS is supported).

- `packages/git/contracts/mutation-census.v1.json`: every commit that touches a judged file stages a census
  regenerated by `node scripts/git-one-door-scan.mjs --root . --write-census` on that exact tree. On rebase: drop your

  `scripts/test-proof-inventory.mjs --write-baseline` on its own tree; on rebase drop the hunk and regenerate. MAIL's CI

  `apps/fgos/tests/cli_tests.rs` cases): the second lander rebases; never resolve by dropping the other phase's line.

  only phase 12 adds or edits `doors` rows. Never edit `CHANGELOG.md`, `docs/backlog.md`, `Cargo.lock` (04 owns it) or
  another phase's files.

## Hygiene

- No plan ids, phase numbers or finding codes in code, comments, test names or commit messages. Conventional commits
  ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Before each commit: `/usr/bin/git diff --cached --stat`; explain any deletion you did not plan. Stage explicit
  paths. Never `git stash`.
- Push the phase branch at least every 30 minutes (`/usr/bin/git push origin HEAD:refs/heads/execution-read-door/pNN`).
  Never push to `main`. Never force-push a shared branch.
- Landing on the integration branch: only after OPC (`forgent-5f`) answers MERGE on your pushed head. A MERGE carries
  over to a rebased head only when `git range-diff` shows the regenerated census or suite line as the only change.
  One board line per landing or blocker in `plans/261017-1313-fgos-platform-program-board/log.md` (insert before the
  first `\n- 20`, stamp with `date '+%Y-%m-%d %H:%M'`, prefix `S5`).
- Report path: `fgos convention path --kind report --type phase --slug erd-pNN-<slug> --plan 261115-2328-execution-read-door --json </dev/null`
  (run from the main checkout). End with `Status / Summary / Concerns`, the "retired test -> owner now" table, and a
  proposed `## [Unreleased]` line if a user sees the change (phase 12 writes CHANGELOG).
- Ids (decision numbers, backlog rows) only from `fgos identity mint <kind>`.

# Phase 04: the `fgos-execution` crate and the executor model in Rust

Start after: 01 landed. Wave 2. Rules: [phase-lead-rules.md](phase-lead-rules.md). Facts: F1, F3, F8.
Worktree `erd-p04`, report slug `erd-p04-executor-model`. Effort: 2.5d.

## Context

D1: Execution's read door gets one crate, `packages/execution/rust` (`fgos-execution`), pure (no I/O, clock,
environment): the machine facts it needs come through one port trait that the host implements (phase 09). Seat
Binding stays the ranking authority; this crate derives what an executor is and composes the bind (06), the decide
(07), the agents listing (08) and the doctor judges (11). This phase creates the crate and the executor model, proven
by `executor-model.v1.json` (01).

## Requirements

1. `packages/execution/rust/Cargo.toml`: name `fgos-execution`; dependencies `serde`, `serde_json`
   (`preserve_order` not needed: answers are maps keyed by id, compared as values), `fgos-seat-binding`, `fgos-yaml-doc`
   (both used by 06 and 08; declared here so `Cargo.lock` changes once). Root `Cargo.toml` workspace member. `Cargo.lock`
   regenerated by cargo, never by hand.
2. `src/lib.rs`: crate doc stating the boundary (what it decides, what Seat Binding and Dispatch decide), `pub mod
   executor_model; pub mod ports;`.
3. `src/ports.rs`: `trait Machine { fn on_path(&self, program: &str) -> bool; fn posture_backend(&self, id: &str) ->
   Option<Backend>; fn herdr_present(&self) -> bool; }` (exactly what the derived facts need; 07 and 08 add their own
   reads through their own small traits, never through a grab-bag).
4. `src/executor_model.rs`: typed executor entry deserialized from the runner section (`executors`, the legacy
   `executor` default command and its merge `with_default_executor`, as `dispatch/config.mjs:46 withDefaultExecutor`,
   which decide applies (`decide.mjs:172`) and explain does not (`bin/fgos.mjs:2447`)); derived facts with one function each: `family`, `mechanism(has_live_task_access)`,
   `credential_store_cli`, `effort_levels`, `default_invocation`/`carries_posture`, `disallowed(governance)`,
   `missing_clis`, `tool_for_entries`. Semantics exactly as the contract (01), which records today's behaviour; a vector marked `knownDefect` keeps
   today's behaviour in Rust too (a port changes no behaviour, RUL104) and becomes a backlog row proposed in 12.
5. `tests/golden_executor_model.rs` reads `packages/execution/contracts/executor-model.v1.json` and runs every vector
   (with a fake `Machine`).

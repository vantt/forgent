## Root cause (confirmed by source read, not accepted from the report)

`createSessionAssignment`'s self-heal branch — entered when a claim record and
`assignment.json` exist but `manifest.assignmentRefs` lacks the id — called
`completeAssignmentRegistration({..., authorizationProvenance})`, which appends
the consuming `assignment-created` event, with no consumption check on that
path. The check lived only in the branch below it, which the self-heal path
returns before ever reaching. The pre-lock gate in `dispatchDeclaredOperation`
cannot compensate: it reads through an UNLOCKED `replaySession`, which is
precisely why the lock-held check exists.

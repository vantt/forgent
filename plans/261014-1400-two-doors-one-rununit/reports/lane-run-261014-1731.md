# Lane run (phase 04): soft `bind()` prefer, `fgos run "<prompt>"`, `--effort`

Branch `feat/rununit-run`, rebased on main `1e8b5a048` (P01 + the resume-lock fix). 6 commits, no `.fgos/**`.

## Motive

- **Proven.** Before this lane `fgos run` needed a unit file. A unit's `prefer` and `persona` were validated by P01 but `bind()` ignored them, so a caller could not say "this provider if it can, else any" (RUL77 lists this as "Not built: a soft provider hint").
- **Proven by test.** On the old `bind.mjs`, the two failover tests fail. The unit prefer was ignored and the capability pool ran first.

## Design

- **`bind()` without an override executor.**
  - The pool is `unit.prefer`, then `capability.prefer`.
  - Each candidate carries its own `source` (`unit-prefer` or `capability:<key>`). Both `provenance.executor.source` and `provenance.invocation.source` come from the chosen candidate. The inline fallback carries `session-lead-inline`, as before.
  - Duplicates are dropped and the order is kept. A unit entry `{executor, invocation}` removes the identical capability entry. A **bare** unit id removes every capability entry of that executor, so failover never walks back onto the executor that just hit its limit (finding 1 from review).
  - A unit-prefer executor that is not registered is skipped with `refusalReason: 'unknown-executor'`. It does not throw.
  - Every existing filter applies unchanged: governance, family-excluded, independence, posture and blind. A human-override independence exception needs `cand.override`, which a unit candidate never has.
  - `--override` with `executor` still pins.
- **Persona.** The order is override > `unit.persona` (source `unit`) > `lockedPersona` > capability. When `lockedPersona` disagrees with `unit.persona`, bind refuses with `locked-persona`.
- **Mutating gate (RUL73.4).**
  - No code change was needed. `assignment-runner.mjs:447` recomputes `bind()` from `unitRecord.unit` and `configSnapshot.runner`. The unit there carries `prefer`, so the gate sees the same pool and index basis as `runRole`.
  - Proven by test: a writing unit with prefer passes, both directly and after walking out of a provider-limited preferred executor.
- **`fgos run "<prompt>"`** is built in `bin/fgos.mjs` by `adhocUnitFromPrompt`. Every check runs before `runUnit`, so a bad flag leaves no unit run behind.
  - The id is `adhoc-<ascii slug ≤40>-<4 hex>`. The slug uses NFKD, drops diacritics, maps đ→d, and falls back to `task`.
  - `--provider a,b` becomes `unit.prefer`. Each id must be a registered executor of kind `agent`; otherwise the error lists the valid ids.
  - `--persona` is resolved through `resolveAgentDefinition` (the same lookup `--seats` uses).
  - `--writes` needs a linked worktree, either from `--worktree` or from the cwd. Otherwise the error says to run `git worktree add <path>` and pass `--worktree`. The command never creates one.
  - Without `--writes` the unit is read-only (`writes: []`). `--capability` defaults to `execute`. `--rigor` goes into the unit and is validated by `validateUnit` before the unit dir exists.
  - `--effort` follows lane B's path unchanged.
  - Refused rather than silently dropped: a prompt together with `--unit` or `--resume`; any prompt-only flag without a prompt; an unquoted multi-word prompt; a bare `--writes`.
- **Help:** `src/cli/command-registry.mjs`: the invoke line, a `prompt` positional, 6 properties and 2 examples. No new verb.

## Independent review + red-team

Done by the `code-reviewer` agent; `dispatch decide --for code-review` returned in-process. Its verdict was "changes requested" with these findings:

1. **HIGH: a bare `--provider` id was not deduplicated against capability entries that pin an invocation.** Failover could re-run the limited executor and rotate through its accounts again. **Fixed** in `99fe84604`, with a test.
2. **MEDIUM: `unit.persona` and `unit.prefer` reach every role.** `roleUnit()` spreads the unit, so the reviewer, panelists and synthesizer all get them. **Not changed.** This matches the existing workflow unit persona, which is an override scoped to `{unit}`, unscoped by role, so it also reaches every seat. Prefer stays subject to independence and spread. It needs a Lead/owner call (see Open).
3. **MEDIUM: one-liner flags were silently dropped with `--unit`/`--resume`.** **Fixed** in `3d6d5896b`.
4. **LOW-MEDIUM: an unquoted prompt was cut to its first word.** **Fixed** in `3d6d5896b`.
5. **LOW: a governance-blocked `--provider` falls to the capability pool without a warning.** Only `provenance.executor.source` shows it. Not fixed; see Open.
6. **LOW: a bare `--writes` gave a read-only unit.** **Fixed** in `3d6d5896b`.
7. **LOW: `lockedPersona` has no production caller.** Its refusal is only unit-tested. Noted.

Red-team floor:

1. **Can prefer bypass a filter?** Held. Governance, `disallowedExecutors`, family-excluded, independence, posture (including a bad invocation id) and blind all apply to unit candidates. Probed by script and covered by tests.
2. **Resume after the config changes?** Held and consistent. Resume reuses the recorded binding (`run.mjs` runRole `recorded`) and the frozen `configSnapshot`. The gate recomputes from the same snapshot, and live config is never re-read. An executor removed or blocked after the run started is therefore not honoured on resume; that is snapshot-by-design and predates this lane.
3. **Prefer against blind panel, `--seats` and spread?** Held. Under `preferIndependentOf`, family use ranks first and pool order only breaks ties, so prefer cannot collapse the spread. `--seats` personas are role-scoped overrides and beat `unit.persona`.
4. **Special characters and very long prompts?** Held. Vietnamese, `../../etc/passwd`, `$(rm -rf /)`, CJK-only (→ `task`) and 500 characters all give `[a-z0-9-]{1,40}`. The slug is stable; the hex suffix is random by spec.
5. **Missing `--persona`?** Held. The error comes before any unit-run dir (asserted). A persona inside a `--unit` file is still not checked up front; that predates this lane.
6. **Extra hit: `--writes` with `--worktree <main checkout>`** was only refused by the mutating gate, after the unit run existed. **Fixed** in `8e712bfcf`: it is now refused up front.

## Spec delta (for L7 / 07a, decision 0061)

- `docs/specs/runner.md`, `bind()` table: without an override executor, the pool is `unit.prefer` then `capability.prefer`.
  - Each candidate carries its own source (`unit-prefer` / `capability:<key>`), and provenance takes the chosen candidate's source.
  - Duplicates are dropped by executor+invocation; a bare unit id covers every capability entry of that executor.
  - An unregistered unit-prefer id is skipped with `unknown-executor`.
  - Every filter applies to every candidate. Spread ranks before pool order.
  - `--override` executor still pins.
- Persona order: override > `unit.persona` (`unit`) > locked > capability. A conflict between locked and unit refuses with `locked-persona`.
- RUL77's "Not built: a soft provider hint" is now built as `unit.prefer` / `fgos run --provider`. It is not built on `dispatch decide`.
- `fgos run "<prompt>"`: the one-liner contract (id shape, flags, the read-only default, the linked-worktree rule, refusals before any unit run, capability default `execute`).

## CHANGELOG delta (`## [Unreleased]`)

- `fgos run "<prompt>"` runs a one-line task as a Unit. The flags are `--provider` (soft preference), `--persona`, `--writes` (needs a linked worktree), `--capability` (default `execute`), `--rigor`, `--effort` and `--override`. Without `--writes` the Unit is read-only. A wrong provider, a wrong persona, or writes from the main checkout fail before anything runs.
- A Unit's `prefer` now goes ahead of the capability's pool, passing the same filters and failing over into the pool. A Unit's `persona` binds unless an override names one. Binding provenance records `unit-prefer` / `unit` as the source.

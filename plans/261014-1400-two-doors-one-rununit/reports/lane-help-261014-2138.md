## CHANGELOG delta (đề xuất, `## [Unreleased]`)

- `fgos --help --json` and `fgos <verb> --help --json` now work through the installed `fgos` host in any project: `--help`/`-h` are routed to the manifest, a Rust-native verb (`version`, `metrics`, `friction`, `convention`, `gate-bypass`) given `--help` prints its manifest entry instead of running, and help never runs a verb.
- `fgos <verb> <sub> --help --json` narrows to one sub-verb; verbs with sub-verbs (`dispatch`, `workflow`, `merge`, `session`, `gateway`, `goal`, `tool`, `agents`, `metrics`, `friction`, `convention`) list each sub-verb's flags, required fields and examples under `subcommands`. Manifest `schema_version` is now `3.0`: those verbs' flags moved from the verb-level `parameters` into `subcommands`.
- `fgos --help` refuses an unknown verb, sub-verb or option with exit 4 instead of ignoring it (it still accepts `--dir`, which the `fgos` shell function appends).
- `fgos run` / `fgos workflow` descriptions say which door to use: one task → `fgos run "<prompt>"`; planned work → `fgos workflow start <preset>|--units <file>`.
- Fixed manifest entries that did not match the CLI: `merge next` forwarding flags, `workflow start --stance-options`, `workflow operations --step` (was `--stage`), `tool --config`, `tool check --name` (was positional), `dispatch decide --assignment`, `run record --result`.

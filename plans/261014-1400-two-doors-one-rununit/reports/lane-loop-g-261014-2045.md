## Thiết kế (đã làm)

### `spawnWorker` (`src/runner/work-dispatch.mjs`)

`spawnWorker(work, cfg, cwd, opts)` giữ tên. Hàm dựng Unit bằng `workUnitFor(work, {cfg, stage, feedback, worktree: cwd})`, rồi gọi `runUnit({unitData, worktree: cwd, cwd, repoRoot, session: {headless: true, herdrPresent: false}, onUnitRunCreated})`.

- `herdrPresent: false`: theo thiết kế mục 9. Loop chạy trong pane herdr vẫn dùng transport cli.
- Hàm giờ là `async`. Lỗi cấu hình (`RunnerConfigError` từ `workUnitFor`) thành promise bị reject trước khi tạo Unit run. Loop vẫn `await` nên kết quả như cũ.
- Đã gỡ: `executeThroughConfinement`, `buildConfinementRequest`, `openRunnerRun`, `watchWritesOutsideWorkspace`, cách tự tính tier→model và `onChunk`. Các phần này giờ do bind/`executeAssignment` lo.

Bảng ánh xạ trường (loop đọc → nguồn):

| Trường | Nguồn |
|---|---|
| `status` | `runResult.runtime.exitCode` |
| `signal` | `runResult.runtime.signal` (thường không có) |
| `executorId` | `binding.executor`: executor **thật** bind đã chọn, không còn là tên job của bước |
| `provider`, `command`, `governance` | `resolveExecutorConfig(configSnapshot của unit.json, tier, executor, …, invocation)`, chỉ để audit, không resolve lại cho lượt chạy |
| `model`, `tier` | `binding.model` / `binding.tier` |
| `stdout` | transport cli: file `runtime.stdoutLog`. herdr: nguồn không rỗng đầu tiên trong report đã settle → stdout.log → `agentClaim.summary` (không ghép, tránh đọc fence hai lần) |
| `stderr` | file `runtime.stderrLog` |
| `attestation` | `{confinement, adapter, runId}` của RunResult |
| `baseCommit`, `headRef` | `git rev-parse HEAD` / nhánh của `cwd` trước lượt chạy |
| `templateName`, `templateHash` | `selectTemplate` như cũ |
| `unitRunId` (mới) | `runUnit().unitRunId` |
| `commit` (mới) | `runner` (Unit run commit), `none` (HEAD không đổi), `self` (HEAD đổi mà runner không commit; dưới bwrap thực tế không xảy ra). `runnerCommit` mang bản ghi commit của Unit run |
| `warnings` | `runResult.warnings` (ví dụ stray-write của lane D); loop log từng dòng |

Ánh xạ outcome → `errorClass` (đã kiểm từng nhánh bằng probe rồi test):

| runUnit | spawnWorker |
|---|---|
| `pass` | trả về, kèm `commit` |
| commit của Unit run `failed` | `DispatchError('worktree-fail')` (yêu cầu 3) |
| `policy-refusal` / `foreign-staged-index` (preflight trước spawn) | `worktree-fail` |
| `policy-refusal` khác **trước khi spawn** (không ứng viên, posture không áp được, governance chặn hết) | `no-executor`: class **mới**, `park`; thông báo nêu `runner.capabilities["<cap>"].prefer` cần khai |
| `provider-limit` (hết ứng viên sau khi đã xoay account và đi hết pool) | `provider-limit`: class **mới**, `park` |
| `execution-timeout` (cứng hoặc idle) | `worker-timeout` |
| exit 127 / `supervisor-spawn-fail` / không có RunResult | `worker-spawn-fail` |
| round đã spawn mà không `pass` (`execution-failure`/`findings`/`blocked`/claim bị từ chối) **và để lại file chưa commit** | `worker-failed`: class **mới**, retry ×2 rồi park; file chưa commit không bao giờ tới goal-check |
| round đã spawn mà không `pass`, worktree **sạch** | trả về `status`, `commit: 'none'`; goal-check quyết trên nhánh như hiện có (D3) |

Mọi `DispatchError` mang theo các trường ở trên (`unitRunId`, `stdout`, `stderr`, …), để loop log được.

### Loop (`src/runner/loop.mjs`)

- Đã xoá `commitWorkerChanges`, `workerResultSummary` và `RESULT_FENCE`. `commit` lấy từ `worker.commit` (yêu cầu 3).
- Event `executor.dispatch` vẫn do loop ghi, thêm `unitRunId` (yêu cầu 4).
- Không còn kênh stream: `onUnitRunCreated` ghi ngay vào `.fgos/logs/<id>.log` một dòng `worker running as unit run <id>; its output is in .fgos/assignments/<id>/producer/*/runs/*/stdout.log`. Block cuối vẫn chứa toàn bộ stdout.
- Sweep discovery dùng cùng `spawnWorker`; fence verdict/discovered đọc từ `worker.stdout`.
- `FRICTION_LAYER['provider-limit'] = 'environment'`.
- **Sửa lỗi có sẵn** trong `startupReap`: một nhánh `fgw/` 0 commit mà vẫn đang được checkout ở một worktree thì được giữ lại kèm log, không còn `git branch -D` rồi sập `--once`. Lỗi này có từ trước (runner bị kill trước khi worker commit), nhưng giờ thành đường bình thường, vì runner chỉ commit sau khi round settle: worktree của lượt bị kill còn file chưa commit. `reclaimOrphanedCheckout` cố ý không xoá checkout bẩn, nên giữ nhánh là đúng.
- Đã gỡ re-export `fanoutBatchExecutorCli` ở cuối `loop.mjs`: không ai dùng.

### Fanout (`src/runner/fanout-batch.mjs`)

- Phần ruột: `pick` → `runUnit({unitData: workUnitFor(item, {cfg, worktree}), …})` → `outcome` pass thì `fgos return` (không truyền `--worker-verified-sha`), khác pass thì `return --to blocked` như nhánh lỗi cũ.
- `fired[i] = {id, unitRunId, outcome, commit}`, thêm `errorClass`/`error` khi item bị trả về blocked.
- Lối vào `node` của 06 giữ nguyên.

### `prefer` có cần `{executor, invocation}` không: **không**

Hôm nay `spawnWorker` gọi `resolveExecutorCommand` không có `invocationId`, tức luôn dùng invocation mặc định của executor. `bind` với prefer trần X loại các mục `{X, invocation}` của pool capability (`bind.mjs:171-174`), rồi dùng invocation mặc định của X. Kết quả giữ đúng hành vi hôm nay. Tinh thần `b78c0019c` (invocation Unit khai thì giữ dưới herdr) không bị đụng: `workUnitFor` không khai invocation, và loop chạy với `herdrPresent: false`.

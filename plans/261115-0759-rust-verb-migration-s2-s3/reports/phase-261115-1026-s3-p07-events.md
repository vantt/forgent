## Settled review notes
1. **Fault class and message.** Node: a verb-stage error carries no fault class of its own, so a failed child was always recorded `event-store-child` with the bare message and `fgos: invocation fault recorded to <path>` was printed. Kept: host records `event-store-child` always (doors `leave`), with the bare message (`CategorisedRefusal`, no `provider failed:` prefix), stderr `fgos: <message>`. Not kept: the `recorded to <path>` line (host prints none for a verb refusal; the child's stderr goes nowhere). Pinned in parity: child-shape refusals compare stderr with that one line dropped, and the fault records (class, message, verb, sub) must be equal.
2. **`DispatchError` exit 1.** Not needed: only dispatch verbs raise it (`src/run-supervisor/dispatch-error.mjs`); no `events` code path does; an `events` failure exits as the table's `unexpected` (1) or 4 for validation.
3. **`parseReleaseEntry` hostBin check:** not done (`harness.mjs` is outside this phase's file list).

## Review round (OPC)
- **Seal child with no host (B1).** `handSealsToChild` returns its first spawn error and the lifecycle records it as `event-store-seal-child: <error>` (the command is not failed). `maintainEventStore` and `runWithEventStoreLifecycle` take `childHost(root)` (default `resolveHostBin`): the native door and the host lookup both read `FGOS_HOST_BIN`, so a test cannot lose only the child's host through the environment. Proofs in `triggers.test.mjs`: the publish child's `event-store-sync-child: host-unavailable`, and the seal child's record.
- **`events seal --stream x` with no `--dir` on a removed state root (B2).** Not reproduced: with `project`, `demo` and a repository-less directory as the fixture, the base release answers `{skipped}`, exit 0, and leaves the root absent, as the host does (parity cases `seal-state-root-gone-no-dir`, `seal-unlisted-stream-state-root-gone-no-dir`, `seal-state-root-gone-outside-a-repository`, `sync-opportunistic-state-root-gone-no-dir` are equal on both entries, root absent). So it is not listed as an accepted change; the phase 00 facts case that recreated the root may have run in a directory the root door resolved differently. Say so if you have the exact call.
- **Committed runner.** `test/rust-host/verb-parity.test.mjs` (table list `events`; other phases add their name) calls the table's `runPreparedCase(entryA, entryB, testCase)`; `FGOS_TEST_PARITY_BASE` names the staged base. `events.cases.mjs` runs each entry on its own repository root with its own `.fgos` at the same path and fails a case when any `.fgos` exists above the fixture tree before or after.

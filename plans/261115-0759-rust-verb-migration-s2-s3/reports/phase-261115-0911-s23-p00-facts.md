### (a) A Node `events` child recreating a removed state root (00 F15): DISPROVED for today's children, mechanism REAL

The mechanism is real; the two children Node spawns never reach it, because both pass `--dir`.

Mechanism, door only (script `resolveInvocationRoot({cwd, dir, policy:'caller-tree'})`, state root removed first, nothing else run):

```text
--- door without --dir                       --- door with --dir <repo>
before: state root exists = false            before: state root exists = false
answer: {root:<repo>, fgosDir:<repo>/.fgos,  answer: {root:<repo>, ... found:true}
         found:true}                         after:  state root exists = false
after:  state root exists = true
        (created: drwx------ git-empty-hooks)
```

Cause: `resolve_invocation_root_with` returns at `packages/git/rust/src/invocation_root.rs:159` for a `--dir` request under
`caller-tree` (the Git read is skipped, `invocation_root.rs:138-159`). Without `--dir` it reads facts
(`read_repo_facts`, 98-108 -> `GitDriver::topology_at` `driver.rs:359-365` -> `GitDriver::new` 266-273) and the driver creates the
absent root. `new_if_root_exists` (277-283) is unused by that read.

The children, exact argv from `src/event-store/maintenance.mjs:11` and `:52` (cwd = project root), state root removed first:

```text

$ rm -rf $STATE; node bin/fgos.mjs events sync --opportunistic --dir $REPO   -> {"data":{"skipped":"state root gone"}}  exit 0; $STATE absent
```

returns `{stateRootGone:true}`. Host `invocation_doors.rs:101-110` also builds its `events sync` child with `--dir`.

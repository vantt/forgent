## Requirements

- **One infra module under `src/git/`** (name from `fgos convention name`, e.g. `src/git/status.mjs`; layer `infra` in `docs/architecture-manifest.json`) owning:
  - `readGitStatus(cwd, { loaderOptions, portOptions })` → `{ repository: { notARepository, commonDir, layout }, journal: { initialized, complete, pendingCount, errors, retention }, pendingOperations: [{ operationId, kind, writer }], retainedLand: { candidates, complete }, worktrees: { issues, pendingOperations }, nativeLocks, mergeInProgress: <sha|null> }`. Read-only; built from the moved `gitFacts` inputs, `recovery.listPending()`, `listRetainedLand()`, and the moved MERGE_HEAD read. Each part that fails is reported in place (`{ error: <cause> }`), never hides the others (same rule as `retainedLandWarning`'s catch).
  - `recoverGitOperations(cwd, { loaderOptions, portOptions })` = the moved body of `fixGitOperationRecovery`, returning `{ recovered: [ids], kept: [{ operationId, cause, writer }], message }`. Worktree findings and native locks are never repaired (Git spec §11, "never removed by fgOS"); a merge in progress is reported with `fgos main-checkout-reset --sha <sha> --confirm` as the next step, never acted on.
- **`fixGitOperationRecovery` becomes a one-line call** to `recoverGitOperations` (same message), so doctor `--fix` and the door run one body until P06 removes the fix. `retainedLandWarning` reads through the module. No second copy of any Git read.

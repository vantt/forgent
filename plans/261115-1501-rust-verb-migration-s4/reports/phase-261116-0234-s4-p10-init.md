# Phase report: `init` native (Work store through the bridge)

Branch `rust-verb-migration-program/s4-p10`, rebased on `origin/rust-verb-migration-program/s4-p04` `e71f9bbf7` (drop p04's commits when p04 lands on s4).

## What changed

- `apps/fgos/src/wiring/init.rs`: `fgos init` as a composition over a `Steps` port, in Node's order: machine id (`fgos-identity` `mint_here`), legacy config settle (config door check, `copy-to-destination` fix, then `provider::answer` for `config migrate`, the same use case the host verb runs), Event Store directories (the doctor's setup context, then `fgos_event_store::locks::prepare_directories`), Work store (bridge, Linux only), coexistence (`fgos-distribution`), header-only config files (`fgos_config::write::init`), HEAD probe and Git recovery (`fgos-git`). Only the first three refuse. Data keys and their order are Node's.
- Node rows bridge: second request `work-store-init` (`doctor-bridge.mjs`, `doctor-bridge.v1.json`, `bridge.rs` `work_store_init`, own 600 s deadline). A refusal line carries an optional `category`, which becomes the exit status.
- Deleted: `bin/fgos.mjs` arm, `src/verbs/state/{init,settle-legacy-config}.mjs`, `src/install/coexist.mjs`, `src/git/status.mjs`, `src/setup/event-store-fixes.mjs`, `mintMachineId` (identity-mint), the matching tests and baseline rows.
- Doors: new `init steps` (allowed `init.rs`) and `retired Node init code` rows with seeded negatives in `architecture.test.mjs`; `coexistence manifest` row lost its debt; `compose Git status and recovery` lost the `status.mjs` entry and its `retiredBy`; dead `src/install/` tier row removed.
- Registry/routes: `native: true`, annotation, `CATALOG` entry (`init.run`, count 35), generated routes regenerated, census regenerated.
- Retired with `init` (L10): the addon's `config.init` entry, the facade's `initConfigFile` and their door and facade test cases; `init.rs` is the one adapter over `fgos_config::write::init` (create-only behaviour: `golden_init.rs`). The lock-directory glue is one helper (`doctor/event_store.rs` `prepare_store_directories`) used by the fix and by init; the recovery writer closure is one (`git_incidents::own_writer`); the bridge module loads the rows' bodies only for check and fix requests.
- Tests that spawned the Node entry for `init` (20 files) now go through `test/helpers/cli-entry.mjs` (`spawnFgos`), which picks the entry from the route table; the cli harness uses it too.

## Accepted changes (for the owner / CHANGELOG)

1. An unset `HOME` is refused up front as a precondition (exit 2, "HOME is not set ..."), before anything is written (OPC note; as in `wire-agents`).
2. Node missing at `init` is a precondition refusal (exit 2) naming Node 18. It refuses after the machine id, the legacy config settle and the lock directories; coexistence, the config files and the Git recovery do not run.
3. The fault-log text of the end trigger for a refused `--dir` that is no repository differs (host wording: `main-checkout-not-found`, `git-driver-io: ...`); normalised in the parity table.
4. `fgos init` through the npm channel's Node entry now answers the "only available in the native fgOS host" refusal (exit 4) instead of the addon refusal (tests updated).

Proposed `## [Unreleased]` line: `fgos init runs in the Rust host: the machine, config, coexistence and Git steps no longer start Node; only the Work store step does, and an unset HOME or a missing Node is refused as a missing precondition (exit 2; with Node missing, init stops after the machine id, the legacy config settle and the lock directories).`

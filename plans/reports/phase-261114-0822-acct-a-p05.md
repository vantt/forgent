## Timer environment check (D4 condition)

Run on fg-server2 under `systemd-run --user --wait --pipe` (the environment a user timer gets), no `--record`, direct leg only:

- Timer env PATH is the bare system PATH (`/usr/local/sbin:...:/snap/bin`); HOME is set; no `HERDR_*` variable exists.
- `fgos dispatch probe-account --all --leg direct` with that PATH: every login store of every account exited 127 (command not found, 0 provider spend). The CLIs (`codex`, `omp`, `pi`, `claude`) live in `~/.local/bin`, which a timer does not have.
- Result: the direct leg does NOT work from a timer unless PATH carries the CLI folders. The unit therefore has one `Environment="PATH=<home>/.local/bin:/usr/local/bin:/usr/bin:/bin"` line (launchd: `EnvironmentVariables`, plus `/opt/homebrew/bin`). PATH is the only variable written; it is on the probe env allowlist (`PROBE_ENV_ALLOW`), never a secret; deterministic from the home dir so doctor does not see a false stale.
- Harness leg: not run (opens panes, spends). Premise for D4(b) holds on the evidence available: no herdr session variables in a timer env, so the timer stays on `--leg direct`; the flag stays.
- Side note: a store that exits 127 yields verdict `mixed` and, with `--record`, only a `probe` line (no quarantine, since reason is null). Harmless, but a wrong PATH is visible only as `mixed` rows with exitCode 127.

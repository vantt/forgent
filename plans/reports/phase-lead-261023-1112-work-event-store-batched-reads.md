Design in one paragraph: one `cat-file --batch -Z` process takes, per revision, the bare revision (root exists and is commit or tree: replaces `cat-file -t`) followed by `<rev>:<path>` lines. A missing or non-commit-or-tree root, a failed or oversized process, or an absent path in a promisor/alternates layout returns "re-ask singly", which reproduces the old error exactly. Follow-up once HARDEN's `layout_cause` lands: `read_paths_at` can become a one-line wrapper over `read_paths_at_many` and lose its own `-t` probe (not done here to avoid the shared hunks).

Event Store side (`packages/event-store/rust`): `walk.rs` (`walk_inner` collects a page's commits, reads them in groups of `READ_GROUP = 64`, processes in the same order; `blob` uses the many-read), `fence.rs` (`pinned_at_head` through the memo, `read_pin` split out), new `commit_memo.rs`, `legacy_import.rs` (`inventory_roots_at` through the memo, `Inventory: Clone`), `lib.rs` (module line).

Memo invalidation: the key is repository common dir + commit oid + question (+ root set for the inventory). A commit's content is immutable, so a moved HEAD (Land, checkout, claim) is simply another key and needs no invalidation; a failed read is never stored; the memo empties itself at 16 entries. Nothing is cached across processes.

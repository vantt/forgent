- Tier-cell validity (which forms a cell may take) is decided once, by the schema and `parseTierCell`; the loader's separate layer-based filter was a second authority and is gone.
- The question "which release can read this config" has no authority anywhere: a release carries no readable capability marker. It was approximated by a doctor row. If it matters again it belongs in the packaging manifest (release version and date), not in doctor.
- Runner spec carried RUL101 and RUL102 twice; one copy removed.

## Lessons

- `fgos config set` cannot target the global file for a non-`global-only` key; a guide that promises a command line for it is wrong. Check the verb's real routing before writing the guide.
- A doctor row that guards "other projects on the machine" cannot work without a project registry; ask what the row can observe before narrowing it.
- Anchors of a heading with a long gloss are fragile; keep new decision headings short and run doc-health before the first push.

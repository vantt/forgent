# HARDEN re-check, new components: YAML Document (`fgos-yaml-doc`) and Secrets (`fgos-secrets`)

Pinned tree: `/home/vantt/projects/forgent-worktrees/harden-recheck-new` at `a5358f127`. This is a read-only audit by code-reviewer on 2026-10-29 (Asia/Saigon). I did not run cargo, npm or any test. Every claim below comes from reading the code, rg, git log and git blame.

**Verdict: DRIFT (8 small, 2 large). No High.** Medium 3, Low 7.

Both crates are T0 leaves. `fgos-yaml-doc` is the one YAML authority in Rust and in Node: js-yaml is gone, no Node file imports a YAML library, and every Rust consumer links the crate. `fgos-secrets` is a T0 leaf too, but nothing in production uses it. Its spec, the config spec, the config test and the shipped config standard all disagree about its status. Most of the drift is at the Secrets edge: a dead Node `${VAR}` twin, dead `secrets.*` config keys, and a crate with no caller.

## Verified

- **Layer placement, yaml-doc.** Its only dependencies are `serde_json`, `sha2` and the vendored `saphyr-parser` (`packages/yaml-doc/rust/Cargo.toml:6-10`). It has no internal crate dependency. `fgos-host-runtime` (T0) depends on it (`packages/host-runtime/rust/Cargo.toml:15`, used at `providers/external_process/manifest.rs:176`), so it must sit at T0 or lower: a **T0 leaf**. The other consumers are `fgos-config` (`packages/config/rust/Cargo.toml:7`), the combined addon (`packages/git/node-addon/Cargo.toml:23`) and the gateway (`apps/fgos-gateway/Cargo.toml:46`, `src/mcp.rs:129`). `rg "fgos_|\.fgos|runner"` over `src` finds no knowledge of an upper layer. The crate has no `std::fs`, no process spawning and no `unsafe` (`lib.rs:20` `#![forbid(unsafe_code)]`).
- **Layer placement, secrets.** Its dependencies are `serde` and, on unix only, `libc` (`packages/secrets/rust/Cargo.toml:6-11`): a **T0 leaf**. `rg "fgos-secrets|fgos_secrets"` over `packages apps src bin scripts test` finds only the crate's own tests and one negative assertion (`packages/config/rust/tests/golden_no_echo.rs:107-113`).
- **One YAML door in Node.** `src/util/yaml.mjs:29-40` calls `nativeDoor().yaml.parse` and has no fallback. `test/architecture.test.mjs:1229-1250` forbids every other YAML import and checks that the vendored js-yaml is gone. `rg "js-yaml"` over `src bin scripts package.json` finds nothing. `package.json` has no `dependencies`.
- **One YAML door in Rust.** No manifest outside yaml-doc names `serde_yaml`, `serde_yml` or `yaml-rust`. `saphyr-parser` is reached only through `[patch.crates-io]` to the vendored copy. Its bytes are pinned by `tests/third_party_integrity.rs:86`.
- **Panic seal.** Every public fallible entry runs through `guard::guard` (`guard.rs:56-63`). The silent hook is installed once and is thread-scoped through a thread-local depth counter (`guard.rs:21-53`). The addon wraps both `yaml.parse` and the `config` namespace in that guard (`node-addon/src/marshal.rs:125-136`, `yaml.rs:68`, `config.rs:230`). No manifest sets `panic = "abort"`. Values never reach error text: `Failure` carries only rule, file, line, column and path (`marshal.rs:76-113`).
- **Limits before recursion.** `prescan::check` bounds size, UTF-8 validity and depth before the parser runs (`document.rs:117`, `prescan.rs:34-60`). The limits come from `contracts/limits.v1.json`, which is compiled in (`model.rs:129`). Node has no copy of any limit.
- **`__proto__` safety.** The addon returns JSON text, and `JSON.parse` defines own properties. Restored non-finite floats use `Object.defineProperty` (`src/native/door.mjs:79-88`). `test/util/yaml.test.mjs:19` is the one wiring proof.
- **Builds on Windows and macOS.** yaml-doc has no `cfg`. In secrets, `file_source` is `#[cfg(unix)]` (`lib.rs:9-18`), and so are its two test files (`tests/file_source.rs:1`, `tests/no_stdin.rs:3`; fixed in `d056c1575`, 10-25).
- **Secret hygiene in the secrets crate.** `SecretValue` and `RedactionSet` have no `Display`, and their `Debug` hides values (`source.rs:18-22`, `redaction.rs:15-21`). `CheckFailure` and `ResolveError` texts carry names, paths and modes only. I printed no secret value while auditing.
- **Gate 8, yaml-doc.** It owns no doctor row, which is correct. An addon that does not load surfaces through the shared door error, and `workflow-definition-files.mjs:61` names YAML parse failures through `describeYamlError`. No yaml-doc config key exists.

## Proposed additions (owner decides)

- **Fail-loud `${VAR}` through the Secrets expansion.** Problem: the remaining Node expansion turns a missing variable into `''` (`adapters.mjs:169`), so a typo becomes an empty API key and the failure surfaces later, somewhere else (secrets spec `:62`, `:280`). Evidence: N1 and N2. Benefit: the crate's `Resolver::expand` (`expand.rs:50-102`) already refuses an unresolved reference by name, so wiring it gives the crate its first consumer. Cost: a Node bridge (an addon namespace or a host verb, secrets spec Q1), which is new surface, so it needs the owner's choice. A cheaper middle path would be for `resolveExecutorEnv` to throw on a missing variable. That changes dispatch behaviour, so it is also the owner's call.

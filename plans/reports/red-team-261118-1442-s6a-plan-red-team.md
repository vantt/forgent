# Red team: S6a plan (261118-1341-s6a-execution-tier-rust)

Read on `b5b237534` (worktree of origin/main, 2026-11-18). Scope: plan.md, phase-00..22, phase-lead-rules.md, facts
report, DISCUSSION D1-D5 (settled), P5 = A (settled; only its implementation is attacked). Every finding below is
checked against code; speculative ones are marked.

## Top 3 risks

1. **The fd-3 peer channel cannot exist on Windows (F3).** The process door refuses descriptor slots on non-unix in
   both directions. After phase 20 every Workflow unit run on Windows fails, though it runs in-process today. P5's
   host-to-Node direction has the same problem.
2. **A blind `releasedUnitRunSettle` on child exit (F5).** If the Rust child dies after it commits, the case ledger
   records "never started". The activity is then admitted and run again on top of a commit that already landed.
3. **Two provisioning doors on main for weeks (F1).** Phase 1 puts Rust provisioning on main. The Node provisioning
   that Work uses stays live until phase 04, which lands only with the whole integration series. Records cross in
   both directions with only a one-way test, and no doors row guards the gap.

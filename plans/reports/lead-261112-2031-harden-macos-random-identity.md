# HARDEN lead report: identity random bytes on macOS and Windows

Branch `harden/identity-random`. Scope: `packages/identity/rust` only, plus the lock line, the one-door census regenerated by the commit hook, the CHANGELOG line, one backlog row and this report.

## Cause

`fgos_identity::text::random_bytes` had a body only for `target_os = "linux"` (`/dev/urandom`); every other OS returned `Unsupported`, "native random identity driver unavailable". Every id mint (machine, work, backlog, project, signing key name) failed on macOS and Windows. Run 43217604616 (macos-latest, `fgos` tests) had 41 such panics.

## Choice: (b)

- `cfg(unix)`: `/dev/urandom` (the Linux code, now also macOS).
- `cfg(windows)`: `BCryptGenRandom` with `BCRYPT_USE_SYSTEM_PREFERRED_RNG` through `windows-sys` (feature `Win32_Security_Cryptography`, already used by `fgos-process`).
- No fallback: any failure is an `io::Error`, never an id from time or pid.

Why not (a): the only in-repo primitive is the private `random_token` in `fgos-process` (hex string, Windows only, in `containment/windows.rs`); reusing it means a new public API in `packages/process`, which is out of this change's scope. Why not (c): `getrandom` is in the lock only transitively (not for identity); depending on it directly is a new edge in the lock and a new dependency decision, where (b) adds only a `windows-sys` edge that already exists elsewhere. Cargo.lock change: one line (`windows-sys` under `fgos-identity`), agreed with the coordinator.

The `fgos` tests do exercise minting on both.

## Other linux-only primitives in identity

Only `proc_tree.rs` (macOS: session-only; Windows: unreadable, caller stays unresolved by design). No others.

## Authority

- What: the kernel random-bytes decision is held twice on Windows: `fgos-process` `random_token` (private) and `fgos-identity` `random_bytes`.
- Where now: `packages/process/rust/src/containment/windows.rs` and `packages/identity/rust/src/text.rs`.
- Where it belongs: one primitive at the lowest tier both crates import. Backlog row p-edapguuh6j opened. Not merged here, by decision.
- Also: the macOS process-tree walk belongs in the process crate (`fgos_process::facts`), not behind identity's `SessionOnlyTree`.

## Lessons

- The one-door census hook refuses any commit that changes a Rust file it digests, so a lane scoped to one crate still touches `packages/git/contracts/mutation-census.v1.json`; run `--write-census` before the first commit.
- Fixing one macOS gap exposed the next layer (git WAL, holder-lock); a macOS "green" needs a list of known platform gaps, not a single fix.
- `holder-lock-cross-platform.yml` does not name `fgos-identity`, so a change there is proved only through `fgos` tests.

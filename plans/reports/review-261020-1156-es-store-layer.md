# Review: Event Store store-layer hardening (dormant), a30008276..1ab6c566d

**Verdict: not ready to merge.** One Critical finding (the new pre-commit rule refuses Work's ordinary event-shard commits on main today) and one High (the dormant census pins byte hashes and line numbers of main's busiest Work files, so it will turn `npm test` red on unrelated edits within days). Both are small to fix. The Rust store changes are sound apart from one Medium durability window. After the Critical and High are fixed, this can merge.

## Critical

**C1. The retired-layout hook rule refuses legitimate Work commits on main now.** `.githooks/pre-commit:344-348` and `:466-467`.
Main tracks 90 per-writer shards under `.fgos/events/` (`.gitattributes`: `.fgos/events/*.jsonl merge=union`), and the live writer (`src/state/event-log.mjs:204`, `src/state/store.mjs:140`) creates a new `<writer-id>-<ts>.jsonl` file per writer session. New shards are committed routinely: `git log --diff-filter=A` shows them added as recently as 2e9cfb7f9 (2026-10-17, checkpoint commit), a67cf7b1d, 44287a09c and so on. Every such commit stages an added path under `.fgos/events/`, which `--diff-filter=ACRT` plus `startsWith('.fgos/events')` refuses. Reproduction in a scratch repo: base commit with `.fgos/events/old.jsonl`, then stage a new shard and run the hook; output `commit refused: retired event paths cannot be added: .fgos/events/new-writer-20261020.jsonl`, exit 1. Checkpoint commits of `.fgos`, `main-fgos-checkpoint.mjs` commits, and merges carrying a new shard (the check runs before the MERGE_HEAD handling) are all blocked. This changes Work's live behaviour on main, which the board's newest line forbids before the Work cutover.
*Fix:* make the rule dormant until the fence exists. Exact condition: enforce only when `.fgos/events` is a blob in HEAD **or** in the index (`git ls-tree HEAD -- .fgos/events` or `git ls-files -s -- .fgos/events` reports mode `100644`/`100755`, not a tree). Before cutover `.fgos/events` is a directory, so the rule is a no-op; the cutover commit that installs the fence (and deletes the shards, which are `D` and never matched) is itself checked; every later commit is checked. Add a test case "legacy directory present, no fence: new shard admitted", and in the `fence` case assert `result.status === 0` (it currently asserts only the absence of the message, `test/githooks/event-layout.test.mjs:24`).

## High

**H1. The dormant regression census freezes main's Work files and will break `npm test` for unrelated lanes.** `test/event-store/door.test.mjs:493-507, 511-528, 547-549`.
The test pins exact sha256 hashes of 13 live files, including `bin/fgos.mjs` (68 commits since 2026-10-01), `src/state/store.mjs`, `replay.mjs` and `registrations.mjs`. It also deep-equals invocation findings keyed by line number (`bin/fgos.mjs:5177`, `src/runner/execution/run.mjs:972/973/980/1026/...`, `src/workflow/case-verbs.mjs:133/230/303`), which shift whenever anyone edits above those lines. `test/event-store` is in the runner's component list (`scripts/run-tests.mjs:37`), so after merge any lane touching those files fails the suite with "WORK owner changed", and must either edit this Event Store test or stop. That is a de facto freeze on Work sources and pushes friction onto every other lane; it is not what "Work isolated and batched for later" asks for. It does not *hide* a new violation (a new site changes the set and fails), but it fails for reasons unrelated to the door.
*Fix:* remove the content hashes. Key findings by `file: function` without line numbers (or by a per-file count), so only a new or removed invocation changes the census. If the census must stay strict, mark it a non-gating diagnostic until cutover. Keep the "no new bypass" assertion.

## Medium

**M1. Removing the unconditional root-directory fsync opens a power-loss window for acknowledged events.** `packages/event-store/rust/src/identity.rs:119-127`, together with `append.rs:133-148`.
Before this change, `sweep_temps_under_append_lock` synced `layout.root` on every append. `prepare_stream` syncs `layout.root` only when it creates `closed/` itself. Sequence: process B runs `create_dir_all(closed)` for a new stream, then dies before `sync_directory(closed)`/`sync_directory(layout.root)`. Process C sees `closed` exists (`created = false`), syncs only `paths.root`, writes, fsyncs `active.jsonl`, and acks. The stream directory's own entry in `layout.root` was never made durable, so a power loss can drop the whole stream including C's acked events. The old per-append root sync covered this, possibly by accident. The comment "Also covers a predecessor killed after creating active but before dir sync" handles the next level down but not this one. ext4 journaling makes this unlikely in practice, but spec item 10 promises no acked-event loss on power loss. Not merge-blocking for a dormant store, but it must be closed before cutover.
*Fix (keeps two steady barriers):* decide durability from a durable marker rather than `try_exists`. For example, have `prepare_stream` write the stream's `hwm` (or another marker) only after both directory syncs, and treat a stream without the marker as "created" (sync `closed` and `layout.root` again). Add a crash-point test: kill after `create_dir_all`, next append acks, then assert the root was synced (FileSystem injection already exists).

**M2. The reader census still exempts whole files by name, so a new retired read inside those files is invisible.** `test/event-store/door.test.mjs:560-562`.
The regex skips `src/state/events.mjs`, `src/state/event-log.mjs`, `src/workflow/store.mjs`, `src/workflow/case-admission-port.mjs`, two `src/verbs/events/*` files, four scripts and `packages/observe/rust/src/friction.rs`. `events.mjs` and `event-log.mjs` *are* the legacy Work readers. Any new retired-layout read added to them passes silently. This contradicts the report's claim that "the scanner does not exempt or suppress them". *Fix:* move these into the asserted finding list (by file and function), or narrow each exemption to named functions with a comment saying why.

## Low

- **L1.** The hook prefix `startsWith('.fgos/events')` also matches `.fgos/events.jsonl.backup-*` and any future `.fgos/events-*` or `.fgos/eventsX`. After the fence this is probably intended for backups, but it should be an explicit list: `.fgos/events.jsonl*` plus `.fgos/events/`. Otherwise a future unrelated `.fgos/events-...` path is refused.
- **L2.** `diagnostics::maintenance` (`diagnostics.rs:72-80`, via `seal::oldest_unsealed_age_sec`) reads every closed segment and active file in full to get one first line, and takes no lock. A writer mid-way through the first batch of a fresh `active.jsonl` produces a torn first line, and the serde parse then fails the whole maintenance call instead of reporting the stream. Read only up to the first `\n` with a buffered reader, and skip or report an incomplete first line rather than erroring. This matters because section 16 runs it at the start and end of every command.
- **L3.** `scripts/event-store/v-spawn-bench.mjs` imports `test/helpers/git-addon.mjs`. A script depending on a test helper is a layering smell. Acceptable for a benchmark, but worth moving the build/load helper to `scripts/` or `src/git/`.
- **L4.** `own_origin` getter (`packages/git/node-addon/src/event_store.rs:88-98`) returns `""` when there is no store. The facade has no doc saying an empty string means "no store yet". Consumers keying `cover[\`${ownOrigin}:project\`]` will silently key `":project"`. Prefer `null`/`undefined` at the facade.

## Focus questions answered

1. **Live-behaviour safety.** The hook is the only change that alters Work on main, and it does (C1); dormant condition stated above. The Git driver change (`packages/git/rust/src/driver.rs:690-699`) does change live Git component behaviour: Inspect config reads now reuse the stamp-validated cache that Publication already used, instead of spawning `git config` each call. I checked that it is safe. The stamp covers dev, inode, size, mtime and ctime in nanoseconds, plus missing files. `config_paths` is policy-independent apart from spawn mechanics. Node callers construct a `GitDriver` per call, so the practical effect is small. This is a foundation-layer change and fits "foundation first". The new facade methods, `branchKey` and `decodeLegacyFiles` have no Work caller (`git diff --name-only a30008276 -- src/state src/runner src/setup bin domains` is empty, confirmed).
2. **Durability.** The steady-state 3→2 change is correct for the sweep itself: a temp file whose removal was not synced just reappears and is removed again. But removing the root sync exposes M1. Verified-frame reuse is safe against a concurrent writer. The cache key is the complete byte content just read plus origin, stream and strictness. A concurrent change produces different bytes and runs the full verifier. Only successes are cached. It is thread-local, so there is no cross-thread race. Memory is bounded to about 4 MiB of input plus one decoded clone per thread. The included test covers a changed byte, a different origin and the strict/non-strict split for a torn suffix.
3. **Maintenance fact.** It is correct that there is no ref walk or legacy read: it uses only `read_dir`, file reads and the sync receipt; `context()` only validates ranks. It is sufficient for the section 16 interval trigger and crash leftovers (closed segments count toward age). It needs the torn-first-line hardening (L2) before it runs at every command start and end.
4. **Door test.** Both test files pass. I did not re-derive every synthetic bypass. The census does not hide new invocation violations, because exact set equality fails on additions. The real problems are the brittleness in H1 and the file-level reader exemptions in M2, which do hide new reads in those files.
5. **Other checks.** `branchKey` has a single source: the facade delegates to `layout::branch_key` through `event_store_branch_key`. Bench seeding is realistic (about 7.9 KB × 1000 ≈ 8 MB, sealed before timing; `--seed-history` copies records without touching the input) and uses no Work consumer. `withStateTx` is the kernel gate. The tests use real repositories and a real native path, not mocks; only L3 is a layering note.

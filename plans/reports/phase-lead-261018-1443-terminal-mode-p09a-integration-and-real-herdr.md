## Real herdr found five product defects, all fixed here
Every one was invisible to the fake-herdr tests; each has a test now.
1. **Launch never identified** (`terminal-control` `match_expected`): the pane shell's pid was excluded, but `cd … && exec launcher` makes the shell pid the launcher. Every real `herdr-spawn` ended `terminal-launch-not-started` after the identify timeout. Fix: argv decides, the shell pid is not excluded (same rule `match_launched` already had since `ce3ed37e0`). Unit tests both ways.
2. **A retained pane could not survive** (`launch_line`): with `exec`, the pane closed when gate/agent ended, so `retain` (timeout, needs-human, blocked: the pane a person should read) kept a slot record for a pane that no longer existed, and the receipt text "the pane is left open" was false. Fix: no `exec`, the pane shell stays the parent (what run-supervisor spec §9 already says: "the parent of bwrap is the pane's shell"). `fake-herdr-pane.py` now models the shell as the `sh -c` child like a real pane. Verified live: hD pane retained.
3. **codex brief swallowed** (`agent-protocol` `confirm_submitted`): a 4 KB paste keeps codex `working` for 1 to 3 s and swallows Enter for up to ~6 s. The adapter read the first `working` as submitted (run hung to its deadline) or, when `working` was missed, read idle plus a composer that shows only a window of the paste as "no draft, not echoed" and cancelled (`delivery-unknown`, brief typed into the shell afterwards). Also herdr's `promptText` for codex is the window title, so the screen fallback never ran. Fixes: `working` counts only when the composer no longer holds the brief or work lasts 8 s; the screen is always read when idle; a composer window (two or more of the brief's own lines in the last six) is a draft, so Enter is pressed again (every 2.5 s, six at most).
4. **codex folder dialog** (v0.163): wording is "Trust this folder?", it opens about 1 s after the first prompt screen, and `ready_gate` never asked the detector again, so the brief was typed into the dialog (Enter on "Quit": codex exits, rest of the brief lands in zsh). Fix: marker for the new wording, detector asked again after the settle wait.
5. **Test harness contamination** (`terminal-harness.mjs` `agentNote`): an unconfined project fell back to scanning every `/tmp/fgos-confinement/*/home` for `agent-starts.txt`, so any concurrent confined agent made "an agent that never started" fail (this is the P08 carry-over `terminal-cutover` failure; proven with a planted file, red on old code, green on fix). It was not a too-tight wait and not a product race.

### HL-N8 / HL-N9, axis A/E, **Low**, reproduced (TEST's mutations; the reasoning below is from `hot-lock.mjs:107-151` and is checkable by the two red tests named). One of the two bytes-equal checks is redundant; one owning proof each, then one check.

Both run under the reclaim kernel lock (`reclaimDeadHolder:127`, `clearHotRecord:144`). Under that lock only another reclaimer or fencer (excluded by the lock) or the holder itself can change the record. Case 1, `reclaimDeadHolder`: the holder was judged dead before the lock; a *live* holder that linked a record between the observation and the lock has another pid, start time or writer, so its bytes differ and `again.raw !== observed.raw` returns `changed` (`:131`); identical bytes name the same tuple the judge already answered `dead` for, and a tuple does not die and live again, so the re-judge at `:132` cannot answer otherwise. `unlinkRecordIfUnchanged(record, observed.raw)` (`:133`) reads and compares a third time, under the same lock, with the same answer. Case 2, `clearHotRecord` (the fence path, `:142-151`): its only guard is the compare inside `unlinkRecordIfUnchanged`; with `--attest-stopped` the person vouches for a holder the judge could not place (`lock-fence.mjs:197-203`). **Decision:** keep the check in `unlinkRecordIfUnchanged` (it is the one both paths share), delete `:130-132` (3 lines) so `reclaimDeadHolder` is `acquire reclaim → unlinkRecordIfUnchanged → cleaned|changed`. **Owning proofs** (in-process, `test/state/hot-lock-tx.test.mjs`, no second process needed because the interleaving is "the file changed between my read and my clear"): (1) *a record that changed after it was judged dead is not reclaimed*: write a dead record, `readHotRecord` it, overwrite the file with another record, `reclaimDeadHolder(fgosDir, 'state', observed)` → `'changed'` and the new bytes are still there; (2) *the fence clears only the bytes it read*: `clearHotRecord(fgosDir, 'state', staleRaw)` after the file changed → `false`, file intact. Both tests are red today only if the check is removed, which is what "one proof per behaviour" asks for; TEST's finding that each check covered for the other dissolves once there is one check. Known limit to record in §15: between the compare and the `unlink` no POSIX call pins the inode, so a holder that is *alive despite the attestation* and that unlinks and relinks inside that window can lose its record; the window is one syscall wide and only reachable through `--attest-stopped`.

## Rejected hypotheses (checked, found fine)

1. **`releaseRecord` unlinks without a bytes check** (`hot-lock.mjs:204-218`): a live holder's record can only be removed by a reclaimer that judged it dead, which the judge forbids for a live tuple; no second check needed.
2. **`lock-record-unreadable` uses mtime** (`lock-record-checks.mjs:15-21`): a warning threshold in a doctor row, not a lock decision; spec §3's "no result derived from mtime" is about port operations. Fine, and it moves into `lock-holders` unchanged.
3. **Two `LockScope` implementations (Rust `scope.rs`, Node `lock-scope.mjs`)**: each tracks the ranks of its own process's callers; no decision crosses the boundary; the kernel excludes across scopes. Not a duplicate rule.
4. **`hostBin()` caches the first resolution and ignores a later `fgosDir`** (`driver.mjs:58-70`): one host per process is the intent (same rule as identity); a process never serves two workspaces.
5. **`registry.mjs` reads the registry from the source tree path** (`:14-17`): the payload ships the file (spec §7); the Rust side embeds it (`scope.rs:40`); `scope_rank.rs:135` pins that both match.
6. **`hot-guard.mjs` wraps `child_process` for the whole process at import** (`:60-71`): a global guard, but it is the mechanism the spec requires ("no switch that turns the guard off", §15) and it has one owner.
7. **`state-root.mjs` route answer cached for the process life** (`:17, 36`): the pin is read fresh (`:34`); only the compatibility channel reaches the cache, and a root cannot move mid-process.
8. **Convention Node client duplicating rules**: `convention-client.mjs` has no rule, pattern or directory (spec §15 row 9 still holds on main). SEAT's additions are reviewed under A.3.
9. **`fgos lock-status` as a duplicate of doctor `lock-holders`**: one is a read-only verb an agent needs mid-task (the fence skill sends it there), the other a health row; after S-E2/E4 both read one door answer. Keep both.
10. **Agent-facing error texts without a next step**: every `HolderLockError`, `WriterIdentityError` and `HotLockError` I read names one (Part B "passed" list), except S-F1.
11. **`run_borrowed_io_watched` and `environment_marked`** (`port.rs:978-1115`): Git's; outside T1.
12. **`predecessorState` facade export** (`index.mjs:683`): one caller (`holder-lock-checks.mjs:475` goes through its own spawn, not through this export) — the export has no caller in `src` (`rg "predecessorState\(" src` → `index.mjs:683` only).

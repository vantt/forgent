## Concerns
- Verdict rule is the plan's literal one: every direct row an account fault -> `account-fault` even if a harness row answered. Harness `ok` rows after a dead direct call are possible only when the two legs read different logins; reported as `account-fault` by rule.
- `--timeout-ms` applies to the harness leg only; the direct call keeps its 90 s default (registry text says so).
- `--executor`/`--invocation` narrow only the harness leg; the direct leg of a narrowed single-account probe still runs under `--leg both`.
- Direct row evidence is the probe's detail (no raw CLI output), so it carries no credential text.
- `accountProbeDoors.cfg` replaces the config loader for tests: the real loader refuses a minimal fixture (default capabilities name invocations), so the CLI case injects the runner config.
- Account lock wait is the door default (30 s); a busy account shows as an `other` direct row with the lock error.

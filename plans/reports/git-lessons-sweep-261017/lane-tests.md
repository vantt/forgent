# Git-mutation test inventory (read-only research)

**Verdict: CLEAR** — exhaustive inventory of tests that import or exercise the named git harnesses is complete from repo evidence. Gaps below are coverage holes in the suite, not inventory holes.

## Goal context

fgOS plans to replace every git harness with one Rust git component. Existing tests are the executable form of past lessons and must be ported or re-expressed. This inventory is evidence only — no product decision.

## Method

1. `rg` over `test/` for imports/exercises of:
   - `src/runner/merge.mjs`, `worktree.mjs`, `main-checkout-lock.mjs`, `lock-wait.mjs`
   - `src/runner/execution/commit-unit-work.mjs`, `unit-sync.mjs`
   - `src/workflow/integrate.mjs`
   - `src/verbs/merge/*` (approve, catchup, sync-root, promote-to-component, merge, review, reject)
   - `.githooks/pre-commit`, `scripts/install-git-hooks.mjs`
2. Extracted every `test('…')` name via quote-aware parse.
3. Included full files when the file is a dedicated harness suite; for doctor/workflow/events/post-merge, filtered to names that actually touch git mutation/hooks/locks.
4. Excluded pure FSM/docs/doctor-config tests that only mention merge paths in fixtures (e.g. graph-metrics footprint strings, gate-approve without git).

## Finding summary

1. **Largest lesson clusters** are lock protocol (main-checkout + merge-target-slot + hook), worktree crash-reclaim/resync/ADR0020, merge CAS (.fgos union, ownFileSet, mid-merge dirty, verify-under-lock), and CLI approve/catchup/sync-root/promote closed-world outcomes.
2. **Hardest port class**: multi-process lock races (`merge-target-slot-multiprocess`, main-checkout two-process atomic create, run-lock SIGKILL/SIGSTOP, merge fanout same session id, mid-merge dirty race). These need a Rust-side multi-process test harness, not a thin CLI re-wrap.
3. **Easiest port class**: CLI black-box suites (`fgos-approve*`, `fgos-merge` sync-root/promote, catchup, claim unlock/lock-status, setup hooksPath) and e2e hook suites if the hook remains a process boundary.
4. **Coverage hole**: `src/runner/execution/unit-sync.mjs` has **zero** direct tests despite owning merge-into-unit-branch behavior for the run door.
5. **Duplicate surface**: many merge behaviors appear both as `test/runner/merge.test.mjs` unit and `test/cli/fgos-approve*.mjs` black-box — porting can collapse to one layer once the Rust component owns the git core.

## Verdict

**CLEAR.** The inventory question is answered from repository evidence. Product choices (what to port first, whether unit-sync moves into the Rust component, how to collapse duplicate CLI/unit layers) are out of scope for this researcher persona.

## CAS revert/restore finding

The reason for `bc818eb85` and `0b7a62e49` is clear:

1. `7e682516e` had already landed the Q5 CAS merge gate on `main`.
2. A later branch brief said that branch must not contain Q5. The worker interpreted the existing mainline code as an earlier agent’s overreach and reverted it without checking ancestry; the repository’s later forensics records the worker’s own admission that it forgot that check (`plans/reports/harness-investigation-261006/behavior-forensics-cases-261006.csv:40`).
3. Review caught the mainline regression, producing the double revert `0b7a62e49`. A follow-up integration commit explicitly says “Restore Q5 CAS merge gate (revert the revert).”
4. Restoration exposed genuine implementation defects, fixed in the same evening/day: Git-file-safe `MERGE_HEAD` detection and verify-skip (`c035e0898`), preservation of live `.fgos` state (`f9fe0b29a`, although its temporary hard-reset approach was later replaced), restored E2E/lock checks (`8276870ff`), dependency/setup provisioning (`7bf215a21`, `f63f7e7d6`), lock narrowed to publish (`ffc64b1aa`), and a final own-file cleanliness recheck under lock (`59e69c18e`).

The implementation-neutral lesson is not “never revert”; it is: **before removing behavior because a branch brief excludes it, establish whether it is inherited mainline contract or branch-local work.** For the Rust component, CAS land should be treated as a settled safety contract, while the original JavaScript implementation details should not be copied blindly.

## Final finding

The history consistently converges on one Git component with four explicit responsibilities:

1. **Prepare:** canonical/trusted repo identity; isolated worktree; dependency/project setup; safe reattach/reclaim/unwind.
2. **Bring base:** pin the base commit; own `MERGE_HEAD`; preserve control-plane state; expose only genuine conflict paths; resume by exact state.
3. **Land:** construct and verify away from the target; lock only the shared publish section; revalidate lease, target tip, and own-file cleanliness; atomic ref CAS; deterministic checkout sync.
4. **Commit/cleanup:** commit exactly declared scope through trusted Git metadata; verify parents/files; never absorb foreign index/state; keep cleanup separate, ownership-proven, and crash recoverable.

This is a research finding, not an architecture decision. The evidence is clear enough for the caller to design the Rust replacement without another history-discovery round.

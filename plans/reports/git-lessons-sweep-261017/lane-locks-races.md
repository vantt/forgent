# Git lock and race hazard inventory for the Rust Git component

**Status:** done (read-only research)  
**Verdict:** **clear for the requested inventory; current proof coverage is incomplete.** The repository provides enough evidence to enumerate the lock/race surface and distinguish shipped mitigations, incident-backed failures, and unproved hazards. The proposed holder-lock kernel removes the file-record ownership class (TTL, heartbeat, identity self-recognition, stale PID cleanup), but it does not make a sequence of Git commands crash-atomic. The highest unresolved boundary is successful `update-ref` followed by process death before checkout reconciliation.

All repository citations are relative to `/home/vantt/projects/forgent`. No workspace file was changed and no test was executed. The test column reports existing proof discovered by inspection; `NONE` means no matching proof was found.

## Scope and governing caveat

I read the required state layer first (`docs/specs/reading-map.md`, `docs/specs/runner.md`, `docs/specs/work-state.md`), then the requested implementation, hook, tests, history, r6 design, and rollout plans. I also ran `git log -S/-G` searches for `main-checkout.lock`, merge slots, `events.lock`, `claims.lock`, `MERGE_HEAD`, `update-ref`, `read-tree`, worktree verbs, native Git locks, GC, and maintenance.

The r6 assessment below is design coverage, not shipped coverage. Plan 4.3 is explicitly frozen pending the Rust Git component (`plans/261016-1306-main-checkout-single-door-hot-lock/plan.md:23-27`), and the roadmap moves main-checkout, merge-slot, and worktree administration into `fgos-git` (`plans/reports/roadmap-261016-2212-fgos-cook-and-git-component.md:42-68,139-162`). The old phase plan covers only `git worktree add`, explicitly excluding remove/prune (`plans/261016-1306-main-checkout-single-door-hot-lock/plan.md:46`; `phase-06-worktree-admin-callers.md:7-14`).

For native Git semantics, the primary references are Git's [lockfile API](https://git-scm.com/docs/api-lockfile/2.0.5.html), [`update-ref`](https://git-scm.com/docs/git-update-ref.html), [`read-tree`](https://git-scm.com/docs/git-read-tree), [`worktree`](https://git-scm.com/docs/git-worktree.html), [`gc`](https://git-scm.com/docs/git-gc), [`maintenance`](https://git-scm.com/docs/git-maintenance), [`pack-refs`](https://git-scm.com/docs/git-pack-refs.html), and [repository layout](https://git-scm.com/docs/gitrepository-layout/2.44.0). Git lockfiles provide atomic publication for individual files/refs; they do not make the multi-command fgOS transaction atomic.

## Ranked multi-process proofs required before cutover

These are proof requirements inferred from the inventory, not product/architecture decisions. Priority ranks consequence first, then how little existing evidence constrains the failure.

1. **P0 — kill after successful `update-ref`, before `read-tree` (L-016/L-017).** Put a real child behind a deterministic Git barrier, confirm the CAS succeeded, then `SIGKILL`. A fresh process must acquire the new lock and reach one defined, lossless state for target ref, symbolic HEAD, index, worktree, staged/untracked changes, and recovery receipt. Repeat under contention.

2. **P0 — kill during `merge --no-commit`, blocked verify, commit, and worktree cleanup (L-007/L-013/L-015/L-032).** Exercise `SIGTERM` and `SIGKILL`. The successor must distinguish owned abandoned state from foreign `MERGE_HEAD`, never abort foreign work, and either recover the owned transaction or fail with a named actionable result.

3. **P0 — native Git lock and maintenance collision matrix (L-020–L-026).** Race land/checkpoint/worktree administration against a real holder of `index.lock`, same-ref lock, `packed-refs.lock`, shallow update, `git pack-refs`, `git gc --prune=now`, and `git maintenance run`. Assert no corruption or silent success, bounded named retry/refusal, survival of the unreferenced verified commit, and no leaked borrowed descriptor.

4. **P0 — state append versus Git staging/restore (L-014/L-036).** Pause checkpoint and merge at status/add/restore/abort barriers while real processes append events. Assert every accepted event remains in the authoritative log, the committed snapshot is a valid prefix/set, abort cannot strand an unowned half-merge, and no caller reports success with silently lost state.

5. **P1 — same-target complete lands under verify (L-011).** Process A pauses inside verify while holding its target slot; B targets the same ref and must block before reading the tip; C targets another ref and may proceed; D may acquire main. After A lands, B must re-read/re-merge/re-CAS rather than publish work based on the stale tip.

6. **P1 — land versus raw checkout/switch/reset and an attached target worktree (L-009/L-017/L-019).** Run both with the hook wired and hooks disabled. Prove the supported boundary yields a named refusal/reconciliation and preserves staged/untracked data. If raw Git stays explicitly outside the guarantee, the test must still prove detectable drift rather than silent overwrite.

7. **P1 — mixed worktree administration (L-027–L-032).** Real processes concurrently add/remove/prune/list/reclaim/relocate temporary and claim worktrees; kill one at each administrative barrier. Assert common-dir metadata remains valid, no live checkout is removed/moved, stale registrations are recoverable, and cleanup never deletes a successor's registration.

8. **P1 — stale-reclaim/release ABA for every migrated lock (L-001/L-002/L-033/L-034).** Use barriers around the final compare/unlink/release. A successor that acquires must never have its kernel handle or state record deleted by an old reclaimer/releaser. Include malformed records and the current claims “live >30 s” case as regression fixtures.

9. **P1 — real foreign `MERGE_HEAD` owner death (L-013–L-015).** Process A creates a real merge state and dies; B attempts land. B may recover only with durable ownership proof, otherwise it must preserve the state and report the foreign owner. Same-process preconstructed files are insufficient.

10. **P1 — staged-but-uncommitted and `read-tree` failure matrix (L-017/L-018).** Cover staged intersecting/non-intersecting paths, unstaged and untracked paths, branch switch between ref CAS and sync, and injected `read-tree` failure. A successful ref move must never be mistaken for a fully reconciled checkout.

11. **P2 — retain and extend holder-lock crash proof (L-003–L-006/L-025/L-038).** Preserve real `SIGKILL`, 8-process exclusion stress, same-session sibling rejection, borrowed Git parent-death lifetime, background-child/fd leak, predecessor-domain reap/timeout, and mixed old/new cutover vectors from the holder-lock plan (`plans/261016-1104-holder-lock-kernel-lock-foundation/plan.md:84-86`).

12. **P2 — hot-state no-exec/no-nesting/order proof (L-035/L-037).** Make the three known historical call sites fail under the guard before refactor (`currentHead` in claim, main-root resolution in claims, plan evidence in state), then prove the migrated code prefetches outside the critical section. Add opposing-order real processes and assert immediate `lock-order-violation`, never timeout.

## Findings handed back to the caller

- The holder-lock primitive's kernel exclusion model is sufficiently specified to replace TTL, heartbeat, PID liveness, ambiguous ownership, and session-identity self-recognition. That finding is **clear** from r6 §6.0–§6.6 and the holder-lock plan.
- The proposed Git layer is **not yet sufficiently proved for cutover**. Its missing evidence is concentrated in transaction recovery, native Git/maintenance collisions, full worktree administration, attached-checkout drift, and the state↔Git staging boundary.
- No architecture choice is made here. In particular, this report does not decide whether recovery uses a receipt/journal, a temporary ref, reconciliation-on-acquire, or another mechanism; it only records the interleavings the chosen mechanism must prove.

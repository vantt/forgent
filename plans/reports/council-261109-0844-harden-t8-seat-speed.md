# HARDEN T8 council, SPEED seat: Skill/Domain

Seat lens: wall time that a project using fgOS pays for skills and domains (Ship Faster, owner priority 1 of the product order), measured. Main `ae6d634ff` (`origin/main`; the baseline was taken at `b7c7c372c`), machine fg-server2, 2026-11-09 08:44 to 09:00 (Asia/Saigon). The machine was **not quiet**: load average (1 minute, 24 cores) was 8 to 15 for the build runs, 36 to 47 for the test passes, 10 to 20 for the doctor run and 41 to 98 for two file-copy runs (other lanes). Every number below says its load. Read-only seat: nothing but this file was committed.

Citations used (glossed): RUL104 (rule "better, not bigger": every change makes the existing thing better without growing it); owner decision 75 (2026-11-09: HARDEN runs T8 Skill/Domain through the same per-layer loop); design principle 8 (one owning proof per behaviour); L10 (extend through the door, not beside it).

## Part B: findings

Severity bar: High = a measured cost that a user pays on every use of a route with a small local fix; Medium = measured and bounded, or a High cost whose fix is a policy choice; Low = measured and small; Not a finding = measured and too small to act on, listed so the council does not spend time on it. No High finding exists in this layer.

**F-1 (Medium, reproduced; the only cost here that a person waits for): every new worktree copies 89 MB and 8 759 files of vendor skills that no executor of this repo declares.**
Scenario: `fgos worktree create` runs `worktreeSetup.commands[0]` (`.fgos/config.yaml:230`), which copies every `ak-*` dir from five skill roots of the main checkout into the new worktree. Measured: create 3.9 s at load 10.6, remove 1.8 s; the copy alone 3.7 s (load 41) and 4.4 s (load 98), 8 759 files, 89 MB (the baseline estimated 92 MB, not measured). The executors declare only `ak:cook` in `supports.skills` (`core/config-standard/runner.yaml:25, 82, 172`; `fgos config show` lists `ak:cook` and `fgos-coding-implement`), and `executor-skills-installed` checks only that the main checkout has them. The copy exists so a worker in a worktree can run `ak:cook` (commit `9fa8a08f0`).
Fix: name what is needed instead of a glob. Two sizes, the owner picks: (a) `ak-cook` only: 55 files, 1 MB, 0.05 s, but `ak-cook` names nine other `ak-*` skills in its text that a worker may call; (b) `ak-cook` plus those nine: 146 files, 1.3 MB per root (730 files, 6.5 MB over five roots, computed), about 93 percent fewer bytes and 92 percent fewer files than now. Either is a one-value edit of one config line; no Node change. Fix size: 1 config line. It is a project-config decision (the config component and the owner machine own that file per the baseline's collision list), and baseline H8 already named it. Not done here (read-only seat).

**F-2 (Low, reproduced): `npm run build:skills` spends 70 percent of its warm time staging the addon, and the render is already fast.**
Scenario: maintainer after editing a skill. Warm 1.13 to 1.27 s: staging 0.82 to 0.90 s, render 0.30 to 0.60 s. Cold first run in a fresh worktree 33.7 s (one cargo build). Nothing here to speed up: staging is the shared door that the script needs because instruction projection reads YAML through the native door, and it is the same door the sibling scripts use. The correctness seat's fix (add `ensureAddonForScript()` to this script, baseline K2 and H2) adds exactly this staging cost that my measuring wrapper already paid, and turns an exit 1 into exit 0. Do not add a skip-if-unchanged cache: it would save under 0.9 s on a 1 s script and add a mechanism (RUL104). Fix size for speed: 0.

**F-3 (Low, reproduced): test time of the layer is about 13 s at quiet load for its own 18 files; most of the rest is not skill code.**
The slow T8-owned files at load 36 to 47: `check-decision-citation-drift` 12.9 s in the full pass (a rerun at load 40 summed to 4.5 s; 12 tests spawn the CLI at 0.7 to 1.1 s each, six tests over 300 ms are 4.2 s), `instruction-registry` 7.5 s, `domain-registry-compiled` 8.1 s, `domain-fields` 3.1 s, `instruction-composition` 4.1 s. One test, `fgos doctor lists every check when a domain workflow cannot be parsed` (`domain-registry-compiled.test.mjs:97`), runs the whole `fgos.mjs doctor --json` for **2.9 s of the file's 8.1 s** to prove that one row reports a bad YAML while the other rows still run; that is the single wiring proof (the neighbouring test at line 88 proves the row message in process), so it stays. The four files that are probably Work's cost 59.9 s of 109.8 s. Fix: none for speed. The only measurable lever in the T8-owned set is the 12 CLI spawns of the citation-drift test (about 1 s each at load 40), moving the non-contract cases to in-process calls and keeping one CLI wiring proof (design principle 8); saving at quiet load about 3 to 4 s, **an estimate, not measured after a change**. Fix size: test lines about -30 to +10.

**F-4 (Not a finding, measured): per-process cost of domains and workflows is under 20 ms and has no cache to remove.**
Import of the domain registry 5 to 9 ms; `loadWorkflow` rescan 9 ms, once per `propose` or `case-start`; `loadAgentRoster` 3 ms; persona resolve under 1 ms. The 172 ms first-call cost of `discoverWorkflows` is the native YAML door starting up in a new process (T0 to T3), paid by anything that parses YAML first, not by T8.

**F-5 (Not a finding, static): the 17 `readdirSync(domains...)` loops are a tidiness item, not a speed item.**
Static count in this tree: 11 outside `skill-wrappers.mjs` (`build-domain-registry`, `project-agents`, `agent-definitions`, `operation-prompt-templates` twice, `registrations` twice, `agent-roster`, `loader`, `instruction-registry`, `domain-registry`) and 6 inside it (lines 426, 454, 675, 681, 893, 931). The baseline counted 14 in 8 files with a narrower pattern. Each reads a two-entry directory (`coding`, `marketing`); the whole `loadAgentRoster`, which includes one, costs 3 ms. One door (baseline H5) is justified by L10, not by time; do not put a time claim in its plan. Which loops run per `fgos run` could not be counted at run time (see "Not measured").

**F-6 (Not a finding, measured): the doctor rows of T8 cost 27 ms of a 38.9 s doctor.**
For the lead, outside this layer: the doctor's own time (111 rows, in process, against the main checkout, load 13 to 19) is dominated by Git and Event Store rows: `event-store-open-root` 6.1 s, `main-checkout-hook-wired` 5.8 s, `delivered-not-on-trunk` 5.3 s, `node-version-and-git` 3.3 s, `event-store-machine-id` 2.2 s, then a dozen rows at 1.1 to 1.6 s (`work-classification-vocabulary`, `seat-binding-dry-bind`, `claude-plugin-marketplace` 1.3 s, each CLI `*-hook-wired`). That is evidence for the T2, T3, T4 and T9 seats; the load was 13 to 19, so the ratios matter more than the seconds.

**F-7 (Low, static plus link-graph measure): the largest agent-read cost in the layer is a T6 doctrine chain, not a skill.**
`fgos-architecture-panel` links a coordinator prompt (4.1 KB) that links an 82.6 KB role doctrine, which links 45.8 KB of artifact templates and 22.3 KB of rubric; the link-reachable total for `fgos-advise` is 254 KB. This is what is reachable, not what an agent reads; no run was observed. If an agent reads the chain whole, that is about 150 KB (about 40k tokens, an estimate at 4 bytes per token) per panel Unit. Fix, if the T6 seat confirms reads: split by role so a seat reads its own part (a doctrine edit, no code). Owner: T6 (agent-coordination doctrine). Not a T8 change.

## Feature ideas (kept apart; owner picks, none is planned)

- `provisionWorktree` derives the skill set from the executors' `supports.skills` itself, instead of a hand-written shell line in config. Problem: the line and the declarations can drift (today the line copies 104 dirs for one declared skill). Benefit: F-1 cannot come back. Cost: a new mechanism in `src/runner/worktree.mjs`, which RUL104 only allows after the owner chooses.
- A doctor row that reports the size a provisioned worktree receives (files and MB) against a budget. Problem: nothing flagged 89 MB per worktree for three weeks; evidence: 41 worktree dirs and 28 GB in the baseline.
- Reflink for provisioning is **not available** here (the worktree volume is ext4, checked with `df -T`); a hard link would share files between worktrees and needs a rule for skills a worker edits.

### version-bump-script
- **What:** `scripts/bump-version.sh` bumps/audits version numbers across every file declared in `.version-bump.json` (JSON field paths like `plugins.0.version`), detects drift (all declared files must agree on one version), and can `--audit` by grepping the whole repo for the current version string to catch files that contain it but aren't declared.
- **Where:** `scripts/bump-version.sh`
- **Notable:** Not itself unit-tested by anything in `tests/` (no `test-bump-version.sh` was found), but `tests/kimi/test-plugin-manifest.sh` cross-checks that `.version-bump.json` declares `.kimi-plugin/plugin.json`. Uses `jq` to convert dotted field paths (`"plugins.0.version"`) into jq paths (`.plugins[0].version"`) via `sed`. Modes: `--check` (drift report), `--audit` (check + repo-wide grep for undeclared occurrences of the version string, with configurable excludes), bare `<version>` (bump then re-audit).
- **Keywords:** `.version-bump.json`, `jq`, drift detection, `--audit`.

### shell-lint-script-and-suite
- **What:** `scripts/lint-shell.sh` runs ShellCheck + a shell syntax check (`bash -n`/`sh -n`) over shell scripts. It auto-detects "is this a shell file" by extension (`*.sh`) OR by shebang line matching `bash|dash|ksh|sh`, so extensionless files like `hooks/session-start` are still linted. File selection modes: default = changed files (`git diff` vs HEAD + staged + untracked), `--all` = every tracked file, or explicit file args. `--format` runs `shfmt -i 2 -ci -bn -w` before linting; `--strict` adds extra ShellCheck checks (`check-extra-masked-returns`, `check-set-e-suppressed`, `quote-safe-variables`, `deprecate-which`, `avoid-nullary-conditions`).
- **Where:** `scripts/lint-shell.sh`; test at `tests/shell-lint/test-lint-shell.sh`.
- **Notable:** The test builds a real throwaway git repo fixture (`git init -b main`, commits a tracked `.sh` and an extensionless `hooks/session-start`, then dirties both plus adds an untracked file and a README with a fenced ```bash``` snippet that must NOT be picked up). It stubs `shellcheck`/`shfmt` as fake executables that just log their invocation args to a file (`write_stub_tool`), then asserts on the logged arg list (e.g. `assert_contains "$tool_log" "<--severity=warning>"`) rather than running real ShellCheck — a "spy binary" pattern for testing a wrapper script's argument construction without needing the real tool to behave any particular way.
- **Keywords:** ShellCheck, shfmt, spy/stub binary via `PATH` override, `git diff --name-only -z`, shebang sniffing.

### codex-plugin-packaging
- **What:** `scripts/package-codex-plugin.sh` builds a rootless, deterministic zip/tar.gz archive of the Codex plugin from a git ref (`git archive`), seeding `skills/*/agents/openai.yaml` metadata from a prior official package (dir, `.zip`, or `.tar.gz`), normalizing timestamps (1980-01-01 for zip, 1970-01-01 for tar) and file modes (`tar.umask=0022`) for reproducibility, and refusing to build from a dirty tree unless `--allow-dirty`.
- **Where:** `scripts/package-codex-plugin.sh`; tests at `tests/codex/test-package-codex-plugin.sh` and `tests/codex/test-marketplace-manifest.sh`.
- **Notable:** `test-package-codex-plugin.sh` actually invokes the real packaging script (no stubbing) and inspects the produced archive: extracts it, lists paths with `unzip -Z1`/`tar -tzf`, asserts excluded source-only paths are absent via one shared regex `unexpected_pattern`, checks a script inside the archive kept its executable bit (`-rwxr-xr-x`), verifies zip entries all show `(1980, 1, 1, 0, 0, 0)` via a `python3`/`zipfile` inline snippet and tar entries all show `mtime` `0` via `tarfile`, confirms zip and tar.gz produce identical path sets, verifies re-running with a tar.gz vs zip metadata source produces byte-identical output (`cmp -s`), and checks the dirty-tree rejection path. `test-marketplace-manifest.sh` is a separate `python3` heredoc script validating `.agents/plugins/marketplace.json` fields (name, displayName, plugin source/policy/category) and cross-checking that `.codex-plugin/plugin.json` declares `"hooks": {}` (an empty object, not absent/`[]`) — the comment explains this exact-empty-object requirement exists to suppress Codex's `hooks/hooks.json` auto-discovery fallback re-registering the Claude Code SessionStart hook.
- **Keywords:** `git archive`, reproducible-archive normalization, `zipfile`/`tarfile` (Python stdlib) assertions, `openai.yaml` metadata seeding, empty-object vs absent-field JSON semantics.

### brainstorm-server-test-suite
- **What:** The most extensive functional test suite in the repo, covering the zero-dependency Node WebSocket/HTTP companion server (`skills/brainstorming/scripts/server.cjs`) used by the `brainstorming` skill's visual companion UI: raw WebSocket frame protocol (RFC 6455) encode/decode, HTTP+WS auth (`?key=` query param and `HttpOnly SameSite=Strict` session cookie), branding/telemetry HTML rendering, process lifecycle (idle timeout, port/token persistence across restarts, PID-ownership safety on stop, Windows/MSYS2-specific behavior), the injected browser-side reconnect helper script, and the browser-launch command builder.
- **Where:** `tests/brainstorm-server/package.json` (chained `node`/`bash` test script, depends on `ws` npm package as the only test-only dependency), `ws-protocol.test.js`, `helper.test.js`, `browser-launcher.test.js`, `auth.test.js`, `branding.test.js`, `server.test.js`, `lifecycle.test.js`, `start-server.test.sh`, `stop-server.test.sh`, `windows-lifecycle.test.sh`.
- **Notable:**
  - `ws-protocol.test.js` unit-tests `computeAcceptKey` against the literal RFC 6455 §4.2.2 worked example, and `encodeFrame`/`decodeFrame` across every frame-size boundary (0, 125/126 bytes, 65535/65536 bytes, >2^16), asserts server frames are never masked (`frame[1] & 0x80 === 0`) and client frames MUST be masked (`assert.throws(..., /mask/i)`), and rejects oversized 64-bit-length frames "from header alone" before any payload allocation (a DoS-guard test).
  - `auth.test.js` spawns a real `node server.cjs` child process (`BRAINSTORM_TOKEN` env var fixes the key) and drives it with raw `http.get`/`ws` (the `ws` npm package) requests: confirms wrong-key-with-valid-cookie still 403s (no silent fallback), confirms every response carries a fixed `EXPECTED_SECURITY_HEADERS` set (`referrer-policy: no-referrer`, `content-security-policy: frame-ancestors 'none'`, etc.), confirms a keyed bootstrap page executes an inline `<script>` (extracted via regex and run through `new Function('sessionStorage','location', code)(...)` in-process) that strips the key from the URL via `location.replace('/')` even if `sessionStorage.setItem` throws, and confirms cross-Origin WebSocket upgrades are rejected even with a valid cookie (CSRF/confused-deputy protection) and never write to `state/events`.
  - `server.test.js` is a broad functional suite: waiting-page vs full-HTML-passthrough vs fragment-wrapped-in-frame-template serving logic, newest-file-by-mtime screen selection, macOS resource-fork dotfile (`._*.html`) exclusion from both serving and file-watch reload triggers, `/files/` path-traversal-via-symlink and path-traversal-via-hardlink rejection (both for direct `/files/name` requests and for the auto-selected root screen), WebSocket broadcast to multiple concurrent clients, and malformed-JSON-from-client crash resistance.
  - `lifecycle.test.js` verifies idle-shutdown actually closes open WebSockets (proving `shutdown()` doesn't hang on a lingering connection), that unauthenticated request floods do NOT reset the idle timer (only authenticated activity counts), port+token persistence and reuse across a simulated restart (kill process A, start process B reusing the same `.last-port`/`.last-token` files), a random-port fallback when the preferred port is taken that must NOT clobber the persisted port file (so the still-running owner of that port keeps its reconnect target), and that an explicit `BRAINSTORM_TOKEN` env var fails closed (refuses to start) rather than falling back to a random token during a port conflict.
  - `helper.test.js` evaluates the *browser-side* `helper.js` source inside a Node `vm`-less sandbox via `new Function('module', src)(moduleShim)` to extract pure functions (`nextReconnectDelay` exponential backoff: doubles 500→1000→2000→…→cap 30000), then separately re-executes the whole browser script against a hand-built fake DOM/WebSocket/timer environment (`makeEnv()` with a `FakeWS` class, fake `document.querySelector`, fake `setTimeout`/`clearTimeout`/`Date.now`) to drive real reconnect/tombstone/status-text state transitions without a browser.

## Decision: the hook probes through `lock-fd --shared-try` (lead, after finding 1 below)
`fgos lock-status` is a `legacy-cli` verb, so the first design cost a Node start per commit. Decision: keep the native route mode `lock-fd --shared-try` with its old name and contract for the hook only (a process-boundary caller, like `--borrowed-check`, arbitration §2.1), and revert the `--lock` filter. Reason: a regression against today's one native route, and every older release already has `--shared-try`, so the new hook also works under the release activated today (checked: the activated release's `fgos internal lock-fd --shared-try` answers `free`). `mainLockVerdict`: `--borrowed-check` first when `FGOS_LOCK_FD` is set, then open the lock file (a missing file is `free`) and run `--shared-try` with it at slot 3 through `runLockRouteSync`; `fgos identity --json` stays for the writer. The hook no longer strips `FGOS_RUST_HOST_RECURSION_GUARD` (identity is native; the route is not a legacy verb) and the case that pinned it is gone. Kept: the no-host case, still "refused by the identity step".

## Findings against the phase file (no design improvised)
1. **`lock-status` is a `legacy-cli` verb, so asking it cost a Node start** (the risk table said ~1.5 ms). Resolved by the decision above.
2. (Landing-order hazard, resolved with it: the new hook works under the currently activated release.)
3. `holders(path)` takes the lock name as a second argument (`holders(path, lockName)`): `FGOS_LOCK_FD=<lock>:` cannot be judged from a path. `drainChild`, `clearDomain`, `releaseFd` take no `killWaitMs`: the lock carries the one given to `lockFd`. `lockFd`'s `mode` stays `'ex'|'sh'` but the facade only uses `'ex'`.
4. Windows: `lockFd`, `drainChild`, `clearDomain`, `releaseFd`, `closeHandedOver` are unix-only exports; the facade never calls them on the hold transport. Windows paths (`probe`, `guarantee`, `predecessorState`, `twoProcessProbe` through the door; `windows_lock_hold_route.rs` probing through `port::probe`) are compile-checked for the two crates only; the cross-platform workflow must prove them.

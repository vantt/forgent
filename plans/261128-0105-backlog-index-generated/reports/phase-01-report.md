# Phase 1 report — land door regenerates the index on every feeding land

## What changed

`packages/supervision/rust/src/land.rs`
- `INDEX_FEEDERS`: one constant, `plans/backlog/*.md`, `plans/*/plan.md`, `plans/discussions/*/DISCUSSION.md`.
- Paths land: `may_close_items` became `may_feed_index`; `close_cited_items` now only closes the cited items and no longer writes the index; the new `write_index` regenerates it whenever the concrete committed paths (or the door's item writes) include a feeding path or `plans/backlog.md` itself. The door's bytes replace a caller's bytes for the index (`DoorWrites::put`), and the existing restore-on-refusal covers it.
- Branch land: `drive` now carries the conflicted-file list; `candidate_index` generates the index from the candidate worktree (all its `plans/backlog/*.md` rows as `committing`) when the merged change set (target tip to candidate) touches a feeding path or the index, and re-prepares the candidate with the index forced in. The regeneration step merges its files with that list. The footprint judge skips `plans/backlog.md` and a conflict in it is settled by the generator, only when the port is wired.
- Doc comment on `LandPorts::backlog_index` updated. No port or signature change: `BacklogPort`, `backlog_index` (supervision.rs) and `portfolio.rs` are unchanged (the generator already takes the root it reads).

`packages/supervision/rust/tests/land.rs`
- Extended: `a_plan_land_that_is_not_a_turn_to_done_touches_no_item` (no item changes, now commits the index) and `a_legacy_id_does_not_match_the_file_of_a_longer_id_that_it_prefixes` (the index is now the one extra file). Neither assertion about items was weakened.
- New: (a) one new row commits that file plus the index; (c) a discussion land commits the index; (d) a land with no feeding path leaves the index alone (paths and branch); (e) a hand-edited index commits the generator's bytes, for scope `plans/backlog.md` and glob `plans`; (f) a branch land with plan status change and new row, footprint omitting the index, commits the regenerated index; plus a branch that edits the index itself gets the generated bytes.

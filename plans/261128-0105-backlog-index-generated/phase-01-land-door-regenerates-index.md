# Phase 1 — Land door regenerates the index on every feeding land

Capability: `code:implement`

## Inputs

- `plan.md` of this directory (Outcome, prior art, criteria 1-3, Risks).
- `docs/platform/supervision/spec.md` (land door sections) and `docs/platform/git/spec.md` (paths and branch land).
- `packages/supervision/rust/src/land.rs`: `BacklogPort`, `BACKLOG_INDEX`, `paths_attempt`, `may_close_items`,
  `close_cited_items`, `land_branch`, the footprint judge (`regen_files`, around "A regenerated file is exempt"),
  and the regenerate step (around "Everything after prepare").
- `apps/fgos/src/wiring/supervision.rs`: `backlog_index` and the `BacklogPort` it builds.
- `apps/fgos/src/wiring/portfolio.rs`: `generate_backlog_index_for_commit`, `tracked_item_paths`.
- `packages/supervision/rust/tests/land.rs`: the backlog cases from `item_text` to
  `a_cited_item_with_uncommitted_edits_is_refused_and_keeps_them`, and `fixture_index`.

## Footprint

packages/supervision/rust/src/land.rs, packages/supervision/rust/tests/land.rs,
apps/fgos/src/wiring/supervision.rs, apps/fgos/src/wiring/portfolio.rs

## Steps

1. Run impact analysis on `close_cited_items`, `may_close_items`, `paths_attempt`, `land_branch` and
   `backlog_index` (gate: `fgos dispatch decide --for impact-analysis --json`); record the blast radius in the
   phase report.
2. Index-feeding paths are one constant in land.rs: `plans/backlog/*.md`, `plans/*/plan.md`,
   `plans/discussions/*/DISCUSSION.md`.
3. Paths land: split "close the items a plan turning done cites" from "regenerate the index". Closing stays as is.
   Regeneration runs whenever the port is wired and the concrete committed paths (or the door's own item writes)
   include an index-feeding path, or include `plans/backlog.md` itself. The door always writes the generator's
   bytes to `plans/backlog.md` and commits them; a caller's bytes for that file are replaced, never committed
   (criterion 3). The restore-on-refusal behaviour of `DoorWrites` covers the index as it does today.
4. Branch land: when the merged change set (merge base to source) touches an index-feeding path, generate the
   index from the candidate worktree (its tracked rows plus the merged tree's plans and discussions, not the
   main checkout) and write it into the candidate before the gates, in the merge commit. Exempt the door's own
   `plans/backlog.md` write from the footprint judge the way `regen_files` are exempt; a branch that itself
   edits `plans/backlog.md` gets the generated bytes, never its own.
5. If the generator call needs a root other than `trusted_main_root()` for step 4, give `BacklogIndexFn` the root
   it reads (it already takes `&Path`); adjust `backlog_index` in supervision.rs and, only if needed,
   `tracked_item_paths` in portfolio.rs to read the candidate's tracked paths. Do not add a second port.
6. Tests in `packages/supervision/rust/tests/land.rs`, at the lowest layer that observes them, each title naming
   the behaviour: (a) a paths land of one new row commits exactly that one new file plus the regenerated index;
   (b) extend `a_plan_land_that_is_not_a_turn_to_done_touches_no_item`: still no item, now the index;
   (c) a discussion land commits the regenerated index; (d) a land with no feeding path leaves the index alone;
   (e) a paths land carrying a hand-edited index commits the generator's bytes; (f) a branch land whose plan
   status changed commits the regenerated index in the merge result, with a footprint that omits
   `plans/backlog.md`. Update the module comments that say the door regenerates only on a plan turning done.

## Verify

`cargo test -p fgos-supervision --test land` and `cargo test -p fgos` pass. Pass condition: cases (a)-(f) exist
and pass, and no existing land case was weakened.

## Rollback

Revert the phase's commit; the door returns to regenerating only when a plan turning done cites a row.

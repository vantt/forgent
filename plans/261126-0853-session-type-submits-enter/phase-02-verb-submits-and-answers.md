`fgos session type` keeps its open-event gate, then calls phase 1's shared call in `Profile` mode and answers
`submitted` or the refusal cause. `--no-enter` keeps the type-only path and answers `held` (discussion D5, D6).

## Steps

1. Parse `--no-enter` as a boolean on `session type`; carry it on `Verb::SessionType`.
2. In `type_into_session`, after the open-event gate: with `--no-enter`, call `type_text` as today and answer
   `{session, held: true}`. Otherwise resolve the head's CLI profile the way the typed wake does, call the shared
   call in `Profile` mode, and answer `{session, submitted: true}` or a refusal with its cause (and the quoted
   draft for `composer-not-empty`). Remove `typed: true`. Record coordination evidence as `submitted`, `held` or
   the cause.
3. Text never goes through a shell; the verb still refuses a newline in `--text`.
4. `supervision_verbs.rs`: one wiring proof that the JSON is `submitted: true` or names the cause and never carries
   `typed`. Adjust the existing gate test only where it asserted the old answer.
5. Add `--no-enter` and the new answer to the `session type` entry of `src/cli/command-registry.mjs`; regenerate the
   manifest with `node scripts/export-command-selectors.mjs`; never hand-edit it.
6. Update the spec row: the verb submits by the CLI's profile, answers `submitted` or a named refusal, `--no-enter`
   answers `held`.
7. Supervisor skill: the wake and on-site steps read the answer; on `composer-not-empty` the supervisor reads the
   quoted draft and raises it, and never types a bare `\r`. Remove any "type `\r` alone" workaround. Run
   `npm run build:skills`.
8. `CHANGELOG.md` `[Unreleased]`: one line naming the `submitted` answer, the named refusals and `--no-enter`.

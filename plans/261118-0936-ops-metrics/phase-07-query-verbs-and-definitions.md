# Phase 7 — Query verbs and named definitions

The CLI surface of layer 1. Rust. In wave 3 this phase is the only writer of `command-registry.mjs`.

- `packages/observe/rust/src/metrics_cli/mod.rs` (verb dispatch), `flags.rs` (flag grammar).

## Steps
1. Add `fgos metrics record --json <file|->`. It is the CLI over the phase-4 write door and keeps that door's
   fail-open rule.
2. Add `fgos metrics query` with the phase-5 grammar as flags.
3. Named definition file `*.query.json`:
   - Shape: `{name, requires?: [kinds], query, params?: {name: {configKey | value}}, minSample?, row?: {kind, reason,
     nextCommand}}`.
   - A required kind that is undeclared, or that has no source, gives `unmeasured: <reason>`. No placeholder
     declaration is needed (OM-D11, OM-D13).
   - Run definitions with `fgos metrics query --def <file|dir>`. The flag can be repeated, and one host call returns
     the rows of every definition.
4. `observe_query.rs` (composition root) resolves each `params.configKey` through the config door and passes the
   values into the query. Observe never reads config.
5. Tests:
   - A definition directory with `head-gone`, `plan-no-progress`, `lane-freed`, `plan-became-ready`,
     `watcher-overdue`, `supervisor-idle-burn` and owner wait, written over the test-local declarations from phase 1.
     It runs through `--def`.
   - A definition whose required kind is missing returns `unmeasured`.
   - A config-backed parameter is resolved.

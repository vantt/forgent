## Risks

| Risk | L × I | Mitigation |
|---|---|---|
| `settle_release` on the duplicate sees Node's still-open fd as an own live copy and reports `released` early (`flock.rs:367-369`), leaving escaped copies unsettled | M × H | Node closes its fd **before** `releaseFd` (requirements); the settle's own-copy check then sees none; `facade-multiprocess` asserts release within the kill wait and phase 1's RT-M2 case guards the handed-over path. |
| The External outlives the handle (a leaked handle) and keeps the description open | L × M | The WeakMap entry owns the External; `release` and `closeHandedOver` dispose it; a dropped `NodeLock` closes its duplicate in `Drop`, never settles (it is not a `Handle`); the inode-retry path disposes before closing. |
| The hook's `fgos lock-status --json --lock main-checkout` costs one cold host call (~1.5 ms plus one probe) per commit | L × L | Cold path; the Node scan it replaces cost 5.5 ms × 3 listings; measured in the report. |
| Another module reaches `lockFd` with a known fd number | L × H | The one-shot capability and its architecture case (D-T1-2). |
| `origin.rs` reads `ProcView` for every holder on every `lockHolders` call (doctor, lock-status) | L × L | Holders are few; the scan already read identities; one `ProcView` per holder is the same reads `holderOrigin` did in Node. |
| GIT's `handover.rs` signature change collides with a GIT lead | M × M | Board note before merge; the change is one argument. |

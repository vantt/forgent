## Decisions made inside the frame (not reopening anything)

- **D-T1-1 Creation mark at lock time.** The door captures the full `CreationMark` (`ticks`, `last_pid`, `at`) inside `lockFd`, after Node's open and before `flock`. For a Node process this is equivalent to the crate's mark-before-open: Node opens close-on-exec and never forks without exec, and a description reaches another process only through `runBorrowed`/`spawnWithLocks` after `acquired`. The mark pair (`since`) lives in the opaque lock External the door returns; no `reachFloorTicks` crosses the door and the per-directory cache goes (RT-M4).
- **D-T1-2 The lock External.** `lockFd` returns a typed N-API External that owns a duplicate of the description (as the Git loan does, `port.rs:311-340`) and the `since` marks; Node keeps its own fd for stdio mapping and close, stores the External beside it in the private WeakMap, and passes it to `drainChild`, `releaseFd`, `clearDomain` and `mintGitLoan`. The External never escapes the facade; disposing it closes only the duplicate. The External's Rust type lives in the holder-lock crate (`port::NodeLock`), so the private `since`/`proven_alone_at` machinery (`port.rs:232-249`) is reused, not re-exported; the addon file only marshals. **Capability guard (red-team security F1):** like the Git handover (`packages/git/node-addon/src/git/handover.rs:1-19`, `takeGitHandover` once per worker thread), the namespace exposes `holderLock.take()` once; `lockFd`, `drainChild`, `releaseFd`, `clearDomain` require the capability the facade consumed in `driver.mjs`, so no other module in the process can mint a lock External from an fd number, and the spec's trust-boundary paragraph (`holder-lock/spec.md:123-126`) stays true. One architecture test mirrors the Git one. Rejected alternative: a plain `{ticks, lastPid, atNs}` object carried by Node and passed back; it would need `CreationMark::at` (`Instant`) to become a wall-clock or monotonic number in `fgos-process` (T0's crate) and would hand the marks to any caller; the External is the pattern already in the addon.

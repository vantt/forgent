Depends on phase 05 (parse, `to_json`, guard). Does not need edits (06) or the seal (07). Suggested executor: sonnet. One commit (L10): consumers, both lock files, the ignore line.

## Steps

1. Facts per consumer before editing (re-verify with `rg`): the typed manifest struct's `String` fields versus real YAML values (does any real manifest hold a number-looking scalar for a `String` field, which `serde_yaml` coerces and `serde_json::from_value` rejects?), and whether any real input uses anchors, tags, or duplicate keys. Inputs: every manifest under the repo and test fixtures (`rg -l "operations:" -g '*.y*ml'`), flow definitions the harness scans (`packages/observe/rust/tests/harness_protocols_test.rs` fixtures and `core`/`domains` flow files), `docs/contracts/fgos-gateway-api-v1.yaml`. Scratch differential: old call vs new call on each file, compare the typed result or the extracted fields. Any difference is resolved by fixing the input (quote the scalar) or by a deliberate behaviour note; never by adding a deserializer mechanism (idea candidate if needed, reported not built).
2. Run impact analysis on `ExternalManifest::from_yaml_str`, `extract_protocol_id_from_file`, `extract_operations`, `search_contract` (callers and processes) if the tool is present; else `rg` callers and list them (count with file:line).
3. host-runtime: `from_yaml_str` calls `fgos_yaml_doc::parse(yaml.as_bytes(), Profile::Tool, "<manifest>")`, then `to_json`, then `serde_json::from_value`; map the refusal text into `ManifestError::MalformedYaml` (text contains rule, file, line, column, no value). The raw-digest line stays. Test at `:399` parses via the crate and `from_value`.
4. observe: parse with `Profile::Tool`, `to_json`, same `.get(...)` chain on `serde_json::Value`; any refusal returns `None` as before (the function is best-effort by design).
5. gateway: `search_contract` parses with the crate; the error string `could not parse {} as YAML: {err}` keeps its shape. The crate is a path dependency (`../../packages/yaml-doc/rust`) like the other path deps (`apps/fgos-gateway/Cargo.toml:80-83`); if layout (a) used `[patch.crates-io]` in the root workspace, the gateway has its own `Cargo.lock` and is excluded from the workspace, so the same `[patch]` lines go into the gateway manifest too (verify by `cargo tree -p fgos-gateway` showing the path source).
6. `cargo update -w` is not needed; run `cargo build --locked` after cargo rewrites the locks once (`cargo metadata` or `cargo build`), then confirm `serde_yaml` and `unsafe-libyaml` are gone from both locks.
7. Delete the `ignore` line in `.github/cargo-deny.toml`.
8. CHANGELOG: only if step 1 found a user-visible difference (a manifest that parsed before and is refused now, e.g. it carried an unknown tag); then one line under `## [Unreleased]`.

What is already done (`6f98ce04a`): the owned-name set and the one filter `ownedSkillDirs` (`skill-wrappers.mjs:177`, whose JSDoc names "a generated-stamp refusal for a same-named folder" as the place Q3 (b) belongs), `renderSkillSurfaces` (`:1401`) computing the owned set and instruction projection before the first write. The lead decides by reading both and reports which.

## Requirements

1. **One copy leaf.** A single function (lstat each entry; a symbolic link anywhere in a source or target path is refused by name with the path and the one-line remedy) used by all four sites: `copyDirRecursive` (`:336`), `atomicCopyFileSync` (`:78`), `copyAssembledFile` (`:1202`), `carriesAssembledHeader` (`:1223`, `statSync` -> `lstatSync`). Callers of `copyDirRecursive` to move or keep: `:226`, `:372`, `:1113` (deleted by P01 if Gemini-only), `:1295`, `:1378`; list the survivors with `file:line` in the report. A dangling link no longer aborts the orphan prune half done.
2. **Fixed point.** After copying an owned skill dir, remove files the source lacks (inside that dir only). `mirrorDevSkillsIntoPlugin` (`:366`) removes `plugins/fgOS/skills/fgos-*` dirs whose name is absent from `.agents/skills` (names from the owned set, never a non-`fgos-` dir: the plugin's 39 hand-authored commands are not touched). A second render over an unchanged tree writes nothing.
3. **Anchored stamp.** One check for "is this generated file ours": the marker must be the first non-blank line after the frontmatter of a wrapper `SKILL.md` (`generateWrapperContent`, `:125-140` writes it there); the assembled header must be the first line after the frontmatter of an assembled `.md` (`withGeneratedHeader`, `:1194`). Replace `includes` in `isGeneratedWrapper` (`:147-153`) and `carriesAssembledHeader` (`:1230`). **Every form a release ever wrote is accepted** (RT-1): run `git log -S"This is a generated thin wrapper" -- src` and `git log -S"Generated by fgOS skill assembly" -- src`, list the earlier forms, one fixture per form.
4. **Same-name refusal (Q3 b).** In `ownedSkillDirs` (the one filter), for a target dir that exists: it is written only if it carries the stamp (the anchored check of requirement 3) or holds no files; otherwise refuse by name, with the dir and the remedy ("remove it, or rename the other skill"), before any write of that run. A refusal is computed in the same compute-first step as the owned set, so a refusal leaves the tree untouched. A source dir not yet present in the target is simply written.
5. **Setup copy filter from the package root.** In `materializeSkillsIntoProject` (`:1353`), the dirs copied from `sourceAgentsSkills` are filtered by `ownedSkillNames(packageRoot)` alone (not the union with `targetRoot`, `:1357`); the union stays only for the wrapper step that writes the target's own surfaces. Test: a package skill whose name equals the target's own core skill never overwrites it.
6. **One `skillSourceRoots`.** The duplicated core-then-domains walks left after P01 (`discoverCanonicalSkills`, `discoverSharedFragments`, `assembleSkills`) take their roots from one function.
7. **Drift-guard message.** The guard in `skill-wrappers.test.mjs` (the one that says "run `npm run build:skills`") names the `.gitignore` cause when the missing render is ignored (`git check-ignore`).
8. **Budget.** `wc -l src/setup/skill-wrappers.mjs` ≤ 780 after this phase. If the added checks keep it above, continue the cut inside the file (helpers with one caller, comment blocks that restate code) until it holds, or report `DONE_WITH_CONCERNS` with the measured gap. No function over 130 lines (`generateAllSkillWrappers`, `assembleSkills`, `materializeSkillsIntoProject` are the candidates; scan with the function-length script).

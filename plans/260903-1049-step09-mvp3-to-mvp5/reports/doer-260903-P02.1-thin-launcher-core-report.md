# Doer Report — P02.1 Thin Launcher Core (MVP4 R1-R4)

## Summary

Built a thin, mechanical CLI/module surface (`fgos coordination
launch-master-loop`, backed by `src/verbs/coordination/launch-master-loop.mjs`)
that accepts a plan/artifact path + objective + writer id and composes a
validated `standalone-master-coordination-loop` request covering ONLY the
fixture's required first pass (produce/review/red-team) — never an
authorize/disposition/revise/recheck step. It calls the existing
`runCoordinationUseCase` door (the same one `fgos coordination run --file`
and the headless adapter already use) and nothing else — no engine internals
touched.

## Design notes worth flagging to Review/Red-Team

1. The launcher deliberately emits ONLY the fixture's `required` first-pass
   operations. It never authorizes or dispositions anything — R2's "no
   hidden actor/operation choice" is satisfied by construction, not by a
   runtime check.
2. Because `fixer` is a required `SessionActor` on the session manifest
   (all 4 fixture actors are, per `openDeclaredProtocolSession`) and
   `revise-candidate` (fixer's only operation) is driver-authorized, a
   first-pass-only launch structurally cannot self-close to `completed` —
   it correctly reports `closed:false` with a `closeRefusalReason` naming
   `fixer`. This is proven directly in the live end-to-end test and is the
   expected, honest behavior of a non-choice-making composer, not a defect.
   Progressing further requires a hand-composed follow-up request against
   the same `coordinationId` — which needs the "resume door" that does not
   exist yet (P02.2/MVP5 territory, already named as a gap by the
   predecessor track).
3. `expectedFixtureVersion` and plan-path-existence are the ONLY two new
   validation checks added anywhere in this cell; every other R4 negative
   case (unknown fixture id, Work fields, missing objective, invalid
   bounds, forbidden context ref) is proven via the EXISTING `schema.mjs`/
   `run.mjs` checks, unmodified — see P02.1.md §5 for the explicit
   reuse-vs-new breakdown the cell brief asked for.

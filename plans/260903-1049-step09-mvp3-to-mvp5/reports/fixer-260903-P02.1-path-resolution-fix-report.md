# Fixer Report — P02.1 `--plan` path-resolution fix

## Finding fixed

Red-Team's accepted MEDIUM in `docs/architect/agent-coordination/verification/step-09-mvp3-to-mvp5/P02.1.md`
(`## Red-Team (Independent)`): `--plan`'s relative-path resolution in
`launch-master-loop` resolved against `repoRootForCoordination`
(`--dir`-derived) instead of `process.cwd()`, unlike the sibling
`run --file` sub-verb — causing a real, existing `plan.md` in the caller's
own cwd to be falsely rejected as "does not exist" whenever `--dir` named a
different repo root.

## Root cause

- `bin/fgos.mjs`'s `run` branch resolves `--file` eagerly:
  `path.resolve(process.cwd(), filePath)` (before this fix, line 3131).
- `bin/fgos.mjs`'s `launch-master-loop` branch passed `flags.plan` raw into
  `launchMasterLoopUseCase`; `assertPlanPathExists` in
  `src/verbs/coordination/launch-master-loop.mjs:53` then resolved it via
  `path.resolve(ctx.cwd, planPath)`, where `ctx.cwd` is
  `repoRootForCoordination` (the `--dir`-derived root), not the invoking
  shell's cwd.

## Fix

Mirrored the exact `run --file` resolution point in `bin/fgos.mjs` (one
line, no new helper, no change to `run.mjs` or `launch-master-loop.mjs`):

Before:
```js
const planPath = requireField(flags.plan, 'coordination launch-master-loop requires --plan <path>');
```

After:
```js
const planPath = path.resolve(process.cwd(), requireField(flags.plan, 'coordination launch-master-loop requires --plan <path>'));
```

`planPath` is now already absolute by the time it reaches
`launchMasterLoopUseCase` → `assertPlanPathExists(planPath, ctx.cwd)`, and
`path.resolve(ctx.cwd, absolutePath)` returns the absolute path unchanged
(Node `path.resolve` semantics), so `launch-master-loop.mjs` needed no
change — it behaves correctly for both the with- and without-`--dir` cases
without any internal modification.

## Regression test added

`test/verbs/coordination-launch-master-loop.test.mjs` — new test:
`CLI: a relative --plan resolves against process.cwd(), not --dir's repo
root, so a real file in the caller's cwd is found`.

Reproduces the Red-Team's exact scenario: two separate `tmpCwd()` roots
(`callerCwd` with `plan.md` written into it, `otherRepoRoot` passed via
`--dir` and holding the fake executor config since
`repoRootForCoordination` becomes `otherRepoRoot`); the CLI is invoked with
`cwd: callerCwd` and a relative `--plan plan.md` plus `--dir otherRepoRoot`.
Before the fix this failed with `plan/artifact path "plan.md" does not
exist (resolved to "<otherRepoRoot>/plan.md")`; after the fix it succeeds
(`status 0`) and dispatches the expected produce/review/red-team steps.

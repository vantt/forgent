# Phase 04 - Production Skill And Decision Dialogue

Depends on: Phase 03 hard shell and registered protocol closed.

## Objective

Project Phase 01's proven operating intelligence into the production
`fgos-architecture-panel` skill, role task prose, examples, and recovery
guidance. The skill must make the hard protocol feel like a capable consulting
group rather than expose a user to a coordination harness.

## Cells

### P04.1 - Production skill and projections

Author `core/skills/fgos-architecture-panel/SKILL.md`. Use the repository's
assembly mechanism to produce `.agents/skills/fgos-architecture-panel/SKILL.md`,
then run `npm run build:skills` for `.claude` and plugin projections. Never edit
generated projections independently. The installed skill must contain enough
Phase 01 doctrine for a fresh agent to operate well; a link-only shell fails.

### P04.2 - Surface, examples, and dialogue

First prove whether `fgos-group-thinking` plus `fgos coordination run/show`
already provides the required entry/resume path. Add a use-case or CLI verb only
for an evidenced ergonomic or provenance gap. Create
`docs/how-to/use-fgos-architecture-panel.md` and the example families below.

## Requirements

- The entry accepts raw intent, including short and ambiguous input. It never
  requires the person to author a problem brief or select a protocol.
- The skill carries the advisory doctrine, phase judgment, role posture,
  question discipline, debate behavior, synthesis style, explanation standard,
  and Decision Dialogue behavior proven in Phase 01.
- Each role packet says what to notice, how to reason, what evidence to seek,
  when to change position, how to communicate uncertainty, and what failure
  posture to avoid. Expected outputs alone are insufficient.
- The skill selects or accepts an explicit per-role safe
  executor/confinement/tier/persona roster, explains the cognitive purpose of each
  binding, and forwards it unchanged through governed dispatch. It never
  collapses the panel to one session-wide provider or silently defaults every
  role to the same model when alternatives are configured.
  It reports the model derived from executor/providerModel + tier and never
  emits `actors[].model` unless Phase 03 has implemented and documented that
  general declared-protocol capability.
- The lead advisor builds a provisional understanding and scouts first. It
  asks only when a material gap is truly user-exclusive, presents reasoning
  before asking, consolidates questions, and states its current default.
- Independent shapers produce genuinely selectable alternatives. Critics
  attack claims. Synthesizer recommends without flattening dissent. Red-team
  attacks framing and advisory quality as well as technical correctness.
- Decision Dialogue supports clarify, challenge, introduce-context,
  request-alternative, request-composition, and decide. It explains impact to
  the person before selectively reopening work.
- A fresh session can resume from durable artifacts and a concise orientation
  packet without reconstructing chat or rereading raw logs.
- The surface invokes the registered protocol through existing doors and never
  reimplements authority, visibility, aggregation, bounds, or replay.
- Include worked clear, unclear, challenged, revised, composite, no-consensus,
  and decision-deferred examples showing good prose, not only request JSON.
- Include a heterogeneous example with independently routed shaper,
  alternative, critic, synthesizer, and red-team roles, plus a homogeneous
  fallback for hosts with only one configured provider while retaining separate
  assignments and fresh role contexts.

Example families: clear start, unclear start, consolidated Decision
Request/resume, clarification/challenge, material-context reopen,
alternative/composite reopen, and final decision/defer. Each pins the protocol
id and shows explicit per-actor routing without pinning it in FlowDefinition.

## Tests And Review

Mechanically test skill installation/projection, request compatibility, resume,
and all hard refusals. Evaluate prose with scenario-based golden rubrics rather
than brittle exact-string snapshots. Reviewer and Red-Team must assess both
hard correctness and loss of soul: premature questions, shallow reframing,
straw alternatives, performative debate, hidden dissent, evasive recommendation,
and explanations written for the system instead of the person.

Run `npm run build:skills`, located projection tests, the focused command from
`plan.md`, relative-link checks, and full `npm test` after P04.2. Add a
`CHANGELOG.md` Unreleased entry for the public capability and render long docs.

## Exit

A person can invoke one named capability and receive the same or better
consulting behavior as the Phase 01 manual playbook, now with hard visibility,
provenance, bounds, replay, and resume underneath it.

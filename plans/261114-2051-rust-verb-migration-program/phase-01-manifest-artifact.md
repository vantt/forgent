## Context

- Today the manifest is built at run time by `publicManifestEntries()` in `bin/fgos.mjs:3825` and printed by `handleHelp` (`bin/fgos.mjs:3986-3989`) as `JSON.stringify({schema_version: MANIFEST_SCHEMA_VERSION, commands}, null, 2) + '\n'`.
- The generator `scripts/export-command-selectors.mjs` already writes `packages/host-runtime/contracts/command-routes.json` atomically (375-377) and checks drift (`checkCommandRoutes`, 381-435); `test/rust-host/command-routes.test.mjs` runs the check.
- `src/cli/command-registry.mjs` is pure data (kernel tier 9 row but imports nothing); it already exports one pure helper (`declared`, line 101).

## Requirements

1. One projection: move `publicManifestEntries` into `src/cli/command-registry.mjs` as an exported pure
   function (for example `publicManifest()` returning `{schema_version, commands}`); `bin/fgos.mjs` uses it
   and keeps no copy. No other change to the registry.
2. The generator writes `packages/host-runtime/contracts/command-manifest.json` in the same run as the
   routes file, bytes = `JSON.stringify(publicManifest(), null, 2) + '\n'`, with the same atomic write
   helper (factor the tmp+rename into one local function used for both files; do not copy it).
3. `--check` fails when either file drifts, naming the file.
4. The generated bytes equal the pre-change `node bin/fgos.mjs --help --json` stdout (phase 00 recorded
   its SHA-256). Record the comparison in the report.

## Measurements (release host, 30 runs after one warm-up, machine load about 2)

From `/tmp` (no repository): `--help --json` 4.2 ms median; `add --help` 7.0 ms; `config show --json` 13.0 ms (a no-project refusal, exit 1); `version` 12.4 ms.
From this worktree (a repository with a store): `--help --json` 4.6 ms; `add --help` 6.9 ms; `config show --json` 24.6 ms; `version` 77.9 ms. Phase 00 baseline for the dev-staged legacy-routed help was about 2.3 s per call; phase 02 measured `config show --json` at 28.9 ms. Exit criterion 1 (help within 5 ms of `config show --json`): met, help is about 20 ms below it.
Open finding: `fgos version` inside a repository costs 78 ms and starts 15 processes (strace: two bwrap probes, then bwrap plus git for `var GIT_CONFIG_*`, `config --list`, `rev-parse --show-object-format`), the full Git open path, not the disk-only root read. Other store-less native verbs measured from the same directory: `identity` 12.5 ms, and `gate-bypass show`, `convention`, `mailbox list` exit 4 early at 4 to 8 ms (arguments not given). I did not run `version` on the pre-F0 base, so I cannot say whether the cost is new; the verb routes through `distribution.build.show`, whose root choice is still the debt entry `packages/distribution/rust/src/workspace.rs` of the `doors` row. Recommend an A/B on the base before landing; not fixed here (outside phase 11).

## Lessons

- A decision-history entry written from memory of the plan can state a wrong reason; the twin rationale was corrected against the phase files before commit.
- `check-decision-citation-drift` keys its baseline on line text: rewriting a baselined line needs the key updated, and `--write-baseline` run in a worktree is not safe.
- Retiring a CLI case whose claim is a declaration needs the vector row first; three verbs (`topic`, `doc`, `return`) had no row, so they were added before the cases went.

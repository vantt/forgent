## Where the facts and Node differ from the phase text

The contract is Node's actual `src/cli/parse-args.mjs`, so the phase text was corrected in three places:

1. No `--k=v` form exists in Node. `--dir=/x` is a flag named `dir=/x` (and takes the next token as value if it does not start with `--`). Rows pin this for `--dir=`, `--dir=/x`, `--opportunistic=false`. Phase 08 must not read `--dir=` as a `--dir` value through this parser.
2. No `-h` handling in `parseArgs`: `-h` is a positional (or a value after a valued flag). Help detection is `rest.includes('--help'|'-h')` in `bin/fgos.mjs` main, outside the parser. Phase 02 owns that helper.
3. Repeated flags: last wins, except `context-ref` and `param`, which collect every use into a list (`REPEATABLE_FLAGS`). Rust mirrors the two names in `REPEATABLE_FLAGS`; a row pins each.
4. Also pinned: `--json start` makes `start` the value of `json` (a flag before the sub-verb swallows it), which is why phase 03/08 need store declarations that read the sub-verb from positionals only when the flag is not valued; a flag named `__proto__` is silently dropped in Node (JS no-op), and Rust drops it too. `--` alone is a flag with the empty name.

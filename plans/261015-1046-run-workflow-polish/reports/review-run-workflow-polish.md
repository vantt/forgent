## Not issues (verified)

- **Unit `timeoutMs` wins in workflows.** `unitData` carries `u.template.timeoutMs` (runner.mjs:545). `unitOverridesOf` skips the override. Test asserts `provenance.timeoutMs.source === 'unit'`.
- **Resume refuses `--timeout`/`--account`** (bin/fgos.mjs:2311-2312). Values re-project from events; `effort`/`timeoutMs`/`account` defaults handle `undefined` state fields.
- **Outcome keys.** Every key in the new table is emitted somewhere:
  - by `runUnit`: `policy-refusal`, `provider-limit`, `execution-failure`, `partial-writes`, `blocked`, `findings`
  - by the workflow: unit outcomes plus `findings`
  - `failed` (to 1) is only a projection default; every current `workflow.fail` emitter sets an outcome.
- **Rust host and gateway.** `apps/fgos/src/legacy_exec.rs:385` passes the child exit code through. The gateway's MCP surface does not expose `run`/`workflow`.
- **Doctor check has no side effects.** It is dry: `simulateUnitBindings` → `bind()`, reading only the backend registry and PATH. Its herdr dependency follows the doctor process env (`detectHerdrPresent`), the same as a run from that shell.
- **Repo rules.** No env switch was added for tests. `RUL99` references in code follow existing repo convention. `subcommand-flag-drift` passes.

Status: DONE
Summary: The exit-code change breaks 3 existing CLI tests. `--account` can fail a whole mixed-provider workflow mid-run, and only an empty id is refused at start. `workflow status` and the inline handoff get non-zero exits. The posture check's read-only/workspace-write split is dead logic backed by mock-only tests, and it hard-fails fresh projects that the existing check only warns about.

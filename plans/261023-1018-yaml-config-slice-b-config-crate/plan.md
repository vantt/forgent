## Outcome

1. Crate `fgos-config` (`packages/config/rust`, contracts `packages/config/contracts/`) answers, in Rust only: what is the effective value of every key and where did it come from (snapshot), is this file legal (JSON Schema validation by the validator crate, scope rules, file rules), and what are the exact bytes after this one change (write transaction with compare-and-swap, comment grammar, writer class).
2. The standard exists as data in two kinds of file (owner 2026-10-23 11:45): section schemas (JSON Schema draft 2020-12 authored as YAML, shape and meaning only, five `x-fgos-` annotations, no `default`) at `core/config-schema/<section>.schema.yaml`, and section standards (the release's standard values, a normal config file in the `@fgos:` format validated by the schema like a project file) at `core/config-standard/<section>.yaml`; both bundled into the crate, linted, and the runner standard authored from this repository's tuned catalog; a pinned equivalence proof shows "standard files + differences" reads back as this repository's effective config.
3. Locks `project-config` (repo) and `global-config` (machine) are registry rows with Rust pin tests.
4. The spec states the settled facts: the Holder-lock bootstrap section is the settled fact (the reader it described was deleted), the registration count and `sectionOf` copies are corrected, and section 4 is JSON Schema. These spec edits were made on 2026-10-23 with the owner's decision; phase 14 only verifies and records the landing.

Non-goals (Slice C): native-door `config` namespace, Node facade, moving any reader or writer, deleting `src/config/` or the write-on-read, the real PATH detector for `runner.executor`, resolving the main checkout root, deciding who is "confined", `fgos config` verbs, `.githooks/pre-commit` check. Non-goals (Slice D): migration, tombstone, backups, doctor checks and fixes, the text renderer of the standard file and `refresh-docs`, `~/.fgos/private` creation by setup, gate G6. Nothing in Slice B is linked by an existing consumer; shipped behaviour does not change.

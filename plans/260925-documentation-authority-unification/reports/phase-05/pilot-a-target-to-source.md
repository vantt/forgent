# Pilot A: Target-To-Source Conservation Audit For host-invocation-routing

## Method

Scope: all 191 heading units (anchors not starting with `unheaded-block-`) of the 33 markdown files under `docs/platform/host-invocation-routing/`, listed with `anchors.mjs`. Each heading was read together with its section body, then matched against the unit-by-unit TSV of the six legacy sources in `docs/architect/host-invocation-routing/`. Evidence cites the legacy file, the line range of the matched unit, the source anchor, and the first 8 hex characters of its claimId (`claim_xxxxxxxx`). Code-derived rows cite repository paths that were checked for existence and, where stated in the note, grepped for the specific symbol or test name. Commit hashes come from `git log` on the target file only; every target file first appears in commit 05b6bf861 (2026-09-14, the migration commit), so only later commits prove post-migration additions.

Classification conventions applied uniformly:

- H1 of a content document takes the class of the legacy section it renames; H1 of a portal or directory index is navigation; the two rollout-plan files are redirect stubs and are navigation.
- `Implementation Alignment` sections are code-derived: the design-claim column restates source claims, but the status, evidence and gap columns come from code and proof records (the cited source anchors are listed as secondary evidence).
- Rules in portal documents (`2. Rule` in directory READMEs) are source-derived only where a plan exit gate or responsibility table in documentation-standardization-plan.md states the same idea; they are flagged moderate confidence.
- Route-matrix counts quoted by the target (73 selectors, 71 legacy-cli, two native) are stale against the current code (packages/host-runtime/contracts/command-routes.json now lists 72 selectors: 68 legacy-cli, 4 native); this is noted on affected rows and is not a classification issue.
- Blindness: the files `history/source-inventory.md`, `intent-preservation-ledger.md`, `verification/source-preservation-audit.md` and `verification/implementation-alignment.md` were not opened; their headings are `unproven` with a heading-level inference in the note.
- Mapping is kept in `mapping.mjs` (scratch) and this table is generated by `build.mjs`, which fails on any unmapped heading, any mapping without a heading, and any unresolvable source anchor.

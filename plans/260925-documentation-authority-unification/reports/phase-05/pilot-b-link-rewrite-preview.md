# Pilot B Link Rewrite Preview: Work State Inbound References

Preview of what each inbound reference to `docs/specs/work-state.md` and `docs/io-contract.md` becomes when the two legacy documents retire in favor of `docs/platform/work-state/`. Read-only analysis: no consumer file was edited. Tables and counts are generated by script from the doc inventory and the frozen map ([pilot-b-target-map.md](pilot-b-target-map.md) sections 3 to 5).

## 1. Method

- **What changed since the first run.** The inventory was regenerated (commit `2d0d67838`), which raised the edge count from 780 to 1130 because the plan and report files written since then cite the two documents (all immutable history). The classifier, the map parser and the extraction rules are unchanged from the first run; only the commit used for `git show` was updated. The acceptance criterion was redefined by the owner: every edge is classified, and every rewrite-class edge either has a document-level target or sits in the owner-judgment queue with a reason; anchors are proposed only where derivable, with no percentage bar.
- **Edge set.** Every entry of `consumerEdges` in the inventory (commit `2d0d67838`) whose `targetPath` is `docs/specs/work-state.md` or `docs/io-contract.md`: **1130 edges** (901 to work-state.md, 229 to io-contract.md). Of these, the 72 `pattern` edges of the docs and code classes are glob edges whose `resolvedTarget` is a pattern (`docs/**`, `docs/specs/*.md` and similar) that merely matches the file; they stay in the counts but carry status `pattern` because no literal reference exists to rewrite.
- **Text of each edge.** The inventory edge holds consumer `path`, `line` and `kind` only (no anchor). The consumer line was read at the inventory commit (`git show 2d0d67838:<path>`) and the literal reference was extracted by regex (path, relative prefix, `#anchor` or `:line` suffix). Lines under `.fgos/` are not tracked in git and are classified by location only.
- **Classes by consumer location.** (1) immutable history: `plans/`, `archive/`, `docs/history/`, `docs/decisions/`, `.fgos/` and any consumer the inventory marks as `history-evidence` corpus; alias only, never rewritten. (4) shipped or generated: `core/`, `domains/`, `.agents/`, `plugins/`, `.claude/`, and generated files (`docs/doc-registry.*`, `docs/enduser-docs-index.json`, files the inventory marks `generated`); no rewrite now, handled by the consumer-preparation phase. (3) code and tests: `src/`, `apps/`, `scripts/`, `test/`, `packages/`, `dogfood-fixture/`. (2) docs: every other path (docs/**, README and so on).
- **Heading to target.** Old anchor to heading: the inventory `githubAnchor` list of the source (heading counts matched: 117 and 11) paired with the heading line found by scan. Heading line to target: the map row (sections 4 and 5) whose source line range holds the heading. The proposed anchor is exactly the frozen target anchor of that row.
- **Status values (docs and code classes).**
  - `anchor`: target and anchor proposed from evidence in the consumer text. Basis is either the old anchor of the link (`old anchor`) or, for bare paths, a nearby (within 60 characters) quoted source heading text or a `RULn` id whose definition line sits in one mapped section (`inferred`).
  - `doclevel`: bare path with no section cue. `io-contract.md` goes to `contracts/cli-io-contract.md` (all 41 source rows map to that one document). `work-state.md` goes to the portal `README.md` only when the line is a pure pointer (at most 2 words besides the path, no section or rule cue, docs class only).
  - `judgment`: `needs owner judgment`; the reason is quoted. Always used for line citations (`work-state.md:886` style; source line numbers drift, example: line 1045 is the answer verb, while the citing text names RUL10, now at line 1169), for a bare path in a topical sentence (the claim owner is not identifiable by script), for a path literal in code or tests, and for an old anchor not in the map.
  - `pattern`, `retire-with-source`, `candidate-pointer`, `switchboard`: not link rewrites; see section 3.
- **Relative links.** When the consumer wrote the path relative (`../../specs/work-state.md`) the proposal is relative too; otherwise repo-relative.
- **Proof coupling (code class).** Flag `proof` when the consumer is under `test/`, or the edge kind is `executable-proof` or `fixture`, or it is a ratchet or shipped-path script that keys on the path. A test that asserts or reads the old path is coupled to the proof: rewriting it changes what the proof checks, so it moves together with its test.

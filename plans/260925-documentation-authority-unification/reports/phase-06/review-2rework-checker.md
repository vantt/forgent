## 1. Evidence-payload ownership exemption (a207f4266)

A10 wording: the always-fatal rule that rows sharing a semanticClaimId name one distinct owner does not apply to rows whose target is of kind evidence-payload (canonical false); each legacy evidence file, including the 48 mirrors and the four raw logs, binds to its own same-path copy; for every canonical kind the rule stays always fatal; record it as an additive constitution/vocabulary amendment with evidence; change the checker tests first; no other exemption.

- Implementation: validateSemanticClaimOwners(claimLedger, constitution) skips a row only when classifyPath(row.targetOwner, constitution).kind is exactly 'evidence-payload' AND the constitution still declares that kind canonical === false. The exemption therefore keys on the target kind, not on the source kind, the claim kind, provenance, review status or disposition. Canonical kinds (spec, contract, architecture, decision, verification, vision, vocabulary, governance, portals) and the other noncanonical kinds (proposal, history, roadmap, generated, knowledge, unknown or ambiguous placements) are still counted and still fatal. Flipping canonical to true on the kind switches the exemption off (tested).
- Single implementation: the only call site is checkConservation (default constitution loaded from DEFAULT_CONSTITUTION_PATH, cached for the process); the retirement gate's one-owner-per-semantic-claim check consumes the same finding type, so there is no second, unexempted copy of the rule. I ran the repository classifier over all 867 physical carrier targets and over all 12,878 Mirror rows of the script-proven population: every target is evidence-payload; verification/README.md classifies as collection-index and verification/implementation-alignment.md as verification, so canonical files in the verification tree stay under the rule.
- Tests first: red commit cd5052f74 has two tests. Run on the extracted tree at cd5052f74, 35 tests, 34 pass, 1 fails (the positive test: two evidence-payload carriers sharing a semanticClaimId must not compete; the failure message is the expected semantic-claim-multiple-owners finding). The second test is a guard (canonical verification/*.md targets, proposals and history targets, a mixed set, and a constitution whose evidence-payload kind is flipped to canonical must all stay fatal); it passes on the old code by construction and is meaningful only against the new code, where mutation testing shows it bites (below). At a207f4266 the two files check-doc-conservation and doc-decision-mirrors pass 40 of 40; the previously evidence-path duplicate-group test was rewritten onto canonical contract paths, so the canonical one-owner rule keeps its own test.
- Amendment: v2.5-001 is additive in both records (vocabulary minorVersion 5 with an amendments entry; constitution amendments entry plus a Markdown section and a vocabulary Markdown paragraph), cites owner decision ea33f3d30 and the same-path-binding evidence, and says no enum, disposition definition, allowed class or authority flag changes; the diff confirms only insertions in those files.

## 2. Reverse closure by committed classification receipt (a63b50749)

A10 wording: a reverse-open candidate unit closes only with a committed classification receipt that an independent review report accepted, only for the classes candidate-native navigation, structural frame and bookkeeping; the receipt names the unit digest, class, reviewer report and pin and is equivalent to an Added in candidate label; units without such a receipt stay open; tests first; no other closure path.

- Implementation: acceptedCandidateClassifications builds a set of claim ids, and unreferencedCandidateRows removes exactly those ids from the open set (the only edit to the filter). A reference counts only if all of the following hold, each read in the code: reviewStatus is reviewed and the report is not checkpoint-named; the receipt path matches the fixed ledger pattern and the receipt commit is a 40-hex ancestor of the inventory commit; the receipt JSON is read from the committed blob at that commit (a later working-tree rewrite is ignored, tested); exactly one receipt for the claim id; class is one of the three allowed; path, anchor and unitDigest equal the claim-ledger row and a unit with that anchor and digest exists in the tree; shownText equals the unit's rendered section payload and shownTextDigest equals its sha256; authors (receipt row, receipt file, shard) are non-empty, not script-authored and differ from the reviewer's session (date-insensitive), and the receipt file and the shard name the same author session; the committed report header Reviewer, the report author and the Receipt commit header equal the reference, the receipt file author and the receipt commit; and the committed report holds a six-cell row whose claim, class, verdict ok, unit digest, shown-text digest and note equal the receipt and the reference note. Pending, uncommitted, changed, non-accepted or wrong-class cases leave the unit open (sixteen parameterized cases plus payload, ancestry and checkpoint cases).
- Not a new closure route: reverseEnabled is also switched on when a shard carries candidateClassifications (stricter, not looser), the loader now rejects a non-array reference list, the schema addition forbids additional properties, and repoRoot is plumbed so that a call without a repository can never close a unit.

## Observations (Low)

1. The receipt-commit ancestor guard is not pinned by a test: the 'pins must be ancestors' test fails for another reason (the report's Receipt commit header no longer matches). A receipt commit that exists in the repository but is not an ancestor of the inventory commit would be rejected by no test. Suggest a direct test.
2. The class truth is by design a human judgment: the gate verifies who accepted which digest and text, not whether a unit is really a frame. In this pass about half of the proposed receipts do not survive that judgment (review-2rework-classifications.md), so the channel works as intended only if the reviewer applies the class definitions strictly.
3. Because evidence-payload is classified by location alone, the exemption also covers Markdown receipts below a verification set directory (for example P08.2-red-team.md), not only logs and JSON. This follows from A10 and plan section 3 item 10; the control that remains is the identical-unit exception table. The default constitution is cached per process in ownerConstitution, which is fine for a single run.

2. What kind of work is this?

3. What contract does it touch?
   - The documentation governance contract (candidate copy at `docs/platform/governance.md`, whose own header says it is `Canonical: No` and "Replacing the current legacy governance authority" is not its use; the switchboard names `docs/doc-governance.md` as the active governance owner: `docs/platform/documentation/switchboard.md#2-area-authority-routes`, Documentation system row, and `#3-root-document-routes`). It must follow metadata discipline (`docs/platform/governance.md#5-metadata`: required baseline fields, Design status, Implementation) and declare itself candidate/proposed (`docs/platform/migration-authoring-rules.md#3-authoring-new-platform-documentation`, item 2). Also: one H1, numbered sections from H2 (`docs/platform/governance.md#10-writing-method`); renderable body links for `Related:` entries (`#11-linking-discipline`); and the component-boundary check or an explicit "No component-boundary change" note if ownership shifts (same anchor).
   - Findability: the proposals index is itself a candidate whose "active list is historical source wording" and whose "navigation owner owes reviewed update" (`docs/platform/proposals/README.md#unheaded-block-2`). The switchboard lists the authority route per area (`docs/platform/documentation/switchboard.md#2-area-authority-routes`); a proposal does not take a row of its own as owner.
4. How much risk?
   - Low for the file; moderate for authority confusion. The migration docs call out dual-authoring and authority-by-path as the main failure (`docs/platform/documentation/switchboard.md#1-operating-invariants`). Because the proposal crosses areas, each affected area's owner must be named; do not copy owner prose into the proposal. Hand edits to legacy index files require a reviewed exception (`docs/platform/migration-authoring-rules.md#2-legacy-roots-ratchet-and-exceptions`, items 2-4).
5. What proof means done?
   - The reviewable checks the files describe: the legacy ratchet passes (`scripts/check-legacy-docs-ratchet.mjs`, named in `docs/platform/migration-authoring-rules.md#4-related-files`); links resolve and use relative markdown links (`docs/platform/governance.md#11-linking-discipline`); header status is explicit (Design status/Implementation) so a reader can tell it is a proposal; the proposals index and the area portal(s) link to it. I found no in-scope statement of a specific test command beyond the ratchet.
6. What learning gets left behind?
   - A proposal records options and trade-offs only. When accepted, extract the settled design into the right canonical document and leave the proposal as history (`docs/platform/proposals/README.md#unheaded-block-5`); promotion targets by type are in `docs/platform/governance.md#7-discussion-scratchpad-workflow`. Record candidate impact in the migration ledger or phase notes (`docs/platform/migration-authoring-rules.md#1-core-principles`, item 4) and preserve simplified or deferred intent in the ledger (`docs/platform/governance.md#8-intent-preservation`).

What a proposal establishes: open questions, alternatives, evidence, provisional reasoning. It does not establish current behavior, binding rules, settled decisions, or implementation approval (`docs/platform/governance.md#4-authority-matrix`; `docs/platform/proposals/README.md#unheaded-block-5`).

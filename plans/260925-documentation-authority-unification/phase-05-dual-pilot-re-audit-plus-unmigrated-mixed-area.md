> Legacy numbering: this was **Phase 04** in the original plan. Git tags, branch names, assignment ids and the historical artifacts under `reports/` keep the legacy number.

## Overview

**Status:** `in-progress`, authorized by the owner on 2026-10-06 (decisions recorded in `plan.md` §7.5b). Phase 4 is closed. Plan written 2026-10-06. ## Requirements

**Pilot A re-audits one already-promoted small area (host-invocation-routing) with the new section/block coverage ledger.** Its job is to discover what the earlier migration audit missed, not to manufacture another target.

**Pilot B transforms one stable, not-yet-promoted area that combines spec decision history, architecture/contracts, and a root authority (work-state spec plus `io-contract.md`).** Not packaging-distribution (promoted, 94 commits in 30 days) and not agent-coordination (1,882 files, 33,905 claim rows, large, active, structurally exceptional).

**Deliverables:**

- discrepancy report between old and new audit methods;
- candidate target docs for Pilot B;
- source-to-claim and target-to-source conservation samples;
- alias and immutable-history lookup test;
- link rewrite preview;
- independent fresh-reader review using the six L5 questions, with explicit pass criteria and no chat-history briefing;
- defects found in the method;
- revised method and constitution (additive 2.x only; see Exit criteria for what forces a stop).

Tests: `env -u CLAUDE_CODE_SESSION_ID node --test test/scripts/*.test.mjs` (753 pass at the Phase 4 close). Commits: `git commit -- <exact paths>` after a `pwd` and `git branch --show-current` check, conventional messages (`docs(unification): ...`, `feat(docs-gates): ...`), no phase or finding labels in code, comments or test names, no `git add -A`, commit the same turn the verification is green. 1. **Reviewed-ledger channel (Code slice, test first).** Finding behind this step (verified in `scripts/generate-doc-inventory.mjs` lines 1090-1130): every claim row is derived from the switchboard; no input exists for a reviewed `targetOwner`, `targetAnchor`, `claimKind`, `disposition`, `reviewStatus` or `rationale` on a live row, and `reviewed` is `reserved` in the vocabulary. Without it the pilots cannot record or check a single decision. Design (smallest that works, generator untouched):
   - 1a (Lead): `pilot/claim-decisions.schema.json` and `pilot/README.md`. A decisions shard is `{ version: 1, shard, sources: [path], files: [{ path, disposition, rationale, reviewedBy, reviewedAt, targets: [path] }], claims: [{ claimId, targetOwner, targetAnchor, claimKind, disposition, reviewStatus, rationale, reviewedBy?, reviewedAt?, searched?: [string] }] }`; one shard per doer (file ownership). `searched` is mandatory when `disposition` is `unknown-blocking` or `delete-*` (the evidence of where the doer looked).
   - 1b (Sonnet doer, tests red first, then green): `check-doc-inventory-gates.mjs --decisions <file|dir>` merges shards onto `claimLedger` and `items` in memory and then runs the existing checks; `--scope <path-or-prefix>` (repeatable) restricts the strict open-data checks (`claims-unknown-blocking`, `claims-not-reviewed`, `claims-without-own-rationale`, `files-unknown-blocking`) to rows whose `sourcePath` is in scope, so `--strict --scope ...` can pass for the pilot while the global run stays red. New fatal findings: unknown `claimId`; two decisions for one claim; disposition or kind outside the vocabulary; `targetOwner` missing from the tree; `targetAnchor` not an anchor of that document (reuse `extractMarkdownConservationUnits`); `reviewStatus: reviewed` without `reviewedBy`, `reviewedAt` and a rationale; a decision for a row whose `sourceUnitDigest` no longer matches the scratch inventory. Without `--decisions` behaviour is byte-identical (the existing conservation tests are the proof). Dispositions the vocabulary lists as `reserved` that the pilots use (`split`, `supersede`, `delete-as-obsolete`, `archive-with-reason`, `reject-with-rationale`, `defer-with-owner`, `reviewed`) are moved to `in-use` by an additive 2.x amendment recorded in the vocabulary file (Lead; no rule text changes).
   - Gate: new tests red then green; full script suite green; independent read-only code review through the `dispatch decide --for review` door, at most one re-review; no change in the default gate run. Commits: `docs(unification): define the claim decisions shard format` (1a), `feat(docs-gates): read reviewed claim decisions and scope strict checks` (1b), `docs(unification): record the vocabulary usage amendment` (amendment). Rollback: revert the three commits; nothing else depends on them yet. If the owner does not authorize 1b (question 3), steps 2 and 6 fall back to a scratch-only checker and the verdict cannot be better than `PASS-WITH-AMENDMENTS`, because the real gate was never exercised.

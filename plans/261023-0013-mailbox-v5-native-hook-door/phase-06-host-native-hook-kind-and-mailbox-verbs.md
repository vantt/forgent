# Phase 6: Host

## Goal

Make the Rust host do three things, with only thin wiring:

- serve `fgos hook mailbox` natively and hand every other kind to legacy-node;
- serve `fgos mailbox send|inbox [--claim]` as native verbs;
- give both the main checkout's `.fgos`.

## Context

- Plan decisions 1, 2, 3, 13 and 15. Phase 2 table (a) decides the resolver.
- Host facts:
  - `apps/fgos/src/main.rs` dispatches `internal` routes before the route table, and builds the composition root only after the route lookup;
  - `command-routes.json` is generated by `scripts/export-command-selectors.mjs` from `src/cli/command-registry.mjs` plus `packages/host-runtime/contracts/command-route-annotations.json`;
  - `test/rust-host/command-routes.test.mjs` checks it;
  - the catalog is `packages/host-runtime/rust/src/catalog.rs`;
  - the presenter emits an `fgos.v1` envelope unless an outcome has a text form.
- Shared files of this phase:
  - `apps/fgos/src/{main.rs,cli_presenter.rs,cli_projector.rs,wiring/mod.rs}` and `apps/fgos/Cargo.toml`;
  - `packages/host-runtime/{contracts/command-route-annotations.json,contracts/command-routes.json,rust/src/catalog.rs}`;
  - `scripts/export-command-selectors.mjs` and `test/rust-host/command-routes.test.mjs`;
  - `src/cli/command-registry.mjs` and `bin/fgos.mjs`.

  At start and end, run `git log origin/main` on all of them. IDENT and HARDEN changed several on 10-22. Merge before each edit.

## Implementation

0. **Disk-only main-checkout read** (`fgos-git`, plan decision 3).
   - Cut the disk-only part of `GitDriver::resolve_topology` (`packages/git/rust/src/driver.rs:418-463`) into a free function `pub fn main_checkout_root(start: &Path) -> Result<Option<PathBuf>>`, exported from `lib.rs`. `resolve_topology` calls it, so there is one copy.
   - It must not call `GitDriver::new`, the floor probe, `git config` or any spawn, and it takes no lock.
   - Commit it alone, with a message that names it for the GIT/HARDEN review (owner rule).
   - The mailbox start directory is `CLAUDE_PROJECT_DIR` when set and a directory, else the process cwd (plan decision 3), and the record root is `main_checkout_root(start)?/.fgos`. One function in `wiring/mailbox_root.rs` serves both the hook and the verbs.
1. **Route data.**
   - In `command-route-annotations.json`, give `hook` the field `"native_kinds": ["mailbox"]`. Add `mailbox` as `{ "route_kind": "native", "operation_id": "mailbox.inbox", "owner_path": "packages/mailbox/rust", "subcommands": true }`, with `subcommand_flags` from the registry projection.
   - `export-command-selectors.mjs` carries `native_kinds` through. Regenerate with `node scripts/export-command-selectors.mjs` (no flag writes; `--check` only checks).
   - `CommandRouteDescriptor` in `main.rs` gains `native_kinds: Option<Vec<String>>`.
   - **Every host consumer of a new native selector** (RT15). Each one fails if it is missed:
     - `NATIVE_SUBCOMMANDS` (`main.rs:116-122`) gets `("mailbox", MAILBOX_SUBCOMMANDS)`; without it `main.rs:251-262` exits 1 "missing subcommand table";
     - `cli_projector::native_operation_id` (`cli_projector.rs:113-118`) and the request-contract `match` (`:85-98`) learn the three `mailbox.*` operations;
     - the catalog count assertions follow the new count: `packages/host-runtime/rust/src/catalog.rs:125` (`CATALOG.len()`), `external_process_router_integration.rs:154` and `external_provider_manifest_and_registry.rs:608`. Change the counts with a comment, never delete the assertions;
     - `test/cli/subcommand-flag-drift.test.mjs:201` lists the native selectors by hand, so add `mailbox`.
   - **Root precedence:** the mailbox provider ignores `request.root` and `resolve_target_root` (`main.rs:125-144`, which walks to the nearest `.fgos`) and uses `wiring/mailbox_root.rs` only. `--dir` is not an accepted flag of `mailbox`.
   - **Body text:** a body that starts with `--` must follow `--` (`unknown_native_flag` stops at `--`, `main.rs:62-95`). A body token that is exactly `--help` or `-h` is taken as a help request anywhere in argv (`main.rs:259`). Both rules go into the registry entry's description and examples.
   - Document the field in `docs/platform/host-invocation-routing/contracts/command-route-descriptor.md` (phase 9 updates the spec).
2. **Registry** (`src/cli/command-registry.mjs`).
   - The `hook` entry's `kind` enum gains `mailbox`, with new parameters `cli` (`claude`, `codex`) and `event` (`stop`, `post-tool-use`) and an example.
   - A new `mailbox` verb entry with sub-verbs `send` (`--to`, `--wake`, `--reply-to`, positional body, `--json`) and `inbox` (`--claim`, `--json`). Each description says that it is read-only or consuming, as `identity`'s does.
3. **The hook branch** (`main.rs`). After `let route = …` and before `build_snapshot`:

   ```rust
   if route.native_kinds.as_ref().is_some_and(|k| cli_args.get(1).and_then(|a| a.to_str()).is_some_and(|s| k.iter().any(|x| x == s)))
       && !wants_help_token(cli_args) {
       wiring::mailbox_hook::main(&cli_args[2..]); // never returns; exits 0
   }
   ```

   `wants_help_token` is **new**: today the check is inline at `main.rs:259` (`any(|a| a == "--help" || a == "-h")`). Extract it into this function, call it from both places, and change nothing about what it matches. A help request falls through to legacy, which owns help.
4. **`wiring/mailbox_hook.rs`** (thin). This is the only place that touches the real process:
   1. It calls `shell::silence_panics()` and arms the budget watchdog first.
   2. It parses `--cli` and `--event`. Any usage error means `exit(0)` with nothing printed.
   3. It resolves the record root through `wiring/mailbox_root.rs` (step 0). An error means quiet, exit 0. No git process is spawned and nothing is written.
   4. It reads the breaker. An open breaker means quiet, exit 0.
   5. It reads the config with `limits::read_project_config` and loads it with `limits::load`. A config error means quiet `ConfigInvalid`, **not counted** by the breaker (plan decision 11).
   6. It builds `HookEnv` and `resolver_for`, and calls `shell::run` with the real stdin, stdout and `ancestry_of(std::process::id())`. **The record is opened lazily:** `ShellInput.record` becomes an opener (`&dyn Fn() -> Result<Record, RecordError>`) that the shell calls only after the payload parsed, the resolver found the head and the caller check passed. A malformed or foreign call therefore creates no directory and takes no lock. This is a small change in `hook::shell`, with its owning test in `tests/hook_shell.rs`: `a_malformed_payload_never_opens_or_creates_the_record`.
   7. It updates the breaker from the outcome (counted failures only) and calls `exit(0)`. The watchdog's `on_exit` writes nothing.

   It contains no logic beyond this sequence, and it writes no log line (spec §9: hook timing is measured outside).
5. **`wiring/mailbox_verbs.rs`.**
   - Provider descriptors and an `OperationProvider` for `mailbox.send`, `mailbox.inbox` and `mailbox.inbox.claim`, with catalog entries in `catalog.rs`. The authority policies are `mailbox.write` and `mailbox.read`, matching identity's naming.
   - `cli_projector::native_operation_id` picks the operation from the sub-command and `--claim`.
   - The provider resolves the root as above, loads limits, identifies the caller with `resolve_current(Some(fgos_dir))` (attribution only, spec §5.1), and calls `verbs::send`, `verbs::inbox` or `verbs::inbox_claim`.
   - Outcome type `MailboxAnswer { kind, recorded_or_claimed: bool, text: String }`. The presenter prints `text` plus a newline, or the envelope with `--json`.
   - Exit codes follow decision 2. Usage errors exit 4, with the host's existing unknown-flag text.
   - **`inbox --claim` (decided, RT16):** the outcome carries `already_written: true`, and the presenter prints nothing for such an outcome (with `--json`, it prints the envelope without `text`). The provider writes the frames to stdout itself through the store's write-then-finish function, and finishes only after a successful flush. Owning test: `inbox_claim_writes_its_frames_once_and_finishes_only_after_the_write` in `mailbox_routes.rs`. If that cannot be done inside `InvocationService`, stop and ask the controller. Do not add a second raw branch on your own.
6. **Composition.** Register the three providers in `COMPOSITION_PROVIDERS` and on the service. `apps/fgos/Cargo.toml` gains `fgos-mailbox` and `fgos-mailbox-core`; update `Cargo.lock`.
7. **Legacy fallback** (`bin/fgos.mjs` `handleHook`, decision 15). `kind === 'mailbox'` returns before `ALLOWED_HOOK_KINDS`, with no output and `process.exit(0)`, and a comment saying why: the native host serves it, and this channel has no mailbox. `ALLOWED_HOOK_KINDS` and the usage text list `mailbox`.
8. **Retire the test-only entry** (RT13; design principle 8). `examples/mailbox-test-hook.rs` and `tests/test_hook_entry.rs` go in this phase's last commit. The commit body names the owner of each behaviour:

   | Behaviour | Owner after this phase |
   |---|---|
   | malformed stdin (`:163`) and usage errors (`:304`) exit 0 | `apps/fgos/tests/mailbox_routes.rs` |
   | a real process delivers, directly and under one shell hop (`:260`, `:273`) | `mailbox_routes.rs` `a_send_then_a_post_tool_use_hook_…` |
   | budget exit (`:200`) and panic (`:244`) exit 0 | `store/tests/hook_shell.rs`: it already drives `shell::run` with a panicking writer and the watchdog. If a case there is missing, add it at store level |
   | the remaining titles (`:171`, `:185`) | read them and map each one |

   - The panic trigger (`--fault`) then exists in no binary. The live harness uses the product door from phase 8 on, and `scripts/lib/mailbox-live-cli.mjs` stops building the example.
9. **Smoke checks through the dev host** (no activation). From a scratch repo under `.fgos/runtime/tmp/mailbox-v5/smoke/`, with its own `.fgos`:

   ```bash
   npm run fgos:dev -- mailbox inbox
   npm run fgos:dev -- mailbox send --to nobody hi; echo "exit=$?"
   echo '{}' | npm run fgos:dev -- hook mailbox --cli claude --event post-tool-use; echo "exit=$?"
   ```

   - The first answers `[inbox.no-address]`.
   - The second exits 1 with the unknown-name refusal.
   - The third exits 0 and prints nothing.

   `npm run fgos:dev` runs from the worktree. Pass `INIT_CWD` as that script documents. Record the outputs in the notes.

## Risks

- **The route table is regenerated by IDENT or HARDEN on main between syncs.** Always regenerate with the script after a merge; never hand-merge the JSON.
- **An `InvocationService` provider writing stdout itself.** `inbox --claim` is the only verb that must write before it finishes. Implementation step 5 decides on `already_written`. If that proves impossible, stop and ask the controller rather than add a second raw branch (one door).
- **The `fgos-git` change is a Git diff.** It is small and has no side effect, but HARDEN reviews every Git diff (board OPC row). It is announced in phase 1 and committed alone.

# Measurement: Files rewritten by `npm run build:skills`

## Method & Environment

From a clean working tree in this worktree (`git status --porcelain` empty), `npm run build:skills` was executed twice consecutively.
After each run, the exit status and `git status --porcelain` output were recorded.
The tree was then restored.

## Empirical Measurement Results

### Run 1
- **Command**: `npm run build:skills`
- **Exit status**: `0`
- **`git status --porcelain` output**:
  ```text
   M .agents/skills/fgos-supervisor/SKILL.md
   M .claude/skills/fgos-supervisor/SKILL.md
   M plugins/fgOS/skills/fgos-supervisor/SKILL.md
  ```
  *(Note: `core/skills/fgos-supervisor/SKILL.md` had been updated earlier upstream; running skill build assembled the canonical updates into the 3 generated skill surfaces).*

### Run 2
- **Command**: `npm run build:skills`
- **Exit status**: `0`
- **`git status --porcelain` output**:
  ```text
   M .agents/skills/fgos-supervisor/SKILL.md
   M .claude/skills/fgos-supervisor/SKILL.md
   M plugins/fgOS/skills/fgos-supervisor/SKILL.md
  ```
  *(The build is idempotent and stable across consecutive executions).*

### Tree Restoration
Execution of the requested restore command:
```bash
git checkout -- . && git clean -fd -- .agents/skills .claude/skills plugins/fgOS/skills
```
- **Exit status**: `128`
- **Error output**:
  ```text
  fatal: Unable to create '/home/vantt/projects/forgent/.git/worktrees/261126-2324-changelog-fragments-and-skill-surface-regeneration-p01/index.lock': Read-only file system
  ```
In this sandbox confinement, `.git` is mounted read-only, preventing git index lock creation. The modified working tree files were restored cleanly via `git show HEAD:<path> > <path>` for the three touched files, restoring `git status --porcelain` to completely clean.

## Path Classification

Based on build execution and inspection:

1. **`.agents/skills/**`** (e.g. `.agents/skills/fgos-supervisor/SKILL.md`)
   - **Generation Mechanism**: Assembled by `scripts/build-skill-wrappers.mjs` from canonical sources (`core/skills/**`, `domains/*/skills/**`).
   - **File Header**: Carries `<!-- Generated by fgOS skill assembly from ... -->`.
   - **Classification**: **Pure output** (safe to declare in `land.regenerate.files`).

2. **`.claude/skills/**`** (e.g. `.claude/skills/fgos-supervisor/SKILL.md`)
   - **Generation Mechanism**: Thin redirection wrapper stubs generated by `scripts/build-skill-wrappers.mjs`.
   - **File Marker**: Carries `This is a generated thin wrapper (tsk-1qi) -- do not edit directly, edit the source instead.`.
   - **Classification**: **Pure output** (safe to declare in `land.regenerate.files`).

3. **`plugins/fgOS/skills/**`** (e.g. `plugins/fgOS/skills/fgos-supervisor/SKILL.md`)
   - **Generation Mechanism**: Mirrored copies of `fgos-*` dev-skills and `_shared/`.
   - **File Header**: Carries assembled generated header.
   - **Classification**: **Pure output** (safe to declare in `land.regenerate.files`).

4. **`AGENTS.md`**
   - **Nature**: Hand-written foundation, governance, and doctrine document with only an internal projection block bounded by `<!-- fgos:instruction-projection:start -->` and `<!-- fgos:instruction-projection:end -->`.
   - **Build Behavior**: Reported `instruction projections already up to date.` and left untouched.
   - **Classification**: **Hand-written with a generated block** (**NEVER declare in `land.regenerate.files`**).

5. **`.fgos/instructions/effective/rules.json` & `.fgos/installation/projections/ledger.json`**
   - **Nature**: Internal projection metadata files, already up to date.

## Recommendation for Phase 3 (`.fgos/config.yaml`)

Phase 3 should configure `land.regenerate` with:
- `run`: `"npm run build:skills"`
- `files`:
  - `".agents/skills/**"`
  - `".claude/skills/**"`
  - `"plugins/fgOS/skills/**"`
- `when`: including `"core/skills/**"`, `"domains/**"` (to trigger when skill sources change).
- Do **not** declare `AGENTS.md`.

## Concerns

- **Unverified code.** Most likely compile/runtime risks: the closure/lifetime shapes in `declare.rs` tests, the
  `tierNames: {}` flow map under the `tool` profile, and the YAML door's emitted block for an appended row.
- **The YAML door has no "append to a sequence" edit** (`set` needs an existing index). A list with rows keeps its old
  bytes, takes the door's `emit` of the new item as one block, and is parsed back and compared to old rows plus the new
  one; anything else is refused `yaml-refused`. An empty list goes through `Document::set`. If you want the door to
  gain an append, that is a change to `packages/yaml-doc`.
- **`--move` needs `--plan`, not `--approved-by`**: the step text asks the owner answer for new components and
  decision kinds; a move changes an owner on an existing row, so only the plan's `survivor:` is required.
- **Reading of the step**: a contract must name at least one consumer; path existence is checked for every path a row
  names (planned components cannot name a file that does not exist yet); `parent` is optional but must exist.
- **Checker fails loudly when the host is unavailable** (`cannot read the authority model: ...`) for `draft`/`ready`
  plans, never a silent pass. Every existing `draft` or `ready` plan without an Authority map now fails
  `plan-contract-check --all` once the active model is read; the Verify line only promises no new error for `running`
  plans. Decide whether older drafts get a created-date cutoff (like the backlog-source rule).
- **`apps/fgos/tests/authority.rs` project test** runs the approved half only from a person's shell: under an agent CLI
  `questions answer` is refused (`answer-not-owner`), so the test asserts that refusal, and everything before it (inactive,
  refused declare, open question refused, nothing created), then stops. It copies the Git/state scaffolding of
  `questions_verb.rs`; run it once from a non-agent shell for the full path.

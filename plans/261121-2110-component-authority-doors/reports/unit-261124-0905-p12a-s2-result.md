# Phase 12a step 2: kernel lock primitive — stopped, nothing moved

Status: stop condition of the phase file reached. No source, registry, model, test or spec file was changed.

## Evidence
- `packages/holder-lock/rust/src/port.rs` `open_lock_file` (line ~840) is `OpenOptions::create(true)` on `resource.path`
  with no `create_dir_all`. `acquire` never creates a directory (no `create_dir`/`create_state_root` call in `port.rs`).
  The lock file would sit under `<state root>/locks/`, so `acquire` needs that directory to exist already.
- `create_state_root` exists in `state_root.rs`, but only callers outside `acquire` use it.
- `single_load::check()` runs from `packages/git/node-addon/src/lib.rs:32`, at addon load. The state root
  (`FGOS_STATE_ROOT` / `XDG_STATE_HOME` / `$HOME/.local/state/fgos`) is a per-user directory that a first load on a
  fresh machine or sandbox `HOME` does not have.
- The current Linux marker is an abstract UnixListener and needs no filesystem at all. Only the macOS branch already
  needs the root (`canonicalize` of it). Moving Linux and Windows onto `acquire` would make a load fail on a missing
  state root where it succeeds today, or would require creating the user's state root as a side effect of loading the
  addon. Both change behaviour the phase told this step not to change.

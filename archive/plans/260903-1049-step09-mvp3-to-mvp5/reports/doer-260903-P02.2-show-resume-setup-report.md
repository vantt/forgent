# Doer Report — P02.2 (Step 09, Phase 02 R5-R6, closes Phase 02)

## Scope

## What changed

- `src/verbs/coordination/launch-master-loop.mjs`: `launchMasterLoopUseCase`'s
  return value now always carries `nextAction`, a plain-text message naming
  the coordination id and the concrete next step (`fgos coordination show
  <id>`), plus — when the session closed with a refusal reason — a
  plain-terms explanation that a driver-authorized step is pending and
  requires separate human authorization. Computed by a new, pure, exported
  `describeNextAction` function. Never implies a resume door exists.
- `src/verbs/coordination/show.mjs`: `showCoordinationUseCase` now also
  calls `replaySession` (wrapped in try/catch so a corrupt/inconsistent
  session degrades gracefully instead of breaking the pre-existing
  manifest/quorum/phase view) and renders four new fields:
  `authorizations`, `ignoredAuthorizations`, `dispositions` (each marked
  `postTerminal` and with ref-ownership booleans), and
  `pendingDriverAuthorizations` (declared driver-authorized bindings with
  no matching authorization yet; `null` for an agent-led session or an
  unloadable definition). Honors both rendering constraints named in the
  cell contract: no recheck-lineage hard-edge claim, and a byte-for-byte
  mirror of `store.mjs`'s own (unexported) `assertDispositionRefOwnedBySession`
  reimplemented as a boolean render-time check.
- `src/cli/command-registry.mjs`: updated the `coordination` command's
  description to match the extended `show`/`launch-master-loop` behavior.
- `CHANGELOG.md`: one new `### Added` bullet (no prior entry existed for
  `launch-master-loop` at all — see Gaps).
- `docs/how-to/run-a-coordination-session.md`: documented the new `show`
  fields and added a `launch-master-loop` usage section.
- Tests: extended `test/verbs/coordination-launch-master-loop.test.mjs`
  (nextAction assertions on the existing live/CLI tests, plus two new unit
  tests for `describeNextAction`'s branches) and
  `test/verbs/coordination-run-driver-steps.test.mjs` (four new tests:
  authorizations/dispositions/pending rendering, post-terminal disposition
  marking via a hand-crafted log — mirroring the existing post-terminal
  `operation-authorized` test pattern — cross-session ref-ownership
  marking, and agent-led `pendingDriverAuthorizations: null`).

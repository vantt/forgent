## Findings (see P01.1.md for full evidence and fix directions)

- **HIGH** — `createSessionAssignment`'s crash-then-retry path can create a
  duplicate Assignment for one logical task when the crash lands between the
  `assignment-created` event append and the `assignmentRefs` manifest append
  (exactly the "interrupted write" scenario the contract's own Required
  Negative Test #3 names). Replay correctly detects the resulting dangling
  ref and fails closed, but nothing stops a retry of `createSessionAssignment`
  itself from silently building a second Assignment for the same taskKey,
  since the taskKey claim record is written only after the ref append and a
  retry never consults `events.jsonl` before proceeding. The Doer's own
  report discloses this as a known gap, framed as R7 ("resume/idempotency")
  scope — but the specific negative test this violates is named in
  `coordination-session.md` itself, the contract this cell was told to
  implement exactly, not an R5-R8 concept.
- **MEDIUM** — Only `replay.mjs`'s `readManifestForReplay` checks
  `schemaVersion` against the running `SCHEMA_VERSION`; all four store
  mutators (`createSessionAssignment`, `bindActor`, `linkResult`,
  `transitionSessionStatus`) read the manifest via the bare
  `readManifestRaw`, which never makes that comparison. Low practical impact
  today (schemaVersion is hardcoded `'1'`, no v2 shape exists yet to
  misinterpret), but it is a real gap against Recovery Rule #4's literal
  text and becomes live risk at the next schema bump.
- **LOW** — My own full-suite run (4720 tests, 4706 pass, 9 fail, 5 skipped)
  surfaced `cliSpawnAdapter kills the whole process GROUP on timeout` failing
  — a title not present anywhere in `index.md`'s 11-item baseline table, and
  not mentioned in the Doer's own report. Strong evidence this is a
  load/timing-sensitive flake (it passed cleanly in the smaller focused-suite
  run, both mine and the Doer's), not a regression from this cell's edits —
  but the Doer's literal "no new failure beyond the baseline list" claim did
  not reproduce exactly on an independent run.

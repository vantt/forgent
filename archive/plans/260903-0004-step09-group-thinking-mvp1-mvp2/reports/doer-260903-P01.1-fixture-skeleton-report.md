## Fixture shape and why each schema-validation choice was made

- **`spec.profile: {kind: CoordinationProtocol}` only** -- no
  `completion`, `topology`, or `cohort`. `topology` is explicitly excluded
  by this cell's Non-Goals (architecture-intent.md's own reasoning: Doer/
  Reviewer/Red-Team operations here are root operations over explicit
  artifact/context refs, not topology-connected SessionActors). `cohort`
  is for diverse-provider actor pooling (used by the fan-out/fan-in
  sibling fixture); this fixture has four fixed, individually-named
  actors, not a pool, so `cohort` does not apply. `completion` is
  optional in the schema and not required by any Acceptance line for this
  cell, so it was left out rather than added speculatively (Bug Taxonomy's
  own warning against declaring fields this cell's acceptance criteria
  don't require).
- **`spec.roles: [doer, reviewer, red-team, fixer]`** and
  **`spec.actors[]`** with exactly those four ids/roles, 1:1 -- matches
  the substrate proposal's own §6 actor list verbatim, and satisfies R2
  ("no coordinator actor declared anywhere in spec.actors[]") directly:
  there is no fifth actor, and none of the four declared roles is
  `coordinator` or `driver`.
- **Six operations** (`produce-candidate`, `review-candidate`,
  `red-team-candidate`, `revise-candidate`, `reviewer-recheck`,
  `red-team-recheck`), each with only `id`, `role`, and `result` --
  matching substrate §6's minimal operation set exactly. No
  `capabilities:`/`minTier` were added: the independent-research
  fixture's own header comment documents that a non-empty `capabilities:`
  hard-rejects planning against real config today, and this fixture has
  zero execution wiring in this phase, so adding either field would only
  plant an avoidable landmine for a later live-proof cell with no benefit
  now (Bug Taxonomy's explicit warning against copying that fixture's
  gotchas carelessly).
- **Graph**: `phase-produce` (produce-candidate/doer) ->
  `phase-first-pass` (review-candidate/reviewer +
  red-team-candidate/red-team, both required-first-pass) ->
  `phase-revision` (revise-candidate/fixer) -> `phase-recheck`
  (reviewer-recheck/reviewer + red-team-recheck/red-team). This expresses
  R3's "required first pass before declared revision/recheck positions,
  in dependency order" purely through graph topology (phase-revision/
  phase-recheck are only reachable after phase-produce/phase-first-pass),
  since the schema has no `required`/`optional` concept to declare
  directly today.
- **No `activation` field anywhere.** Confirmed by direct read of
  `src/runner/definitions/schema.mjs:54`
  (`NODE_OPERATION_REF_FIELDS = new Set(['ref', 'actor'])`) that
  `activation` is not yet a legal field on a node-operation binding --
  adding it would have made the fixture fail to validate, not "almost
  work." Per R4/Non-Goals, `revise-candidate`/`reviewer-recheck`/
  `red-team-recheck` are declared as plain graph positions, schema-
  identical to the required first-pass operations, with the fixture's own
  header comment recording in plain prose (not a fake field, not a
  schema-mistakable comment convention) that this is the honest,
  undecorated MVP1 state until Phase 02 adds `activation`.

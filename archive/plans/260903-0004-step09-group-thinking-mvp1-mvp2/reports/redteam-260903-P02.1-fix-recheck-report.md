## 2. Genuine idempotent resume was not broken

Both crash sub-shapes still complete. The second could not be reached through
`dispatchDeclaredOperation` — `replaySession` refuses to read the
"event landed, ref missing" state (the pre-existing dangling-ref direction-1
check, Red-Team LOW-1's neighbour), so it was driven at the store layer, which
is exactly where the exemption lives:

```
(2a) resume via dispatch, authorization unconsumed: SUCCEEDED (same Assignment as the crashed attempt),
     consumers=1, refs=["asgn_..._op_001"], replay=clean
(2b) self-heal, own consuming event already on the log: SUCCEEDED (sameAsCrashed=true),
     consumerEvents=1 (must be 1), refs=["asgn_..._op_001"], replay=clean
(2c) self-heal, authorization unconsumed: SUCCEEDED (sameAsCrashed=true),
     consumerEvents=1, replay=clean
```

(2b) is the case the `ownAssignmentId` exemption exists for: the sole consumer
IS this claim's own Assignment, so the resume is exempt, only the missing ref is
completed, and no second event is appended.

**The fix also does not trade a bricked replay for a bricked session.** After
the new refusal fires on a crashed taskKey, the session stays fully usable:

```
resume T2: refused (validation)
replaySession after the refusal: clean
later dispatch on a fresh taskKey + fresh authorization: SUCCEEDED
final replay: clean; authorizations=2, consumed=2, assignmentRefs=2
```

The only residual is that the orphaned taskKey is permanently refused — the
correct fail-closed outcome, and it is not in `assignmentRefs`, so it never
poisons replay. Informational, no action requested.

## 3. MEDIUM-1a — fabricated `authorizationId` refused at WRITE time

Driven with a REAL contract captured from a real dispatch, on both paths:

```
(3) new-taskKey path, fabricated authorizationId: refused at write time (validation)
    -- authorization "never_issued" ... names no "operation-authorized" event in this session
(3 self-heal) fabricated authorizationId: refused at write time (validation)
(3) assignment-created events naming "never_issued": 0 (must be 0)
(3) replay after refusal: clean
```

Before the fix this was `write: ACCEPTED` followed by
`replay: THROWS dangling-ref` forever. The poison pill is closed at the write.

*Note, no action requested:* the `issued` check counts any
`operation-authorized` in the raw log, including one replay would neutralize as
post-terminal. That is unreachable — `createSessionAssignment` refuses on
`manifest.status !== 'active'` earlier in the same critical section, and a
terminal event and its manifest write land together under the same lock — so
the laxer notion of "issued" can never be exercised. Recorded only so a future
reader does not mistake it for a gap.
